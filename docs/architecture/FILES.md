# 文件、传输与编辑

本文说明桌面文件服务、SFTP 身份、传输和编辑器的实现。系统边界见[总体架构](ARCHITECTURE.md)，操作见[文件使用说明](https://ops.hiboot.cn/docs/files.html)，插件文件契约见[公开 SDK](../plugins/PLUGIN_SDK.md#文件与传输)。

## SFTP、传输和编辑

### 本地与远程目录树

`FilesView` 在两栏的 `FilePane` 上方分别按需挂载 `DirectoryTree`，远程复制的目标目录选择器也使用此组件。树从已确认的 `DirectoryListing` 展开当前路径，按层读取祖先和用户展开的分支，只列出目录。本地树通过 `files_local` 读取磁盘、UNC 共享或 Unix 路径，保留 Windows 扩展路径前缀；远程树通过当前 SFTP 会话的 `files_list` 读取。展开分支独立于导航，选择目录分别调用 Files Store 的 `localLoad` 或 `navigate`，沿用对应栏的地址、历史和错误处理。同目录刷新保留仍存在的展开分支，切换本地根、远程会话或关闭树会清除对应缓存并使在途结果失效。

### 远程目录书签

`RemoteDirectoryBookmarks` 按 HostId 按需读取本地书签。收藏使用当前连接已成功列出的规范目录，选择书签调用 Files Store 的 `navigate`，沿用当前 SFTP 身份、路径历史和错误处理。切换主机、连接身份或离开文件页时收起菜单。

主窗口专用 `files_bookmarks` / `files_add_bookmark` / `files_remove_bookmark` 通过受限存储执行器读写 `application_settings.sftp_bookmarks:<HostId>`。写入事务复验主机存在及 v1 记录，按路径去重；删除主机时同事务清除其书签。存储只包含名称和路径。

### 从当前目录打开终端

`FilesView` 从对应栏的 `DirectoryListing.path` 取得路径，`App` 通过 Terminals Store 建立新会话并切换到对应工作区。远程入口使用已连接 SFTP 所属主机，经主窗口专用 `file_terminal` 使用保存的 SSH 连接配置申请独立 PTY。后端验证远程绝对路径并以 POSIX 单引号转义，固定启动流程在成功进入目录后打开交互式 Shell。本地入口经 `terminal_local_open` 提交起始目录，复用普通本地 PTY 启动流程，见[本地目录与手动保存](CONNECTIONS_TERMINALS.md#本地目录与手动保存)。

### 新建文本文件

远程工具栏的“新建文件”打开 `NewRemoteFileDialog`，输入仅限当前目录内的叶名称。`FilesView` 冻结 HostId、父目录和 SFTP 会话，提交前复验；`Files Store.createFile` 与既有编辑操作共用内置编辑器忙碌、文档状态及事件代号。成功或失败后刷新仅绑定原会话及原目录，不导航到用户已离开的路径；失败留在名称弹窗，不转入外部编辑流程。

桌面私有 `editor_open` 接受可选 `create` 标志，省略时保持原有读取行为。原生入口先取得单编辑器打开锁并检查退出、已有窗口及外部编辑，再由 `Application.text_create` 调用 `Files.create_text`。创建持有现有执行槽及主机变更锁，在支持原子保存且文档数量未满时，以 SFTP `CREATE | EXCLUDE | WRITE` 请求 `0644`，拒绝已有文件、目录及链接；不执行 Shell 或截断已有文件。关闭新句柄后读取内容与元数据，复用文档登记及后续冲突检测、原子保存。创建后的载入、登记或窗口打开失败保留空文件和错误原因链，并明确提示已创建，不能自动删除。权限仍受服务端 umask 约束。该标志沿用主窗口权限，插件与独立编辑窗口不能创建其他编辑文档，不修改公开 SDK 或持久格式。

### 远程名称搜索

`FilesView` 的远程工具栏打开 `RemoteFileSearchDialog`，沿用原生 `Modal`，仅保留标题栏关闭和 Esc；结果双击或键盘 Enter 发起定位。`Files Store` 将搜索条件、增量结果、未读目录及状态放在原 `FileConnection`，只在当前身份的内存会话保留。请求代号、HostId、连接对象和 SFTP 会话共同检查回调归属；切换用户清空搜索，旧响应不能写入新身份或新请求。停止先等待启动 IPC 完成注册，再提交取消，合并重复取消；关闭弹窗等待取消确认，取消失败保留界面并报告原因。页面卸载取消所属搜索。定位重新读取结果的父目录，复验会话和条目存在后交给 `FilePane.focusPath` 选择分页、滚动和聚焦；隐藏目标会开启远程隐藏项显示，不自动编辑或下载文件。

主窗口专用 `files_search_start` / `files_search_cancel` 使用严格 `FileSearchInput` 和 `FileSearchEvent`，不开放给插件或编辑窗口，不改公开 SDK 和持久格式。开始先同步登记每个租约的任务，再以 Tokio 工作在现有四槽限额内申请独立 SFTP Channel；通道仍由原 Files 租约和切换后的真实用户身份拥有。按目录流式发送增量批次及累计计数，最多每批 64 个匹配或每 200ms 更新；消费端失效也会取消。任务由 Files 服务持有，关闭租约和应用退出先取消并等待搜索收尾。

扫描仅使用 SFTP 元数据和目录读取，名称及条件转为 Unicode 小写；普通关键词按包含匹配，含 `*` / `?` 时以独立名称匹配器匹配完整名称，不执行正则、Shell 展开或读取文件正文。`*` 可匹配零到多个字符，`?` 匹配一个字符，其余模式字符均为字面值。扫描大目录时定期让出执行器并检查取消。起始目录规范化后，进入每个后代目录前 lstat 及 canonical 复验，不遍历链接或已被重定向的目录。取消在请求之间检查，已发送的 opendir/readdir 排空后显式 close 句柄；搜索专用通道结束时释放，避免中断共享浏览通道。两分钟期限触发相同取消和收尾流程；计数、深度、结果数及名称/路径字节另有界限。子目录权限、缺失、重定向和单目录限额转为可见的不完整结果，错误原因链保留；起始目录和网络故障通过失败终态及安全消息反馈。精确产品上限见 [PRD](../product/PRD.md#远程文件搜索)。

### 菜单、重命名与删除

本地和远程 `FilePane` 的单选条目支持 F2 和右键“重命名”，在名称单元格内显示输入框，不创建重命名弹窗。普通文件默认选中最后一段扩展名前的名称，目录、无扩展名和仅以点开头的名称选中全名；Enter 或失焦提交，Esc 取消，组合输入和按键连发不提交，输入框内的点击、双击及 Delete 不触发文件打开、拖放或删除。失焦提交不抢回焦点或覆盖用户新选中的其他行。

行内草稿由 `FilesView` 的操作状态持有，冻结所属栏、原主机、父目录、源路径及远程 SFTP 会话；提交前复验，目录加载、主机变化或源条目消失时取消未提交编辑，远程连接/身份变化或分页、隐藏使条目不可见时也取消。远程提交复用 `files_action` 及既有名称校验，后端继续拒绝覆盖已存在的目标。请求期间输入只读并拒绝 Enter/失焦重复提交，失败保留草稿与行内错误，成功只刷新原目标栏；Enter 在焦点未被用户移走时聚焦新名称，不改名直接结束编辑，不发送操作请求。

同目录刷新将待访问路径传给 `FilePane`，保留行和分页并显示读取状态，关闭浏览器滚动锚定，避免先清空表格导致滚动归零；切换目录仍清空旧条目。重命名后的本地刷新按原 HostId 和父目录复验，远程刷新绑定原会话与目录，不刷新另一栏或跳回用户已离开的目录。

本地重命名使用主窗口专用的 `files_local_rename`，严格 `LocalRename` DTO 只接受规范父目录、直接子项目源路径和新叶名称，不需要 SSH 连接。Application 经 SFTP 服务现有四槽执行限额进入阻塞线程，许可在原生调用完成后释放；Windows 文件互操作模块校验目录、Unicode、命名规则和边界，以不带覆盖或复制回退标志的 `MoveFileExW` 在同一目录重命名文件、目录或链接本身，返回实际目标路径，不跟随选中链接的目标。失败保留错误原因链和源文件；插件和编辑窗口没有该权限，非 Windows 明确返回不支持。此 IPC 不修改持久格式或公开插件 SDK。

`FilePane` 在文件列表范围内处理 Delete，由 `FilesView` 按栏冻结选区并复用确认流程；行点击将焦点移到该行文件名，复选框保留自身焦点，路径输入不进入删除监听。确认前复验主机、连接、目录及加载/关闭状态，提交后的本地刷新绑定原 HostId。远程仍走 `files_action`，本地 Delete 与右键“删除”共用主窗口专用的 `files_local_recycle`。

`FilesView` 在窗口捕获阶段监听 `contextmenu` 关闭旧文件菜单，不阻止原事件继续交给文件行或其他业务组件；文件行随后按新目标打开菜单。外部 `pointerdown` 关闭菜单，菜单内部操作继续执行；不设置阻挡文件命中的全屏遮罩。组件卸载时移除监听。

本地回收站请求使用严格 `LocalRecycle` DTO，冻结规范父目录、1–256 个直接子路径及确认标志；原生边界拒绝根目录、重复、越界、路径过长、缺失及已变化目录，在开始前检查整批项目，不解析选中链接的目标。Windows 在阻塞工作线程自有 STA 内复用 `windows-file-drag` 的 Shell 互操作，使用 `IFileOperation` 的回收站及提前失败标志；进度回调拒绝永久删除提议，检查逐项结果、回收对象和中止状态，不将跳过或部分完成视为成功。系统不支持回收或权限不足时保留错误原因，不调用永久删除接口。仅主窗口本地 origin 获得该 IPC 权限，插件与独立编辑窗口不获得权限；非 Windows 明确返回不支持。批量回收不是事务，失败后需核对已回收与剩余项目。

### 属性窗口与操作

`FilePropertiesDialog` 绑定打开时的 HostId、SFTP 会话和路径，主机/身份变化或页面卸载时请求取消。`files_properties` 读取最新 lstat 快照，`files_property_operation` 使用严格 `PropertyRequest` 在现有四槽限额中计算大小、SHA-256 或应用属性；每个会话最多一个属性操作，全局最多四个，以请求 UUID 精确取消，关闭连接和退出先取消并等待收尾。五分钟到达后先发取消信号，再等待在途请求及句柄关闭，不直接丢弃读写 Future。

大小扫描逐项 lstat，不跟随链接或特殊文件；目录 canonical 复验，限制 100000 项、128 层及累计 16 MiB 路径。SHA-256 复用现有有界读取、属性及 EOF 校验。扫描失败和取消返回明确消息及不完整计数，不伪装成功。递归修改持有与传输/编辑共用的主机变更锁，先完整扫描，再按子项优先更新；根目标比对弹窗原快照，每项提交前复验 canonical 路径和元数据。UID/GID 成对写入并保留未指定字段，权限只写 07777 范围；先属主后权限，以应对 chown 清除 set-ID 位，提交后读取核验。只记录已确认的修改数；失败、取消或断线可能留下部分更改，不自动回退。SFTP v3 的路径 setstat 没有原子 no-follow/CAS，最后检查到提交间的外部替换竞态仍存在，服务端文件系统权限是最终边界。

Windows 本地 `files_local_properties` 仅授权主窗口，经阻塞线程自有 STA 调用 `SHObjectProperties(SHOP_FILEPATH)`，将原始盘符/UNC 路径转换为 Shell 展示格式；不启动 Shell 命令、不执行文件、不解析选中链接目标。失败保留原因链，非 Windows 明确不支持。新增接口为桌面私有 IPC，不改变插件 SDK 或持久格式。

### 路径、元数据与连接身份

SFTP 新文件上传及单文件中转通过 `Remote::stage` 请求 `0644`，递归上传通过 `Remote::mkdir` 请求 `0755`。文件页的 `NewRemoteDirectoryDialog` 将可选权限交给 `files_action` 的 `Mkdir`，未指定时仍请求 `0755`；`Remote::mkdir_with_permissions` 拒绝超出 `0000–7777` 的值，直接在 SFTP mkdir 属性中发送权限，不执行 Shell 或创建后另行 chmod。最终创建权限受服务端 umask 和策略约束。权限记忆仅存于原 `FileConnection` 并绑定会话 ID，创建成功后更新，切换用户时清空，不写持久配置或开放插件契约。覆盖上传和编辑器保存的暂存文件仍以 `0600` 创建，校验后保留原目标权限和属主再提交；合并已有目录不改其权限，不复制本地源的权限位。

SFTP 上传及单文件中转在校验后、提交前调用 `Remote::preserve_modified`，使用源快照中的 mtime。SFTP v3 必须同时发送 atime/mtime，因此保留暂存文件的 atime，仅替换 mtime，并重新读取属性核验。覆盖时原有属主和权限保留逻辑独立执行；时间设置失败不会替换目标。源时间在本地转换为协议支持的 `u32` Unix 秒，缺失或超范围时明确报错。递归上传对普通文件逐个执行，合并目录不恢复目录时间。

普通 Files 租约请求 SFTP 子系统，各传输独立 Channel，请求、扫描和响应有界。Files Store 按 HostId 保存本地浏览状态（目录列表、加载态、待访问路径、请求代号及后退/前进历史），远程状态归各主机连接；活动主机只决定当前展示。异步读取、连接初始化和刷新绑定发起主机，同一栏按请求代号丢弃旧响应，失败保留原目录。主机工作区成功关闭后清除目录列表、加载状态和后退/前进历史，并使在途响应失效。Windows 磁盘枚举通过专用原生接口，不启动 Shell；目录下拉只是规范路径提示，不授予权限。桌面和插件共用 SDK `paths.displayLocalPath`，仅在本地路径的展示与复制时将扩展盘符/UNC 路径转换为普通形式；原生插件传输确认采用相同显示规则。Store、授权、传输及未修改的目录输入继续使用原始路径，不处理远程路径或其他 Windows 命名空间。

`files_switch_user` 仅主窗口可用，通过当前 SSH 账号 sudo 权限运行目标用户外部 sftp-server，不复用其他 Files 租约。候选通道读取成功且原连接无传输/文档才切换；失败释放候选并保留原连接。固定包装、唯一密码提示、无 PTY、超时/关闭清理，sudo 密码只留租约内存；插件只使用登录用户租约。

Files Store 首次读取任一栏时，经主窗口私有 `files_last_directory` 按 HostId 和栏位查询上次路径。显式指定路径或点击主目录时直接读取目标。远程目录经当前 SFTP 租约和服务端权限检查，记录缺失、目录缺失或不可访问时尝试 `.`；连接及协议错误沿用原错误流程。本地路径经本机文件服务读取，缺少记录、路径消失、目标类型变化或权限不足时使用本机用户主目录。保存记录读取故障会提示，并保留原记录。

界面接受的目录结果经 `files_remember_directory` 保存，按主机和栏位顺序写入。关闭工作区、退出和安装更新前等待已排队写入。后台复制准备连接不会更新记录。切换远程身份后的新列表可更新路径记录，身份和授权只在当前文件租约内保留。数据库版本及记录边界见[数据升级契约](DATA_MIGRATIONS.md#当前版本和支持范围)。

### 远程复制

`RemoteDirectorySelect` 在 `RemoteCopyDialog` 内提供不可输入的 combobox，使用原生 auto popover 承载 `DirectoryTree`，不创建额外 Modal。下拉层与选择框对齐，根据视口上下空间定位，滚动时更新位置；选择后回填并恢复选择框焦点，Esc、点击外部、身份变化或禁用时关闭并卸载目录树。新复制的目标路径初始为空，仅目录选择更新该值，不继承连接浏览目录；重试保留原值并禁用目录选择。

目录树通过既有 `filesApi.list` / `files_list` 读取已选目标租约，不调用 Files Store 的导航或改变两端目录。初始仅读取 `/` 并展开一层；每个节点按需读取直接子目录，独立保留加载、空态、错误和已读子项，折叠不递归请求，刷新重建一级目录树。只展示普通目录，不把文件或符号链接作为候选；点击名称或键盘 Enter/空格仅选择路径，不提交表单。卸载、目标主机或租约变化时使读取代号失效，旧异步响应不能回填新目标。底部“确认”沿用原复制校验和提交，服务端重新验证目标。

主窗口的 `RemoteCopyDialog` 通过私有 `files_remote_copy` 发送严格 `RemoteCopyInput`，冻结源会话、`targetSessionId`、源路径和目标，`Transfers::start_remote_copy` 在原有有界队列中登记 `remote_copy::Job`。选择已保存主机时直接复用其 Files 连接，或调用 Files Store 的后台打开并在弹窗内处理目标指纹确认，不改变活动主机及现有目标目录。新开重试窗口自动准备原目标主机并绑定当前租约；绑定后弹窗内的租约替换仍拒绝自动沿用，须重新选择主机或重开窗口。异步连接完成及失败反馈核对发起主机和组件生命周期，不能把旧主机结果绑定到新选择；失败仅在用户重试或重选主机时再连接。底部条件提示只用于禁用确认及按钮 title，真实连接错误在主机区域、真实提交错误在窗口上方保留反馈。`TransferInfo.remoteCopy/remoteName/remoteTargetHostId/remoteTargetSessionId` 标识远程复制、单选名称及目标身份，上传/下载与插件公开 DTO 保持原契约。两端使用独立 SSH 身份、认证和主机密钥校验，不创建 Shell 或转发凭据。

跨主机任务同时登记源、目标租约，参与两端的取消、关闭、身份切换和退出审核；同一任务在两端可见，任一端清除终态记录即移除共享记录。调度同时计入两端主机并发，同主机仅计一次，全局仅计一个任务。关闭任一端须等待请求排空及目标暂存清理，不关闭另一端租约。执行通道、目标快照及提交锁使用目标身份，源规划、读取及复验使用源身份，写入前复验两端租约。相同 HostId 的不同租约仍执行同主机路径重叠校验；不同主机允许相同绝对路径。

服务端先验证绝对路径、1–256 个源、显式操作/覆盖确认、名称及源/目标重叠，再在独立 SFTP Channel 中完整规划后写入。复制扫描逐项 lstat、复验源父目录与 canonical，不跟随链接；冲突和不支持的覆盖在写入前拒绝。新目标及目录按父级优先创建，文件复用 `transfer::copy` 的有界流水线、暂存、SHA-256 读回、源/目标快照复验和主机提交锁，聚合到同一任务的总字节及项目数。新文件提交前恢复源 0777 基本权限；新目录在子项处理后恢复基本权限，避免提前收紧访问阻断复制。源目录在结束时复验；现有合并目录不改权限。

复制重试保留原任务目标主机、名称及路径，重新确认连接和冲突策略后提交完整新请求。前端按两端 HostId 与原会话刷新远程终态结果，失败/取消也处理已提交项目，不刷新无关主机或替换后的身份。复制的数据经过本机内存，不写入本地临时副本；目录操作不是整体事务，SFTP v3 最后检查到提交的外部替换竞态及断线后的不确定结果仍需用户核对。

### 队列、进度与取消

传输状态为 queued/scanning/running/verifying/completed 或 cancelling/cancelled/failed。匹配的断点直接进入 verifying 核对前缀；仅失效断点进入 awaitingRestart，等待确认期间仍计入活动任务。默认每主机三个活动任务、可配置 1–6，全局最多 12 活动；降低并发不抢占已开始任务。界面冲突策略为 fail/skip/overwrite，底层还支持 rename；任务不跨进程恢复。

桌面传输快照 `TransferInfo.elapsedSeconds` 使用单调时钟累计每个文件的数据读写阶段；`bytesPerSecond` 以累计已传字节除以累计传输时间计算，不计排队、扫描、校验和提交。上传、下载和插件中转在有界请求排空后、EOF/属性复核及句柄关闭前切换为 verifying 并暂停时钟；下一文件开始数据读写时恢复累计。数据阶段作用域结束或取消请求会停止时钟，防止异常清理改变统计；校验期间及终态的传输用时、平均速度保持固定，前端随既有轮询更新，不按组件挂载时间另建计时器。剩余数据传输时间以 `remainingBytes / bytesPerSecond` 向上取整估算；未知速度、校验和终态分别展示估算中、校验中、零或不可用，不将其作为整体完成承诺。此字段属于桌面 IPC 快照，插件公开传输契约仍使用独立 DTO。

`FilesView` 将当前 HostId 的未完成任务（含窗口外拖放的暂存下载）交给现有 `Modal` 和 `TransferPanel`，进度弹窗通过主窗口 DOM 渲染，不创建额外 Tauri 窗口或 IPC 权限。新增任务或需确认丢弃失效断点时打开弹窗，普通快照刷新保持用户的隐藏选择；当前主机任务排空后关闭，已结束的普通任务仍从记录弹窗查看。× 和 Esc 均只收起弹窗，取消清理期间也可收起。点击“取消传输”时冻结弹窗内任务 ID，逐个请求取消并汇总失败，作用范围仅限该快照；请求及清理期间禁用重复取消，失败显示安全原因并允许重试。离开文件页卸载弹窗，任务和轮询继续由 Files Store 管理。

桌面快照 `TransferInfo.dragExport` 标记 Windows Shell 托管的暂存下载。`files_drag_download` 通过 OLE 的 FileGroupDescriptor/FileContents 交付虚拟文件，Shell 负责最终目标的复制；文件描述符不设置 `FD_PROGRESSUI`，由应用显示下载进度。活动拖放任务参与应用弹窗和取消，目标使用拖放文件夹提示，隐藏内部暂存目录；终态拖放任务仍不进入传输历史。该标记不改变队列、清理、未完成任务计数及退出/关闭/切换身份的保护。Windows 外拖须验证 Shell 最终字节交付，不能只以暂存下载成功作为完成。插件传输使用原独立 DTO，不继承此标记。

### 上传断点

文件页逐文件在数据目录的 `upload-recovery/` 保存版本 1 的本地记录。记录按已验证的目标主机密钥、连接路由、登录及切换用户身份、规范目标路径的摘要定位。源快照绑定规范路径、大小和修改时间，并包含原目标的大小、时间、权限、UID 和 GID。记录只保存随机标识、目录属主和摘要，用独占创建、原子发布和操作系统文件锁隔离并发上传。

远端在目标父目录独占创建隐藏的 `.serverdeck-*.upload` 目录，请求权限 0700，在其中独占创建普通暂存文件。服务端拒绝新建私有目录或未提供所需权限属性时，该文件使用普通同目录暂存。恢复只使用本机记录定位的暂存，复验目录类型、属主、权限、规范路径，以及文件的 lstat 和句柄属性。源和原目标快照匹配、暂存长度未超过源文件时，重新上传会自动按序比对远端前缀和本地内容，从第一个不同的分块或前缀末尾开始写。已复用字节计入完成进度，速度仅统计本次写入。快照不匹配或暂存过长时，丢弃旧进度须用任务 ID 和单次令牌确认。所有上传均执行整文件 SHA-256 读回、源和目标复验及原有提交规则。成功后清除私有空目录及本地记录；取消或退出时保留当前断点。任务历史仍在内存中，启动不会自动连接或传输。

### 校验与提交

上传/下载在目标同目录独占暂存、流式写入并回读 SHA-256，复验源和目标后受控提交。递归不跟随链接，显式文件链接在读取及提交前复核。提交临界区等待结果，取消不撤销已提交内容，清理失败给出恢复路径。Windows 窗口外拖放用 Shell 虚拟文件按需读取，共用传输校验。

SSH 使用 2 MiB 接收窗口和 32 KiB 最大数据包，避免小窗口限制大文件下载及校验回读；终端仍按独立的 16 KiB UI ACK 控制输出。文件页上传/下载、插件上传/服务器间中转及远端 SHA-256 回读共用最多 32 个 32 KiB 分块的有界 SFTP 窗口。文件页本地读写增加 1 MiB 缓冲，降低逐块调度文件 I/O 的开销；摘要和本地写入保持文件偏移顺序。取消和首个 I/O 错误停止提交新请求，排空在途请求、关闭句柄后保留可恢复上传的断点或清理普通暂存，不以丢弃传输 Future 代替正常取消。保留源/目标属性复验、SHA-256、覆盖策略及原子提交。服务器间字节经过桌面本机中转，吞吐受各段链路、加密与磁盘影响。

### 编辑器边界

Monaco/worker 本地按需加载，桌面一次打开一个内置或外部文档；底层八文档配额不代表桌面多窗口编辑。内置文本限严格 UTF-8 普通文件 2 MiB。保存核对原始 hash、大小、时间和 uid/gid/mode，暂存后保留并复核基础元数据，使用 OpenSSH posix-rename；失败不降级 unlink 或原地截断。

`editor_open` 绑定唯一文档并创建独立顶层 WebviewWindow。专用 capability 仅允许实际调用窗口绑定文档的加载、dirty、保存、重读、关闭和剪贴板；主窗口只接收摘要，不同步正文。读取/保存/关闭互斥，失败保留草稿。编辑器打开期间阻止所属连接关闭、切用户、数据目录迁移和页面重载；意外关闭没有持久草稿恢复。

Windows 外部编辑下载至独立 `external-edits/edit-*`，属性与哈希校验后才交系统选择器；原生 token 固定远程身份/路径及本地副本，回传须用户确认并复用冲突/原子保存。外部会话持续计入关闭保护，副本结束后保留，不自动恢复授权。二进制不转换编码。

原子替换改变 inode，SFTP v3 无服务端 CAS，ACL/xattr/硬链接及最终检查至 rename 竞态不能完整保证；提交后断线可能未知，须重新核对。插件文件请求另受更小配额和授权根约束，见 SDK。
