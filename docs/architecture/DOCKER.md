# Docker 插件实现

Docker 业务位于 `plugins/system/docker/`，只消费[公开 SDK](../plugins/PLUGIN_SDK.md)。操作见[Docker 使用说明](https://ops.hiboot.cn/docs/docker.html)，插件平台边界见[插件架构](../plugins/PLUGIN_ARCHITECTURE.md)。

## 查询与变更授权

清单预授权版本检测、容器列表、镜像列表、容器详情、环境变量、Compose 项目列表、服务快照、启动配置及 Compose 配置隐藏/显式变量十条完整固定查询，进入、刷新、展开启动配置或环境变量分组无需逐次命令确认。详情读取当前主机快照，再按完整容器 ID 筛选；概览不读取环境变量，环境变量快照仅在展开环境变量或启动配置分组时查询，前端只收到当前容器的数据，收起时隐藏并保留当前弹窗缓存，关闭详情、离开页面或连接变化时清除明文。查询仍受平台输出和超时限制，容器数量或详情过大时会明确失败。内置包预置独立 `ssh.execute.preapproved` 授权；作为上传包安装时需在权限页核对命令后单独授予。

日志和 Shell 直接打开，使用独立 `ssh.interactive.preapproved` 权限；上传安装仍需用户单独授予，该能力允许当前安装版本直接启动任意远程流/终端命令。Shell 默认 `/bin/sh`。容器启动、停止、删除及镜像删除仅保留宿主一次确认，无需输入目标 ID。标题明确操作，正文显示容器/镜像名称、短 ID、实际 SSH 主机及服务中断/数据丢失影响，按钮直接标注“启动”“停止”或“删除”；不提供“执行详情”或命令脚本入口，完整命令仍由原生审批绑定。取消不执行命令；删除仍不强制、不删除卷。其他未声明命令继续审批，宿主没有 Docker 专用匹配规则。

## 详情与明文生命周期

Docker 容器详情使用原生 `details/summary` 渲染三个独立折叠分组，默认仅展开概览；配置和环境变量子组件在对应分组首次展开时挂载，原生折叠仅隐藏内容，不重复读取或重建在途请求；失败保留重试入口。缓存仅属于当前详情弹窗，关闭、页面隐藏或主机连接变化时卸载并使迟到响应失效，不进入列表缓存或持久存储。弹窗标题和关闭按钮固定，分组共用内容滚动区。插件不提供容器资源使用查询及其固定命令预授权。

容器详情为纵向的「概览、启动配置、环境变量」三个独立折叠分组，左侧箭头指示展开状态。默认只展开概览，启动配置和环境变量首次展开读取并在当前弹窗内缓存，折叠不重读，失败仅显式重试，关闭后重开重新读取；不提供资源使用功能。端口映射和挂载通过启动配置中的只读 Compose YAML 展示：Compose 来源读取当前项目文件的完整 service 及其引用的顶层定义；普通容器根据 inspect 转换，未支持的有效设置明确提示，已存在的卷和网络保留 external 引用。Compose 配置由两条固定预授权脚本读取，按项目去重并复验成员的原始目录和有序文件；失败可显式改用容器信息转换。先检测 Compose 选项，旧版不使用不支持的 `--no-env-resolution`，启动配置按当前项目环境解析 env_file 与变量表达式。单个项目失败不会阻断当前其他项目，参数逐项传递，未扩展宿主匹配或变更权限。当前文件可能与创建时不同，转换结果不能保证完整复现历史启动参数或独立部署；不提供配置编辑或执行。启动配置展开即直接显示环境变量值，不提供查看/隐藏按钮，收起时保留缓存，关闭详情、离开页面或连接变化时清除明文及迟到响应；容器详情标题和关闭按钮固定，三个折叠分组在同一内容区滚动；内联 secrets/configs 内容始终隐藏，不读取它们引用的文件。

## 职责与助手共用能力

Docker 管理页面、Compose、解析和日常容器/镜像命令归 Docker 插件；资产匹配、脱敏、提示词、连续工具循环、计划及按需 Skill 加载归助手。匹配与执行都使用成对对话历史及明确的入口主机上下文，任务需要来源且未另行指定时采用当前工作区；保留运维所需的主机地址和原始匹配 ID，凭据继续脱敏。两个插件复用独立的镜像归档脚本模块，导出使用固定脚本与受限 argv，宿主的普通执行和长任务通道共用严格模板及审批模式校验。助手由模型组合镜像导出/导入、普通传输等工具并复查目标镜像 ID/标签，不在执行器中固定迁移流程。宿主只提供连接/执行/文件/模型/审批等原语，不按插件 ID 提供业务后门。助手工具、任务、局部文件修改、传输、流式脱敏和限额见[助手架构](ASSISTANT_AGENT.md)。

## Compose 入口与配置解析

Docker 插件的 `compose-cli.sh` 在每次命令作用域内用只读版本探测选择入口，优先 `docker compose`，再检测独立 `docker-compose`；接受 V1.29.2 及 V2 或后续版本。同一脚本内选定后不再探测，业务失败不切换入口重放。V1 项目由固定容器 inspect 快照按项目标签聚合，排除一次性容器；配置使用 V1 原生 YAML 输出，以 JSON 元数据及明确 UTF-8 字节数分帧，插件只解析通过项目、目录、文件及成员校验的所选项目。`serde-saphyr` 仅启用反序列化，限制输入、文档数、节点、深度及别名，不启用文件 include 或变量扩展；保留原有 service 隔离及环境变量、内联 secrets/configs 隐藏。V1 不使用 `--profile '*'` 或 JSON config 选项，操作和日志按快照明确传入已有服务，由 V1 启用相应 profile；V2 保持原参数路径。CLI 插件显式传入 `--host`，独立程序通过 `DOCKER_HOST` 指向同一 Unix socket，保留 context/TLS 清理、路径引用、目标复验和审批。变更与日志经 `exec` 替换命令 Shell，沿用监督与取消。三个涉及版本选择的固定读取脚本同步进入完整命令预授权，不新增通配授权或宿主原语。

变更和日志在执行前绑定 SSH 配置修订，从真实容器标签重新读取原始工作目录及有序配置文件，不接受前端传入路径；各路径逐项引用，目录或配置元数据缺失、相互冲突或不是绝对路径时明确拒绝。V2 启用全部 profiles，V1 显式传入已有服务，使已创建的 profile 服务也参与整组操作。命令仍依赖远端原始配置和环境；配置文件名包含逗号时不支持恢复；不保证恢复自定义 `--env-file` 等全部历史启动参数，文件缺失或变量无法解析时如实失败。命令超时可能部分完成，须刷新核对，不自动重放。切换容器/镜像/Compose 标签或隐藏页面会关闭自有日志流，迟到的日志打开结果也会释放。

## 镜像导入与导出

Docker 镜像归档由插件编排本机选择、SFTP 队列及受主机修订绑定的长命令流，使用独立的 `sftp.transfer.preapproved` 与交互预授权，使点击操作后无需逐次确认，不受单次 Execute 的 30 秒限额限制。命令流在 `/tmp/serverdeck-image-<nonce>/` 创建私有目录，导入等待原子上传文件后 load，导出复核标签指向完整 ID 后 save 并等待下载；完成标记绑定随机 nonce。UI 先取消并排空文件传输，再停止命令流；远端脚本跟踪并终止子 CLI，退出时仅删除已知归档并尝试移除空目录，不递归清理未知内容。SSH 断线与异常退出无法保证远端收尾，失败显示暂存位置，Docker daemon 已接受的变更不保证回滚。通用下载原语复用 SFTP 的暂存、双端 SHA-256 和不覆盖提交，并持续校验 owner、安装、权限、SSH 及配置修订；宿主不理解镜像或执行 Docker 专用逻辑。镜像页面按原生传输状态与实际字节数区分传输、校验提交、Docker 加载及清理；字节传完即隐藏吞吐速度，收到已校验的 completed 后才继续下一阶段，清理返回后才报告整体成功。远端 SHA-256 通过 SFTP 回读，可能在字节进度已满后继续占用网络和磁盘。

## 列表缓存与日志生命周期

Docker 工作区的全局统计由 `docker-summary.ts` 独立于 KeepAlive 页签管理，使用已有的 capabilities、images、containers、compose_projects 四种只读查询，不新增宿主原语或权限。成功统计和各页签列表在同一主机连接内保留，普通切页、隐藏后返回及搜索不触发已完成数据的重读；初次或失败/未完成的读取按需补齐。手动刷新、变更成功及镜像传输完成通过刷新修订更新统计和当前列表，使其他缓存页签在再次显示时重读；其他页签操作迟到完成时，可见列表也会更新。读取期间保留旧值，失败显示原因；主机或连接状态变化清除缓存，隐藏和销毁使在途批次失效，不能写回迟到响应。日志、详情明文和交互资源继续在隐藏时关闭，不进入列表缓存。日志弹窗的本地清屏仅重置前端 LogBuffer、预算和显示修订，保留 UTF-8 解码器、过滤条件及暂停/错误状态并恢复跟随；不调用平台或重建远端流，复制/导出继续使用当前可见缓存。远程日志流停止时，无论正处于暂停或 ACK 等待，均发送 TERM 和 stdin EOF 并排空到远端 exit-status/exit-signal，消费者失败也执行同样清理，2 秒未确认则 KILL 后再等 1 秒，仍未确认则报告 LOG_STOP_UNCONFIRMED；不能以 channel close 代替进程退出确认。主动关闭 SSH 会话/主机先通过 Operations 关闭关联日志（含跳板链），再释放 SSH；流注册与 SSH 断开共用生命周期屏障，排空期间拒绝新流，并发关闭及被取消的关闭调用者仍等待同一清理任务。Docker/Compose 日志在插件内用远端监督 Shell 保持 stdin EOF 守卫，GNU timeout 为本次日志进程组转发 TERM 并在 1 秒后 KILL，单次最长 10 分钟；不依赖 SSH 服务端必然接受 signal 请求，缺少 GNU timeout 时明确拒绝启动。正常应用退出维持插件、Ops 先于 SSH 的排空顺序。插件命令用 exec 替换外层 Shell，减少信号经过的中间进程。网络硬中断或强制结束应用时不能保证远端即时清理；不提供截断远端日志的功能，Docker 日志文件由 daemon 管理。缓存只用于展示，变更执行仍经后端复核真实目标。

## 镜像远程传输

镜像行内远程传输复用上述归档流：插件从公开主机目录选择其它目标，用现有镜像列表查询取得目标标签快照；冲突由用户明确确认后才开始导出。源 save 成功后开启目标接收流，再调用通用 `transfer_prepare` 的 remote 来源与目标目录，经 Native SFTP 有界窗口中转，不在本机落地完整归档。接收脚本在 load 前复查标签仍指向用户检查的 ID（或仍不存在），源导出在远端对平台、非空配置字段及有序 RootFS 层摘要计算 SHA-256，只将摘要作为 nonce 绑定的元数据传回；load 后以相同规则复核内容再发送完成标记。默认空字段统一省略，兼容 Docker API 的空值展示差异；不比较不同存储实现的显示 ID。带标签镜像核对所选标签，无标签从本次 load 输出取得目标实际 ID 后核对。当前校验针对 inspect 的默认平台，不证明多平台索引中的全部平台一致。取消和失败先关闭并排空传输，再分别停止目标与来源归档流，两端收尾错误均保留并显示主机及暂存目录。失败批次中的末尾输出在报告终态前保存，命令失败不使用日志业务文案；弹窗保留失败状态及原始输出，错误详情只发一次全局通知。源与目标都使用既有 SSH 指纹、主机修订、目录权限和生命周期约束，不新增 SDK 或宿主 Docker 接口；Docker 无原子标签锁，最终复查到 load 间仍有外部并发竞态。
