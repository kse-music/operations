# ServerDeck 技术决策

## 当前插件平台边界（SDK5，2026-11-09）

Host/Rust/TypeScript SDK统一5.0.0，UI4、ABI/wire1。Docker、AI助手、Nginx及外部MySQL的命令/SQL/解析/脱敏/提示词/计划/DTO均归插件；宿主只提供通用SSH执行/字节流/PTY、SFTP原子编辑、模型消息传输、公开资产元数据、插件配置、权限与单次确认。公开SDK不包含桌面Store、服务枚举或特定插件ID的业务特权。

目标显式hostId，Native冻结并复验实际SSH配置；模型使用修订绑定。页面owner隔离资源，审批续接原WASM Future而不重放动作。全部插件相同执行配额，关闭owner只撤销自有工作。系统来源仅决定分发及预置授权。新增完整plugins/system目录自动构建/注册；外部包从下载SDK独立开发后上传。当前精确接口和配额以[SDK文档](../plugins/PLUGIN_SDK.md)为准。

平台未release，不保留SDK4领域接口兼容或自动迁移；当前消费者/开发规范/样例/测试同步更新，不重置用户配置。下方涉及早期插件协议的日期章节仅作历史记录，其旧契约不适用于当前版本。

## 2026-11-09 无效插件记录不阻断宿主启动

SDK5 严格读取日常目录中的 SDK4 助手/Docker 记录时，已删除权限枚举使反序列化失败，原分发流程将单插件错误提升为 setup 致命错误。选择逐项隔离并展示诊断，保留原始错误原因和用户数据；不恢复旧 SDK 接口，不清空目录，也不自动改写旧记录。

内置包可通过主窗口显式备份并重装，确认绑定原记录摘要并在提交前复验。持久备份成功才原子替换记录，保留原载荷/配置，新插件禁用且不继承旧权限。数据库和仓库根安全错误仍然失败；单插件问题写入已初始化的日志并在管理页显示。此处只增加宿主私有管理契约，公开 SDK 与第三方开发包不变。

## 2026-11-08 插件使用通用能力，服务业务留在插件

初版为 Nginx/MySQL 增加专用 SDK 枚举与宿主 SQL/解析，导致开发新的服务插件需要发布平台，不符合插件独立开发的要求，已撤回。改为插件拥有动作输入、命令/SQL、目标校验和输出解析，经已存在的 Execute、文件、日志及容器发现能力运行；不开辟服务专用 IPC、SDK 请求或宿主白名单。通用草稿保护属于平台能力，不包含任何 Nginx/MySQL 分支。第三方只需下载 SDK、开发、打包和上传；平台基础能力确有缺失时才单独扩展通用契约。

保持现有 Execute 权限/单次确认、30 秒超时和每路 4 KiB 输出限制。不能为了“只读巡检”在插件中伪造宿主免审声明，也不向平台加入 MySQL 命令特例；大结果明确失败。MySQL 插件使用远端客户端配置、固定 SELECT/SHOW 和显式只读会话，不读取原始 SQL/复制错误文本。真实 MySQL 8.4 验证发现空 `--init-command=` 会发送空语句，故插件使用 `SET SESSION TRANSACTION READ ONLY`，概览返回真实只读状态。参考 [MySQL 客户端选项](https://dev.mysql.com/doc/refman/8.4/en/mysql-command-options.html)。

Docker Nginx 配置采用目录 bind 与服务器 SFTP 的映射。单文件 bind 下原子替换宿主文件可能使容器仍引用旧 inode，故只读，不退化为不安全的原地覆盖；无 bind 配置的容器仍支持检测、校验、重载和容器日志。保存不自动重载，reload 先校验再发送信号，不将信号发送成功等同于站点已生效。参考 [Nginx 命令选项](https://nginx.org/en/docs/switches.html)。平台尚未 release，当前 4.0.0 SDK/宿主一并更新，不保留旧开发包兼容层。

## 2026-11-08 主机工作台与独立设置窗口

移除重复的右上角应用菜单。顶部只保留侧栏开关、产品标识和全局搜索；底部应用导航、主机栏新建和设置内关于分别负责已有功能。菜单专用事件、监听和样式一起删除。

按用户批准的主机工作台预览，本地终端固定在主机树上方，底部只保留设置；收起的 52px 图标栏上方放主机与本地终端，下方为设置。插件管理作为设置分类，日常 Docker/AI 功能继续直接位于主机工具栏。插件详情在同一设置窗口内切换，复用原配置、授权和独立保存语义，插件管理不创建工作区标签。树和插件列表保持挂载以保留搜索/筛选，插件保存期间禁止离开，关闭设置恢复入口焦点。全局搜索从右上角或快捷键打开，无新增配置、依赖或连接所有权。

采用常驻资源树、单排工作区标签和主机内部工具切换。去掉只影响侧栏、却与活动页面独立的模块选择状态，减少“模块、页面、全部主机、主机”之间的重复层级。全局工具与主机标签按打开顺序排列，“关闭右侧”遵循可见顺序。

设置独立于工作区标签，复用现有草稿、保存和迁移逻辑；模型与关于作为同一设置窗口的分类。窗口存续期间保持偏好组件挂载，避免切换分类丢失草稿；关闭窗口统一审核未保存修改。继续保留主机关闭的传输确认与失败保护，不引入新导航框架、数据迁移、原生权限或配置项。较早关于模块和设置分类标签的决定仅描述当时设计。

## 2026-11-08 非插件模块的开发期兼容清理

以实际调用与数据保护区分兼容代码和当前功能：删除旧身份、旧服务、旧格式转换和停用接口；保留主动目录迁移、正常版本回滚、受控通用 AI 命令和 OpenSSH 私钥路径。新数据库直接使用与当前 schema 9 等价的基线，旧数据库版本拒绝，避免用清库或静默重置掩盖不兼容。历史附加表、未使用的 tags 列和旧目录/凭据原始内容不自动删除。

旧智能体响应不再触发另一种命令建议流程，格式错误以 AI_PROTOCOL 结束；当前通用分析 API 仍按自己的显式协议处理。无实现与消费者的费用空字段及恒真插件兼容标记直接移除，SDK/调用方/验证同步更新。

## 2026-11-08 从插件源码生成内置注册

内置插件以 `plugins/system/<name>/manifest.json` 为唯一发现来源；构建器生成 Rust `include_bytes!` 注册文件，宿主继续复用标准安装与授权链。不在 Rust 和 CI 维护另一份插件名单，也不在运行时扫描可写目录并授予 system 权限。生成注册只在所有包构建和身份校验成功后更新，陈旧产物不参与发现。无新依赖；新增插件的锁定依赖准备与编译明确分开。新增插件仍须遵循 SDK 能力边界，源码发现不赋予额外原生接口。

## 2026-11-08 未发布平台不保留插件兼容层

当前不存在历史发行包，旧 UI、Host API 协商和插件迁移没有实际使用对象。选择直接统一当前契约，删除兼容实现和专属回归，示例与开发包同步到 Host/SDK 4.0.0、UI v4；不新增迁移框架或另一套包版本。继续测试当前契约的拒绝边界，以及正常升级回滚、权限/摘要/路径安全和用户数据保留。历史记录保留为开发证据，不再构成兼容承诺。

## 2026-11-07 应用内下载本地 AI 工具

缺失提示与安装是模型来源选择流程的一部分，在设置和聊天页复用同一组件。按需获取官方原生可执行文件，安装到应用独立目录；优先使用已有用户安装。避免依赖 npm、执行远程安装脚本或改写全局 PATH。安装只获得程序，不代表授权读取已有登录；后者继续使用可信宿主确认。

采用现有 reqwest、SHA-256、Tokio 和 tempfile，无新依赖。Codex 通过 GitHub 官方资产 API 下载；本机网页发行下载入口实测超时，而该 API 可达。版本跟随官方发行清单，若清单、散列、平台或启动验证不通过则拒绝安装。官方来源见 [Codex CLI](https://learn.chatgpt.com/docs/codex/cli) 与 [Claude Code 安装](https://code.claude.com/docs/en/setup)。

## 2026-11-07 复用用户本地 Claude Code

沿用本地 Codex 的选择和独立访问授权交互，使用用户已安装的 Claude Code 原生 CLI，让其读取配置及维护认证。采用 print 流式协议，无需新增 SDK 依赖、复制订阅 token 或改写用户配置。用 safe-mode 与进程级参数限制自带工具；不用会跳过 OAuth/钥匙串的 bare 模式。注册模型继续走已有 HTTP Provider，CLI 仅替换推理入口。

当前实机基线为 Windows Claude Code 2.1.270。其他版本或平台需分别验收；不兼容选项、额外工具和异常流按失败处理。商业发行使用订阅认证的条件需按 [Anthropic 官方认证说明](https://code.claude.com/docs/en/authentication)及[法律与合规说明](https://code.claude.com/docs/en/legal-and-compliance)确认。本地授权仅表示用户允许 ServerDeck 调用其 CLI。

## 2026-11-07 复用用户本地 Codex 运行时

按用户确认的 CC GUI 方式，使用本地 CLI 的 App Server 接口复用已有配置与登录。ServerDeck 保存独立的本地访问授权，凭据和刷新由 CLI 管理，不将 token 转换为注册模型的 API Key。HTTP 注册模型和本地来源共用原有请求、查询、计划与执行链路，通过保留来源 ID 兼容已有插件绑定。专属桥方法只允许内置 system 助手，未给上传插件扩展秘密或进程能力。

为保持运维审批边界，本地 Codex 仅承担推理，使用临时目录、ephemeral 会话和进程级工具限制。每次模型轮次独立启动 CLI，停止时终止本次进程，避免在所有主机间维护共享外部会话或令牌副本。用户目录配置变化和账户切换使旧计划失效。Windows 原生 Codex 0.167.0-alpha.3.2 已完成固定文本真实请求验证；其他版本和平台需分别验收。App Server 协议及供应商对第三方订阅认证的发行限制仍由发布流程确认，参考 [OpenAI 官方说明](https://learn.chatgpt.com/docs/app-server#auth-endpoints)。

## 2026-11-07 以 14px 为界面标准字号

主要文字统一使用 14px，辅助信息 12px、分组标题 16px、弹窗标题 20px、页面标题 24px，避免只修改 body 而保留列表与表单中的 11/12px 覆盖。公共 SDK 提供包含缩放比例的语义字号变量，内置插件复用；行高使用相对值，普通控件最低 36px，允许随文字增高。

保留小/标准/大/特大/超大的 95%/100%/115%/130%/145%，主要文字为 13.3/14/16.1/18.2/20.3px。放大三档保持相同的 15 个百分点间距，小档轻微缩小；不改已保存的档位语义，不新增配置或迁移。SFTP 根据更大文字所需的面板宽度更早上下排列。iframe 沿用现有 context 消息增量同步可选缩放值，旧宿主缺失时回退 100%，不重新挂载插件或改变终端内容字号。第三方旧包的自有样式需作者重新构建，宿主不跨隔离边界改写。

## 2026-11-07 Windows SFTP 窗口外拖放

使用 Windows Shell 虚拟文件协议实现复制。Shell 选择实际落点并处理目标重名，ServerDeck 在收到文件流请求后复用 SFTP 校验流程。只有窗口外拖动会交给 OLE，窗口内拖动继续按双栏交互处理。Windows FFI 隔离在专用 crate 内，工作区原有安全 lint 保留。

## 2026-11-07 SFTP 文件链接和拖放下载

显式选择的符号链接只在目标为普通文件时参与下载，并以链接名写入本地。规划、读取前和提交前核对解析路径，避免因链接改指向而下载不同目标。目录扫描拒绝链接。右栏到左栏的拖放复用原传输确认和队列，以左栏当前目录为预填目标。远程删除每次明确确认，递归删除目录内容需单独勾选。

## 2026-11-06 主机认证使用独立凭据版本

主机表单输入新密码或私钥时创建独立引用。此前共享同一凭据的主机，以及从当前主机复制的配置，继续使用各自保存的引用。事务内只回收失去全部引用的主机专用凭据，迁移保留旧式共享凭据。这样主机配置写入失败时仍可使用原认证，修改一台主机也不会连带更新其他主机。

## 2026-11-06 Linux 终端字形下沿保护

在既有字体解析模块中增加 Linux 有效行高 110% 的下限，使 WebKitGTK 的下划线留在 xterm 行盒内。初始渲染和偏好变化使用同一路径，存储值及其他平台按原逻辑处理；更大行高继续生效。代价是紧凑配置下可见行数略减，实际复制和终端缓冲保持原文本。

## 2026-11-06 平台版本更新为 0.2.0

按本次版本要求，将 Cargo 工作区、npm 与 Tauri 平台版本统一为 0.2.0，插件与 SDK 版本独立维护。发布清单继续校验版本一致性、应用身份、权限、图标和产物摘要，取消版本必须包含 beta 的旧命名约束。发布验收仍以发布检查表中的实测证据为准；历史安装包、测试及安全报告保持原版本，不因版本号更新视为通过。

## 2026-11-06 本地终端沿用用户交互配置

Unix 本地终端复用 portable-pty 已有的默认 Shell 解析，避免固定 `/bin/sh` 跳过 Bash 的提示符、别名和补全配置。保留非登录交互模式 `-i`，不直接使用依赖库默认的登录启动方式，以确保 Bash 读取 `~/.bashrc`；不注入 `PS1` 或改写用户配置。路径与参数独立传递，子进程 `SHELL` 和返回的程序名使用同一次解析结果，无新增依赖或 IPC 参数。

## 2026-11-06 内置 Docker 环境变量直接查看

选择「环境变量」标签作为用户读取明文的操作。原生层按实际安装来源、插件 ID 和请求类型限定免弹窗范围，继续校验 `system.manage` 与已绑定主机。只在对应标签存放和渲染明文，关闭弹窗、切换标签或丢失上下文时清除，其他来源仍需宿主审批。

## 2026-11-06 统一插件设置弹窗

所有安装身份统一使用无主机设置弹窗，保留当前工作区。启停、授权和目录范围集中在窗内的“权限与详情”。宿主复用原有设置贡献和隔离桥，助手通过可见性恢复读取持久绑定。旧插件可继续使用原表单，助手的保存与取消沿用宿主弹窗的生命周期。

## 2026-11-06 私钥存储与模型预算

私钥导入复用现有系统凭据库和秘密版本机制。导入时校验解锁口令，将规范化密钥作为单个秘密保存。凭据表沿用秘密引用，以旧路径是否存在区分连接方式。这样旧主机关联可在原凭据 ID 上升级，替换或删除也由原有清理机制处理。

上下文窗口适用于 OpenAI 兼容模型。沿用与服务端分词器无关的 UTF-8 估算，并为配置的输出预留空间。旧模型默认 131072 Token，以覆盖原有请求上限和最大输出。旧费用响应字段留空，Token 用量继续取自模型响应。

## 2026-11-05：镜像删除只保留可信宿主确认

镜像删除去除包内完整目标输入，以宿主一次“取消 / 确认删除”满足交互要求。保留原生 approval 门禁，通过可选 imageId 直接传递已冻结目标；不解析说明文案，也不将 iframe 请求中的 ID 当作批准依据。这样同时保留权限、连接身份、TTL 和单次批准，并避免两层确认。其他操作沿用原确认规则，旧响应缺少字段时仍使用通用宿主审批。

## 2026-11-05：统一数据根目录与确认后清理

按用户选择合并现有设置分类，并用一个本机根目录管理数据库、插件、日志和 WebView；下载目录独立，系统秘密继续由凭据库保护。保留默认配置位置的小型定位文件，避免从尚未定位的数据库读取自己的路径，也避免业务备份覆盖机器目录。

选择重启期间复制校验、启动成功后自动清理源副本，支持跨磁盘并避免运行中的 SQLite/WebView 文件占用。清理前先持久化提交状态，逐文件核验清单；清理失败不回退到部分删除的旧目录。目标只接受空的专用目录（允许本应用定位文件），不合并用户已有目录。复制中断可校验续传，候选未完成启动则回退，失败副本保留供诊断。新增 fs2 用于不引入本地 unsafe 的跨平台空间查询，SHA-256 与临时文件沿用现有依赖版本。

## 2026-11-05：删除系统服务及旧标准系统界面

按用户确认，删除插件及第三方复用的旧系统视图，接受失去无模型的可视化资源趋势和手动系统管理入口。保留 AI 和独立插件共享的后端及公开能力；不搬迁或重建系统页面。Docker 旧界面复用现有实现，避免维护第二份业务页面。

合同移除使用 Host/SDK 4.0.0，保留未受影响的 v1–v3 能力。退役归档保留原始记录、包及用户数据；只清理失效的活动备份指针，并保存独立包，避免后续常规版本清理损坏历史归档。迁移失败阻断启动并保留原因，不重置环境。

## 2026-11-05：AI 工作不随视图可见性取消

## 0011：分离脚本参数、持久状态与本地确认式调度

日期：2026-11-02；状态：已实施，证据见 [自动化验收](../validation/operations/VALIDATION_AUTOMATION.md)。

用户明确追加 PRD P1 运维范围。选择现有 SSH + Docker CLI，而非新增 Docker HTTP 客户端和 API 转发：CLI 兼容协商与 JSON 格式足够当前操作，减少认证/网络暴露面。只显式连接标准 Unix Socket并清除 context/Host/TLS 环境覆盖；不默认启用 TCP、sudo 或 su。普通账号无权限就失败，测试服务器权限由用户在服务器侧授予，应用不修改权限。

所有动作由 Rust 封闭枚举构造，参数严格校验/单引号转义；容器/镜像用全 ID，服务带明确 scope，写操作要求 confirmed，UI 输入全文并绑定 SessionId。容器环境全部默认遮蔽，显式确认才显示；不将输出存日志/数据库。进程信号选 pidfd + boot/start 标识，不使用存在 PID 复用窗口的检查后 kill；代价是信号需要较新的 Linux 和 Python pidfd 支持，能力不足明确失败。

## 0007：SFTP 租约、独立后台队列和保守文本替换

日期：2026-11-01；状态：已实现，验证见 [阶段四验收](../validation/files/VALIDATION_STAGE4.md)。

采用已锁定并验证的 russh-sftp 3.0.1，使用 RawSftpSession 是为了有界目录读取、明确请求大小和 OpenSSH posix-rename 扩展；普通文件操作均是 SFTP 请求。Files 租约复用现有认证路由的 Transport，目录和传输有独立 Channel。任务由 Rust 保存，UI 页面不拥有取消权限；显式断开、应用退出才执行相应取消流程。

传输选择同目录独占临时文件、SHA-256 校验及明确冲突策略，不增加断点续传、跨重启自动任务或通用任务框架。并发和队列/目录/规划内存均设边界。取消保留已提交文件，提交临界阶段等待结果；网络故障清理失败必须呈现恢复路径。

编辑仅支持小型 UTF-8 普通文件。以内容 hash 和基础属性两次检测外部变化，必须有 WRITE 权限，原子替换必须保留 uid/gid/mode，缺少扩展或保留失败则不保存，不退化为删除/截断原件。原子替换的 inode、ACL/xattr、硬链接局限必须由用户明确确认；服务端无 CAS，最后检查与 rename 的竞态无法彻底消除，不能夸大保证。

终端目录采用 OSC 7 报告并由用户勾选跟随，不解析 pwd/提示符，不安装远端 Agent、不修改 Shell 启动文件。文件终端动作只运行经过确认、固定模板且 POSIX 转义的目录/less/tail 命令，使用独立 PTY，避免污染或注入已有 Shell。

Monaco 0.57 和 worker 均本地打包、按需加载，基础语言高亮，无远程 schema、脚本执行或插件。新引入的 DOMPurify 通过 override 锁定已发布 3.4.17 修复，生产 npm 审计重新检查；不强制升级无关开发依赖。Rust RSA 既有门禁保持。

实际原生验收发现同步 Tauri 传输入口没有 Tokio 运行时，已改异步并加入错误线程回归；另补退出的后端实时复核，不能让前端轮询延迟绕过未完成传输确认。tail 的 exit-signal 与断线分离，保留其他终端可用。

依据：[russh-sftp 3.0.1](https://docs.rs/russh-sftp/3.0.1/russh_sftp/)、[OpenSSH SFTP 扩展](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL)、[Monaco ESM](https://github.com/microsoft/monaco-editor/blob/main/docs/integrate-esm.md)、[Tauri 原生选择器](https://v2.tauri.app/plugin/dialog/)。实现以固定版本源码、协议测试及原生 Linux 证据为准。

## 0006：日常终端、受管路由与归属明确的端口转发

日期：2026-11-01；状态：已实施。证据见 [SSH 使用增强验收](../validation/terminal/VALIDATION_SSH_USABILITY.md)。

继续使用锁定的 russh 0.65：connect_stream 接受 TCP、代理流或 direct-tcpip ChannelStream，避免为了代理执行本地 Shell。受管跳板逐跳验证密钥、独立认证，最多 4 层，配置和凭据 revision 参与 Transport 复用。SOCKS5 支持无认证/用户名密码，HTTP CONNECT 支持无认证/Basic；秘密仍来自 OS 库。HTTP 代理不使用 TLS，代理认证没有额外加密，界面明确提示可信网络边界。ProxyCommand 不启用；Include/Match、复杂 ProxyJump 字符串拒绝，不能忽略后连接错误目标。导入依赖按事务排序，同名跳板端点冲突阻断，不写回 ssh_config。

标签拥有布局，窗格拥有 Session，Transport 可共享；二叉树只计算百分比几何，不重排 xterm DOM，避免拖动导致 Shell 重启。最多 8 窗格/标签、32 总窗格。布局只持久化 HostId、标题、顺序和比例，重启恢复未连接状态；不保存终端正文，不回放命令。终端偏好追加到原版本配置并默认兼容，键位校验保留 Ctrl+C/Z；大文本先确认并遵守远端 Bracketed Paste，显式本地导出，默认不录制。

转发归属于创建它的 Session，不采用全局永久隧道服务。Local/Remote/Dynamic 显式启停，默认回环、公共绑定需要前后端显式确认；Remote 仍受服务端 GatewayPorts/AllowTcpForwarding 策略约束。并发流、记录、入口队列均有上限。停止、断线、关闭清理监听和子任务；同一远程端口的精确所有权防止重复请求撤销其他隧道。远程取消未确认时断开所属 Transport，优先避免服务器遗留监听，并明确提示共享终端受影响。Dynamic 暂限无认证 CONNECT，不支持 UDP/BIND；Remote 不支持端口 0；转发不自动恢复。

原生验证发现并修复两项实际交互缺陷：ResizeObserver 不再抢搜索焦点；布局保存与凭据读取改为有界元数据等待，连接前 BUSY 有限重试必须新建 Tauri Channel。输入数据只在原 Session 内重试，重连清空旧队列，不能重放命令。

依据：[OpenSSH 配置语义](https://man.openbsd.org/ssh_config)、[xterm 终端偏好/Bracketed Paste](https://xtermjs.org/docs/api/terminal/interfaces/iterminaloptions/)、固定版本本地 russh client Config/Handle/Handler 源码与实际协议测试。未引入 SFTP、远程执行命令模板或通用任务框架。

## 0005：russh 生产接入、独立 PTY 和应用层背压

日期：2026-11-01；状态：已实施，Windows → Ubuntu OpenSSH 实测。

采用锁定于 Cargo.lock 的 russh 0.65.0，关闭默认 feature，使用 ring + rsa。真实握手、密码、普通/加密 Ed25519、Agent 签名、独立 Channel、PTY resize、断线和有界输出已验证，无需替换实现。保持原有 probe 独立，不把 SFTP 子系统接入本阶段产品。

应用自己的 SQLite 信任表以 hostname+port 保存完整公钥；未知主机必须完成 live challenge 确认才发送认证信息，密钥变化硬性阻止。系统 known_hosts 的 CA/哈希/撤销导入没有被简化成不正确的字符串解析，明确留待后续。

Transport 与终端 Session 分开管理：复用键包含主机、端点、账户和凭据 ID/revision。每个 Shell 一个 Channel；关闭一个只取消该 Channel，最后一个退出后才关闭 Transport。重连创建新 Shell，不重放输入。总数限制 32；受远端 MaxSessions 限制时明确失败，不自动增开无限连接。

Tauri Channel 本身不提供端到端背压，采用最多一块 16KiB 输出 + xterm.write 完成回调 ACK，后台收到对应序号才继续读取。控制输入/resize 与输出消费分开，Ctrl+C 和取消不被解析等待阻塞。代价是每块有一次 IPC 往返；2MiB 实测通过，尚无长期吞吐和内存基准。russh 内部控制队列仍有无界部分，不能宣称恶意服务端下有硬内存上限。

保留 RUSTSEC-2023-0071 的非零审计结果，不添加 ignore。生产私钥文件入口拒绝 RSA；RSA Agent 使用系统进程签名并要求 SHA-2，应用不做 RSA 私钥运算。Ed25519/ECDSA 文件、密码、Agent 可用；主机 RSA 公钥验证不属于本地私钥签名。系统 Agent 的实现安全性由系统提供，当前只验证了隔离命名管道 Agent 的真实签名认证，未验证用户系统服务与实际加载身份。

依据：[russh 0.65 API](https://docs.rs/russh/0.65.0/russh/client/struct.Handle.html)、[xterm flow control](https://xtermjs.org/docs/guides/flowcontrol/)、[Tauri Channel](https://v2.tauri.app/develop/calling-frontend/#channels)、[RustSec RSA 通告](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)。实际证据与限制见 [阶段三验收](../validation/terminal/VALIDATION_STAGE3.md)。

## 0002：原生凭据库、不可变秘密引用与清理意图

日期：2026-11-01；状态：已实施，Windows 已验证。

问题：主机配置必须在 SQLite 中持久化，秘密必须放在 OS 安全库。两者无跨系统原子事务；直接更新同一秘密可能使数据库保存失败后仍替换共享凭据，删除失败也不能假装完成。

采用 keyring 4.2 原生适配（Windows Credential Manager、macOS Keychain、Linux Secret Service），没有普通 JSON/SQLite 或进程内 mock fallback。应用只定义写入、读取、删除的窄 Rust 边界，读取不暴露为 IPC。测试中的故障注入实现只用于自动化。

新秘密使用新 UUID reference；先记录 SQLite secret_gc 意图，再写 OS entry。随后 SQLite 事务切换引用、增加 revision、移除新意图并登记旧 entry 待删除。提交失败补偿删除新 entry；崩溃和删除失败保留清理记录，UI 明确报告且允许重试。
被共享的凭据类型不可直接更改；更新用 revision 拒绝过期编辑。删除引用默认拒绝有主机关联的凭据，显式确认后解除关联并保留主机配置。删除主机只减少引用，不自动删除凭据。

权衡：只使用系统库比自建加密文件保险库少一套密钥管理与恢复逻辑；代价是依赖用户会话和服务可用性。当前“检查可用性”只证明读取服务可达，不提前承诺后续写入一定成功。秘密写入失败返回安全错误并保留原引用，不退化为明文。
若操作中断，可能存在待清理秘密，但它有持久化 opaque 引用；本轮不保证在系统服务长期不可用时秘密立即物理删除。服务恢复后可重试，不能隐藏此限制。

秘密输入 DTO 不实现 Debug/Serialize，Rust 缓冲使用 Zeroizing；前端表单提交/卸载清空输入。JS、OS 与依赖库内部内存副本的清零不作绝对保证。私钥只引用文件路径，不读取/复制正文，不宣称已验证文件、加密算法或 SSH 可登录。

验证：SQLite 迁移、凭据关联/共享/过期版本、故障库不回退、旧秘密重试清理、日志/数据库泄漏扫描，外加原生 Windows 凭据库测试和真实打包应用 E2E。
依据：[keyring v1 原生存储说明](https://docs.rs/keyring/4.2.0/keyring/v1/index.html)。macOS/Linux 尚需各自实机验收。

## 0003：保守 OpenSSH 导入与字段白名单导出（初始决策）

日期：2026-11-01；状态：已实施。

受限 ProxyJump 与 Keepalive 已由 0006 扩展；以下为原始阶段二边界。

验证：全局/Host 顺序与首次赋值、引号/注释/等号、通配符否定、多别名、重复识别、非法值、Include/Match/ProxyJump 阻断、事务回滚与实际导入界面。
依据：[OpenSSH ssh_config 手册](https://man.openbsd.org/ssh_config)。
