# ADR 0017：严格当前契约与保留用户数据

日期：2026-11-08。状态：部分被 [ADR 0028](0028-safe-data-upgrades.md) 替代。已知数据库和持久配置改为安全自动升级；下文保留原决策理由，插件执行契约、旧身份目录及秘密保护仍有效。

本记录整理自原技术决策中的相关条目，保留设计依据和替代关系；不是本次文档整理新增的功能。

## 背景与选择

平台尚未正式发布，开发期旧包、身份、设置字段和模型格式的自动兼容增加了无实际发行对象的维护路径。选择只接受当前契约，同步更新实现、SDK、样例和测试，删除历史转换；保留真实用户数据保护、错误原因链、正常升级/回滚及用户主动数据根迁移。

数据库仅为空库初始化等价 schema 9，现有当前库不改写，旧/未知版本明确拒绝并保留原文件。闲置列和附加表不自动删除；不复制旧凭据服务、不搬移旧身份目录、不靠补默认掩盖不完整的持久配置。

系统凭据使用不可变引用/清理意图。主机认证修改创建自己的凭据版本，避免改变其他主机和副本的共享认证；新建/编辑提交要求绑定完整草稿和路由的单次 SSH 测试。OpenSSH 路径导入是当前功能，不能与旧格式自动迁移混淆。

## 故障隔离与取舍

严格拒绝不等于阻断所有独立功能：单插件旧/损坏记录隔离展示，根目录安全故障/数据库错误继续传播。有内置替代包时用户可显式备份并重装，先逐字持久备份、复验摘要再原子替换，新安装默认禁用且不继承旧权限。没有兼容解码或自动重装。

代价是旧开发数据可能需要用户检查后手动修复/重装，平台不提供透明升级承诺。此决策修订 ADR 0002 的私钥/共享凭据边界、ADR 0003 的旧归档方案及早期应用身份迁移，不能据此批准清库或重置配置。

证据见[当前契约清理](../../validation/foundation/VALIDATION_PRE_RELEASE_CLEANUP.md)、[主机认证](../../validation/hosts/VALIDATION_HOST_INVENTORY.md)和[单插件故障隔离](../../validation/plugins/PLUGIN_TEST_REPORT.md#2026-11-09-旧插件记录导致启动失败修复)。
