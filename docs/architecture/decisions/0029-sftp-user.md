# ADR 0029：SFTP 独立 sudo 身份

- 日期：2026-11-09
- 状态：接受

## 背景与选项

终端切用户只改变该 PTY 的进程身份，不能改变已有 SFTP 服务。自动解析提示符不能证明实际权限；修改主机 SSH 用户也无法解决禁止 root SSH 登录的常见环境。采用文件页显式 sudo 授权，与终端及主机配置分离。

## 选择

为切换创建独立、不可变身份的文件租约，复用已校验 SSH 路由；真实目录读取成功后才替换旧连接。原连接有传输或编辑文档时拒绝切换。浏览及每个传输 Channel 分别通过无 PTY 的 sudo 和固定 Shell 包装启动外部 sftp-server；使用随机密码提示/就绪标记分隔认证与二进制协议。密码只走 SSH stdin，最多响应一次提示，以 Zeroizing 绑定运行期租约，不持久化、不复用系统凭据或终端 sudo 缓存。

插件只能选择原登录身份的文件租约；桌面授权不会变为插件的新权限。切回原用户也创建独立候选，不复用可能属于其他调用方的文件租约。

## 后果

用户可在不开放 root SSH 登录的服务器上管理授权范围内的文件；sudo 必须允许固定 Shell 和外部 sftp-server，requiretty、仅 internal-sftp、复杂交互认证不在支持范围。目标 HOME 无法进入时从 `/` 开始。密码在连接存续期间留在内存，以便建立独立传输通道；重连/重启必须重新授权。没有数据库或持久配置格式变化。

见 [SFTP 验证记录](../../validation/files/VALIDATION_STAGE4.md#2026-11-09-sftp-切换用户)：真实回环协议覆盖密码与免密分支，隔离 OpenSSH/sudo 验证真实 UID、上传、失败保护与切回；当前平台限制保留在报告中。
