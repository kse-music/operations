# ADR 0001：SSH 候选的密码学安全门禁

日期：2026-11-01。状态：阶段一采取隔离与限制；生产 SSH 选型仍待阶段三前复审。

阶段三复审已完成，受限生产接入见 [决策 0005](../DECISIONS.md)。下文保留阶段一证据；桌面依赖图现在包含 russh/rsa，本地 RSA 私钥签名仍被拒绝，审计非零与跨平台门禁保留。

## 问题与证据

本机 cargo-audit 0.22.2 使用最新 RustSec 数据库审计 Cargo.lock，报告 1 个漏洞：
`rsa 0.10.0-rc.18 / RUSTSEC-2023-0071`，Marvin timing side-channel，公告当前无 patched version。
已通过 [RustSec 原始公告](https://rustsec.org/advisories/RUSTSEC-2023-0071.html) 及 [上游跟踪](https://github.com/RustCrypto/RSA/issues/626) 核实，不能靠升级到另一个同系列未修复版本消除，也不能以 RSA SHA-2 代替恒定时间实现的保证。

实际普通依赖链：`serverdeck-ssh-probe → russh → rsa / ssh-key → rsa`。
`cargo tree -p serverdeck-desktop --edges normal` 不含 rsa、russh 或 russh-sftp。
这说明当前桌面阶段一未暴露 RSA 签名路径，不能据此宣称候选库已通过安全审查。

## 可选方案

| 方案                                                               | 安全与兼容影响                                                             | 性能与维护成本                                                 |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 继续把候选直接接入生产                                             | 未解决私钥操作时序风险，不满足安全门禁                                     | 初期改动小，但不可接受                                         |
| 保留隔离探针，外部使用 Ed25519 或 OS Agent，RSA 仅合成密钥本机测试 | 避免当前 CLI 用真实 RSA 私钥签名；Agent 私钥操作由系统实现，仍需审查其策略 | 保留 Tokio 多 Channel 设计；减少返工；不能提前承诺所有私钥算法 |
| 等待经审计修复或验证其他密码后端/SSH 实现                          | 必须重新确认实际私钥路径与算法支持，不只是改版本号                         | 增加实验、构建与跨平台成本                                     |

## 当前决策

1. 阶段一桌面完全不依赖探针，暂不创建生产 SSH crate。
2. 外部探针的 `key` 模式拒绝 RSA 私钥，保留 Ed25519 和系统 Agent 入口；后者尚未经本机 Agent 联调。
3. RSA 加密密钥/签名测试仅用运行时生成的临时测试密钥，在回环服务器上验证协议兼容性，不接触用户 RSA 密钥。
4. 不增加 audit ignore，不把失败审计写成通过。Cargo.lock 仍会报告该漏洞，保留其可见性。
5. 阶段三前复审：候选修复状态、可替代后端、Agent 签名路径、OpenSSH 实机矩阵。未解决则不给真实 RSA 私钥功能放行。

这些限制不改变 PRD 的密码/私钥/Agent 认证要求；PRD 要求验证算法兼容性并禁止降低安全标准，没有要求接受所有私钥算法。
若最终必须削减明确的产品能力，届时再向用户列出影响和推荐决策，不在本轮擅自改需求。

## 其他审计结果

完整锁文件还有 Linux GTK/Tauri 依赖的 `glib 0.18.5` unsoundness 警告 RUSTSEC-2024-0429，以及 proc-macro-error、zbus_names、zvariant、zvariant_derive 的维护状态警告。
这些包未在本轮 Windows 普通依赖图出现。Linux 发布前必须验证升级或审查回补方案；不能直接把不兼容的 glib 主版本强行替换进 GTK 0.18 依赖链。
完整 npm 审计有 14 个中危告警（由 minimatch 相关开发依赖链传播），生产 npm 审计为 0。未执行强制降级或未经兼容测试的跨主版本 override。

## 验证方式

- 运行 cargo-audit，全量保留非零退出结果，并检查依赖链归属。
- 运行本机 SSH 协议测试，继续验证加密 Ed25519/RSA 合成密钥、错误认证、主机密钥阻断、PTY/多 Channel/SFTP。
- 检查外部 CLI key 分支，在 authenticate_key 之前拒绝 RSA。
- 未来以修复公告、可重复的审计、算法测试与授权真实服务器兼容结果解除门禁，不以“测试通过”替代密码学审查。
