# 0036：Compose 启动配置采用固定读取预授权

- 日期：2026-11-10
- 状态：已接受，补充 [0020](0020-command-preapproval.md)，不改变宿主精确匹配规则。

## 背景与选项

Docker 2.2.4 根据所选容器标签构造动态 `compose config` 命令，每次打开启动配置都触发审批；同时无条件使用 `--no-env-resolution`，在不支持该选项的 Compose 上失败。用户要求读取启动配置免逐次确认并修复报错。

保留动态命令不能达到免确认目标；在宿主新增 Docker 参数白名单、通配预授权或借用交互会话权限会扩大通用授权边界。固定主机快照与现有容器详情读取模式一致，可以由插件独立实现。

## 选择

Docker 2.2.5 新增两条完整固定命令，分别读取隐藏/显式展示环境变量的 Compose 配置。脚本从真实容器标签发现项目，按项目去重并复验所有成员的目录和有序文件一致性。容器 ID、项目名、绝对路径、控制字符及文件数量均校验；参数使用位置参数逐项传递，不使用 eval、命令拼接执行或前端提供的路径，仅调用 Compose help/config 和 Docker 读取命令。

先检查 `compose config --help`，仅在支持时加入 `--no-env-resolution`。旧版允许解析 env_file，环境变量在 WASM 选中 service 后隐藏再返回界面，提示实际解析行为；显式显示仍由用户操作。单个项目失败写入该项目结果及独立诊断段，不阻断其他项目，不能伪装成功。

固定命令受现有 `ssh.execute.preapproved`、当前安装版本、SSH 配置修订及输出/超时上限约束。宿主不增加领域匹配、不放宽其他命令；上传包仍需用户单独授予固定命令预授权。启停、重建和删除不在这两条命令中，既有变更确认保持。

## 后果

启动配置及显式变量读取无需逐次命令确认。为保持完整命令固定，会读取当前主机已发现项目的配置快照；前端仅收到所选容器当前项目的 service，WASM 重新校验项目、成员及标签路径，配置变化或身份丢失明确失败。项目很多或输出很大仍可能触及平台上限，不截断结果、不自动放宽限制。

旧版 Compose 可能读取环境文件；缺少文件、权限不足或配置损坏继续真实失败。当前文件/环境仍不能保证与容器创建时一致，不自动安装或升级 Compose，不写远端配置或更改容器状态。
