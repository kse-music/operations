# ADR 0031：系统应用选择与确认式远程外部编辑

日期：2026-11-10；状态：已接受。扩展 [ADR 0007](0007-safe-files.md) 的编辑范围，原子替换、安全元数据及无服务端 CAS 的边界继续有效。

## 背景与选项

本地文件双击没有打开动作，远端统一尝试 UTF-8 文本，用户不能用本机应用编辑不支持的内容。可选择仅提示下载、自动监控并上传、或者显式外部编辑与确认回传。用户要求外部保存后确认回传；自动监控不能可靠判断外部应用是否保存完成，也可能覆盖他人修改。

## 选择

Windows 显示原生应用选择器，参数只有已校验的普通文件路径，不拼接命令，不自动执行默认关联。原生调用在 STA 工作线程执行，绑定主窗口 owner；其他平台不伪装支持。调用契约参照 [Microsoft SHOpenWithDialog 文档](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenwithdialog)。

远端文件经现有校验下载队列写入数据目录内的独立私有副本，保留原名；副本/远端 hash 与下载前属性一致后才启动应用。后端运行期 token 固定 SFTP 身份、远程目标和本地源，文本与外部文档共用最多八个配额。用户先在外部应用保存，再确认回传；共用原子编辑链路，以流式字节保留非 UTF-8 和二进制。回传两次核对远端原始快照，核对本地稳定性、权限及元数据保留，取消不跨越提交临界区。

不自动回传，不持久化或恢复执行授权。外部会话持续参与关闭/退出保护；结束后保留本地副本和路径，不自动删除，避免外部应用仍持有句柄或修改尚未回传。

## 后果与限制

本机应用及副本不属于插件沙箱，用户选择应用后按本机权限运行。副本会占用磁盘，用户可在结束外部编辑并关闭应用后自行管理。SQLite 等关联多文件格式需要应用自身保证一致性，不提供数据库事务或关联文件同步。SFTP v3 无 CAS、无法保留完整 ACL/xattr/硬链接，断线时可能结果未知；这些边界继续明确显示。

见 [SFTP 外部编辑验证](../../validation/files/VALIDATION_STAGE4.md#2026-11-10-文件打开与外部编辑回传)。原生、回环协议与浏览器夹具分别记录，不将单项通过视为跨平台或真实服务器全量验收。
