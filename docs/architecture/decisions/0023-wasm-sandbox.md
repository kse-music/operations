# ADR 0023：以无 WASI 的 Wasmi 约束插件能力

原决策日期：2026-11-03。状态：有效；SDK5 沿用该运行时取舍。此记录补回原决策中未完整迁出的理由，不是新增功能或新的安全承诺。

## 背景与选项

插件需要跨平台执行，又不能把普通本地子进程误称为沙箱。原方案比较独立 Node 子进程与 WASM：前者需要额外配置各系统文件/网络限制，部署和验证成本较高；后者可通过不导入操作系统能力收敛权限。

## 选择与后果

使用 Wasmi 解释执行 wasm32-unknown-unknown，不接入 WASI 或任意原生导入，外部操作通过已授权平台原语完成。用 fuel 终止死循环、限制线性内存、消息、编译结构、调用栈、并发和活动实例；平台等待通过 async Future 让出，不采用超时后丢弃仍在执行的线程。

它不提供 OS 进程隔离或全进程 OOM 硬上限；壁钟预算在受限入口完成后检查，不是 OS 抢占。运行时漏洞仍可能影响宿主，Web UI 也没有 fuel/CPU/内存硬配额。不能把单项测试通过写成所有恶意输入和平台均安全。

SDK5 的 owner、审批续接和通用能力见[ADR 0016](0016-plugin-platform.md)；精确限额见[运行时](../../plugins/PLUGIN_RUNTIME.md)。原阶段验证和未完成保障见[插件验证记录](../../validation/plugins/PLUGIN_TEST_REPORT.md)。
