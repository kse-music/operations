# ADR 0038：三种审批模式与有界参数化读取

日期：2026-11-11。状态：已实施；完全访问的10分钟期限和切换失效规则由 [0039](0039-session-full-access.md) 部分替代，以下保留原取舍。部分替代 [0035](0035-task-approval-modes.md) 的模式范围与动态读取限制；原计划冻结、逐项复验和单次消费规则继续有效。

## 背景与选项

用户选择“帮我批准”后，CPU/内存诊断中的进程详情仍因 PID 不同而反复确认。用户明确要求按参考图提供请求批准、帮我批准及完全访问权限三种语义。继续只允许完整固定命令会保留该问题；信任插件的 readOnly 声明、用通配符匹配 Shell 或由插件自行启用完全访问，会扩大执行权限。

## 选择

- 请求批准保持逐次询问；帮我批准把已授予的文件读取、传输预检、固定查询和严格参数化读取作为可直接执行的操作，未知命令、写入及其他风险操作请求批准。
- SDK5.3 在现有 Command 数组中增加独立参数模板权限 `operations.read.arguments.preapproved`，仍需基础 SSH 与读取预授权。模板只允许 `sh -c` 固定脚本及固定 `$0`，变化只能位于后续完整 argv 项；仅支持有界十进制整数、定长十六进制和带长度/后缀约束的 ASCII 标识符。没有 Shell 文本替换、任意正则、程序名或脚本文本模板；调用参数仍经 POSIX 引用。助手仅声明经过核对的进程、容器和 systemd 详情脚本。
- 完全访问通过独立 `operations.full.preapproved` 授予，并须在可信宿主中首次确认。批准后创建当前插件、owner、VM 代绑定的运行期策略，最多有效 10 分钟；同一页面有效期内复用，不逐次确认已授予范围内的命令、读写和传输。插件声明或模型字段不能生成此授权。
- 完全访问仍检查当前安装/grant、目录边界、真实连接及配置修订，变更计划继续预检、冻结、限次消费和复查。撤权、关闭页面、插件停止/升级或到期使策略失效。模式固定在发送时，切换不升级已有任务；隐藏页面不自动发起新计划。

## 后果与验证

Host/Rust/Vue SDK 为 5.3.0，新增能力包声明 `^5.3.0`；ABI/wire 1、UI4、Manifest/包/授权记录的字段格式不变，没有数据库或配置迁移。新增权限不会补入旧上传包授权，升级仍按包摘要和修订重新授权；内置包按已有分发流程更新，完全访问仍需宿主首次确认。数据、设置、凭据和旧授权记录不清理、不重置。

风险判断对未列入可信读取模板的命令保持保守；完全访问不增加插件本来没有的功能、目录或系统权限，不自动提权。首次指纹、取消、输出/资源限额和未知结果处理保持。验证见[三种模式报告](../../validation/ai/VALIDATION_ASSISTANT_CHAT.md#2026-11-11-三种审批模式与参数化读取)。
