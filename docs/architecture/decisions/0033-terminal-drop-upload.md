# 0033：通过当前 Shell 接收终端拖放上传

- 日期：2026-11-10
- 状态：已接受

## 背景与选项

终端需要文件/文件夹拖放，且用户执行 sudo -i 后应直接使用该 Shell 的有效身份和当前目录。独立 SFTP 不继承此身份；重新 sudo 会改变授权和交互语义。复用 rz 需服务器安装 lrzsz，目录另需封装；trzsz 增加协议及远端安装要求。

## 选择

用户确认后在原 PTY 启动固定临时接收脚本，使用兼容的 GNU tar/coreutils 等已有命令，不安装软件、不读取 sudo 密码、不新增自动提权。原生拖放登记一次性本地文件授权，Rust 生成规范化 tar，Base64 有界分块及随机任务标识 ACK 隔离协议与普通输出。有效 UID、当前目录、umask 来自接收进程继承，不信任提示符或 OSC 7 作为权限证据。

接收、校验、解包在目标同目录的私有暂存完成，禁止恢复归档属主；目标名称整批预检、逐项不覆盖提交。窗口/会话关闭先确认并等待取消结果；不确定是否退出或恢复终端时不解除输入隔离。原有 rz 和文件页 SFTP 保留各自契约。

确认及进度共用同一 Modal，成功后自动关闭。启动命令至原 Shell 的 RETURN 帧期间不向 xterm 渲染回显、续行提示、诊断或协议；只有接收结果与原 Shell 返回都确认后才结束，保留原终端历史并原地刷新正常提示符。

## 后果与限制

Base64 增加约三分之一传输量，临时归档和解包需要额外磁盘；上传占用当前窗格，不能脱离 PTY 后台续传。无法通用可靠地从 SSH 流识别所有 Shell 提示符，因此确认界面要求用户回到空白提示符，并拒绝已知备用屏幕和特殊会话。服务器缺少基础命令或策略不允许时明确失败，不降级为新 sudo、另开 SFTP 或静默安装。批次提交并非整体事务，失败保留已提交项目；断线可能保留远端暂存。首版不承诺 ACL/xattr、特殊权限、嵌套终端或未实测平台。
