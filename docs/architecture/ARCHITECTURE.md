# ServerDeck 总体架构

本文描述当前模块、数据流、安全边界和资源生命周期。功能见[产品基线](../product/PRD.md)，精确插件契约见[公开 SDK](../plugins/PLUGIN_SDK.md)，候选产物验收见[发布检查表](../release/RELEASE_CHECKLIST.md)。

## 系统边界与工程结构

应用为本地 Tauri 2 + Vue 3/TypeScript/Pinia 客户端，Rust Cargo Workspace 使用 Tokio。通过 SSH/SFTP 管理远端，无 HTTP 业务服务端、云账号或远端 Agent；前端不直接访问 SQLite、凭据库或任意本地 Shell。

| 位置                                        | 职责                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `apps/desktop/src`                          | 页面、组件、工作区、状态、类型化 IPC、主题与交互 |
| `apps/desktop/src-tauri`                    | 组合根、capability、原生交互、窗口和退出协调     |
| `crates/core`                               | 宿主 DTO、配置、校验和安全错误                   |
| `crates/application`                        | 用例编排、资源所有权、有界阻塞工作和关闭协调     |
| `crates/storage` / `security`               | SQLite 与配置升级；系统凭据及秘密生命周期        |
| `crates/ssh` / `sftp`                       | 信任、认证、连接/Channel；文件、传输和原子编辑   |
| `crates/monitor` / `ops`                    | 宿主内部监控与运维服务                           |
| `crates/tasks` / `ai`                       | 有界单次 SSH 执行；模型传输、本地 CLI 与安装器   |
| `crates/plugin-core` / `plugin-runtime`     | 包、仓库、授权与 Wasmi 运行时                    |
| `crates/plugin-sdk` / `packages/plugin-sdk` | 公开协议、WASM async 执行器、TS 客户端和通用 UI  |
| `plugins/system/{assistant,docker}`         | 独立 Vue/WASM 业务，只依赖公开 SDK 和普通库      |
| `crates/windows-file-drag`                  | Windows 文件/磁盘互操作，必要 FFI 收敛于专用模块 |
| `crates/windows-terminal`                   | Windows 本地终端提权与私有进程通信互操作         |
| `tools` / `tests/fixtures`                  | 构建、隔离 QA、探针及不分发的测试夹具            |

主要依赖方向为 `desktop → application → 具体服务 → core`，SSH 读取 storage/security 中的受管配置与秘密，文件/监控/执行复用独立 SSH 租约。模块不反向依赖 UI。

产品版本只在根 `Cargo.toml` 声明。Tauri、平台 Rust 包和关于页继承工作区版本；桌面 dev/build 检查来源并同步工作区锁记录。SDK、插件包和持久格式独立管理版本。关于页发布时间由前端构建生成，按北京时间显示。

## 启动、IPC 与错误

1. 单实例检查并聚焦已有窗口。
2. 在打开数据库/WebView 前解析存储定位及用户明确登记的目录迁移。
3. 初始化安全日志，打开数据库并完成必要升级，加载严格配置后创建 Application 和有界引擎。
4. 逐包分发内置插件，隔离并聚合单插件问题；bootstrap 返回真实状态。
5. 前端初始化工作区并显示欢迎页，不恢复终端或自动连接。

初始化失败保留原数据并提供诊断，不创建空库伪装成功；模型配置故障按需隔离，不阻断主机启动。

```text
Vue / Pinia → 类型化 invoke → Tauri capability → Application
  → DTO / 权限 / 目标 / 修订校验 → 具体服务或有界 spawn_blocking
  → 结果 DTO / IpcError → 状态与通知
```

Rust/TS 显式维护 camelCase DTO，拒绝未知字段。秘密读取不开放给前端；浏览器预览显示后端未连接，不提供假数据。`IpcError = {code,message}` 提供安全文案，Rust 保留 source 原因链，不把 SQL、输入正文或敏感参数写入日志。已提交变更和待清理警告分别表达。

错误通过有界通知 Store 去重展示，弹窗中仍可交互；状态、重试、原始业务输出和安全确认独立保留。

## 工作区、设置和语言

Workspace 将全局入口 `area`（首页、本地终端、设置）与运行期设备/插件标签分开管理；切换入口只改变可见性，保留首页活动标签、本地最近会话及设置分类。`homeTabs` 从运行期标签中过滤本地工作区，首页标签渲染、批量关闭范围与关闭后的相邻选择均使用该列表；本地会话保留于本地终端入口，无首页标签时回到“首页”欢迎页。HostId 是持久目标，活动页变化不能修改已有资源的目标。`HostTools` 平铺 SSH/SFTP 和启用插件，主机保存本次打开期间的最近工具、会话和路径。

首页没有活动工作区或选择“首页”标签时，`WelcomeView` 以限宽卡片展示本地终端、新建主机和 SSH 配置导入，发出事件由 `App` 复用已有导航与弹窗流程；组件不创建连接或维护业务状态。键盘提示读取已保存的搜索快捷键并展示连接选中主机的 Enter 键，布局按工作区容器宽度改为单列。主机标题不提供新增或收起按钮，新建入口保留在欢迎页和文件夹右键菜单。

主窗口默认 1280×820，最小 960×600 逻辑像素；恢复时按当前最小尺寸及显示器约束放大已存尺寸。resize/显示缩放事件在保存普通窗口尺寸前复核内容区域最小尺寸，纠正无系统装饰窗口的原生边框偏差，不保存低于限制的尺寸；最小化、全屏和最大化不执行该纠正。`AppNavigation` 固定在第一栏，`HostSidebar`、本地会话列表和 `SettingsNavigation` 共享始终常驻的第二栏；第三栏为内容工作区。第二栏复用 `sidebarWidth` 配置及拖动保存，不变更配置格式。`TerminalsView` 将本地会话头通过 Teleport 放入第二栏，复用原会话行为；SSH 会话头仍在第三栏工具栏，所有 PaneKey 和 xterm 实例保持。

主窗口关闭系统窗口装饰，由 `AppHeader` 合并标题栏与工具栏，沿用主题变量。Windows WebView 使用 `app-region: drag` 识别原生拖动区域，按钮显式使用 `no-drag`；Tauri 的 `data-tauri-drag-region="deep"` 为其他运行时提供非交互区域拖动与双击最大化，按钮由运行时排除。`useWindowControls` 通过当前窗口 API 最小化、切换最大化和请求关闭，并监听 resize 同步最大化/还原图标，卸载时释放监听；调用失败进入统一错误通知，浏览器预览不创建窗口 API。主窗口 capability 只增加所需窗口权限，不向插件或独立编辑器开放；关闭调用 `Window.close()` 触发已有 Rust `CloseRequested` 审核，再由确认退出用例排空资源，不直接销毁窗口或退出进程。

主窗口与独立编辑窗口创建时，通过 Tauri `initialization_script_for_all_frames` 在文档脚本执行前向顶层页面及所有子框架注入统一的 `contextmenu` 捕获监听。监听只调用 `preventDefault`，不阻止事件传播，屏蔽浏览器默认菜单并保留业务菜单；覆盖受限插件 iframe，无需修改或重装插件包。主界面保留前端监听以支持浏览器预览。

`SettingsView` 在第三栏按需挂载并在全局切换时保持。`useSettingsAutosave` 管理偏好草稿和已保存基线：通用、终端、快捷键、数据与存储的普通偏好在修改后以 300ms 防抖校验并串行保存，写入使用独立快照，保存期间的新修改继续排队；外部配置更新合并未编辑字段。下载目录、传输并发和日志级别直接复用同一自动保存链路。数据根目录由迁移状态独立维护，不进入偏好写入载荷，也不参与普通偏好的表单有效性校验；仅独立的“迁移并重启”入口校验完整表单并打开迁移预览，确认后沿用既有迁移和重启协议。校验失败不写入，存储失败保留草稿并允许重试。关闭设置先尝试提交有效的待保存偏好，再复用剩余修改的放弃确认；界面字号即时预览，成功后持久生效。模型和插件分别保存，模型的本地/远程 Tab 不因切换全局入口中断下载。设置忙碌状态阻止入口与分类切换。工作区插件配置统一进入设置页面；业务页隐藏时 `active=false`，返回时复用原 owner 和页面。配置写入成功只向同插件推送运行期 `settingsRevision`，不广播正文或强制刷新业务列表。

已保存的 `zh-CN`/`en-US` 驱动响应式界面语言，桌面、SDK 和内置插件各自维护字典。只翻译 UI，用户内容和原始诊断保持原文。插件通过公开 context 接收语言，不重挂载页面或重新授权；独立编辑器下次打开读取偏好。配置不可读的启动错误采用双语。

桌面和内置插件共享 SDK 基础控件样式。单选下拉框在支持 `appearance: base-select` 的运行时使用浏览器可定制选项层，以主题 `--accent-bg` 显示选中、悬停及键盘定位状态，保留原生 select 的值、禁用、校验与 Vue 绑定；旧运行时沿用原生控件。目录等自定义选择器复用同一背景色，全局搜索独立维护未选择或活动结果索引，输入焦点不自动选择第一项。

关闭主机先禁止新提交，审核文档/草稿、确认取消传输，再排空提交与清理，关闭文件租约、终端和插件 owner；成功后清除该主机临时记录，失败保留工作区。切页仅隐藏，不执行关闭流程。宿主为仍打开的工作区保留插件命令流和运行期任务；Assist/Full仅继续符合精确自动审批规则的步骤，高风险计划等待返回可见页。交互PTY仍在隐藏时关闭，关闭owner或撤权释放自有命令流和传输。

## 主机与凭据

### 主机目录、测试和导入

SQLite 持久化 HostId、多级文件夹及 SSH 参数。文件夹防环，删除时事务性提升主机和直接子文件夹。主机按名称/地址/用户名搜索，保留现存数据库附加数据但不将其作为当前 DTO。

`host_test` 使用完整草稿和实际路由握手、核验指纹并认证，完成即断开。五分钟单次结果绑定草稿、原主机、路由和凭据修订；tested 创建/更新提交前复验。移动、复制和导入使用各自受控用例。

OpenSSH Config 解析限 1 MiB、10000 行、500 个明确别名。支持 Host/HostName/Port/User/IdentityFile/超时/Keepalive 和受管 ProxyJump，遵循 first-value-wins。通配符不展开资产，不执行 ProxyCommand；Include/Match、多身份或未知关键项无法安全确定时拒绝。跳板最多四层，拒绝循环、缺失和冲突。提交重新解析并按依赖事务导入，重复跳过，不覆盖或写回原文件。

导入目标由 `HostFolderPicker` 复用 `hostFolderRows` 和祖先路径计算渲染目录树，仅管理选择与展开状态；`ImportDialog` 继续将选中目录 ID（根目录为 null）传入原导入接口。目录菜单使用弹窗内的原生 Popover 顶层显示，按视口空间选择向上或向下展开并限制高度，避免受弹窗滚动区域裁剪；忙碌时禁用选择并关闭菜单。

### 秘密与一致性

NativeStore 使用系统凭据库，服务名 `cn.hiboot.desktop.credentials.v1`；SQLite 只存 opaque 引用、类型和 revision，秘密 DTO 不实现 Debug/Serialize，Rust 使用 Zeroizing。

新秘密先登记 `secret_gc` 意图，再写新系统 entry；SQLite 事务切换引用，提交后清理旧 entry，失败补偿或保留重试意图。主机认证变更创建独立凭据，不改写其他主机仍在使用的共享认证；显式共享凭据不自动删除。系统库不可用明确失败。

## SSH 和终端

持久 HostId 与运行期 ConnectionId/SessionId/TaskId 分离。Transport 复用键包括主机、端点、用户、认证/秘密修订、跳板链、代理和超时；配置变化不能复用旧认证上下文。

```text
连接：Disconnected → Connecting → AwaitingHostTrust → Authenticating → Connected
      → Disconnecting → Disconnected / Failed
会话：Creating → Running → Closing → Closed / Failed
```

应用自己的 known-hosts 按规范 hostname+port 保存完整公钥、SHA-256 和信任时间。未知主机认证前等待用户核验，challenge 60 秒；已知密钥变化硬拒绝，证书默认拒绝。系统 known_hosts 哈希/CA/撤销未接入。私钥导入与路径认证共用解析和解锁，支持 Ed25519/ECDSA/RSA；RSA 按服务器 `server-sig-algs` 协商 SHA-512 或 SHA-256，未声明 SHA-2 时返回 `SSH_RSA_SHA2_REQUIRED`，不使用 SHA-1。工作区固定 russh 上游提交以使用已修复 RUSTSEC-2023-0071 的 `rsa 0.10.0`，具体依赖及审计边界见[安全说明](../release/SECURITY.md#日志依赖与发布)。

每终端拥有独立 PTY、取消令牌和任务；文件、Monitor、执行分别持租约。关闭一个 Channel 不误关其他租约，无引用时释放 Transport。同步锁只覆盖短注册表操作，不跨 await。

Windows 管理员本地终端由 `crates/windows-terminal` 封装 `ShellExecuteExW(runas)`、进程令牌查询、命名管道身份校验和 Job Object。宿主只通过主窗口专用 IPC 请求启动当前 EXE 的固定 PTY 代理模式；代理在 Tauri、单实例、存储、凭据和插件初始化前分流，仅运行既有本地终端引擎。系统 UAC 只提升该代理及其 PowerShell，主程序不重启、不提权，不接受自定义程序、命令或 Shell 路径。

每个代理使用独占随机命名管道，拒绝远程客户端，ACL 仅允许当前用户、管理员和 Local System。宿主以 UAC 返回的进程句柄核验管道客户端 PID，代理核验服务端 PID 与宿主 EXE 路径，且使用 identification 级连接禁止宿主模拟管理员令牌。协议有版本与帧长上限，输入、尺寸、序号沿用本地引擎校验；输出继续按 xterm ACK 背压。代理先确认实际提权，再建立 PTY；断线、取消、超时与退出触发清理，Job Object 在代理退出时回收受管后代，主程序等待代理退出后完成会话回收。UAC 提示尚未响应时不能强行关闭系统授权窗口，应用退出须先等待用户允许或取消；等待超时保留工作区并报告失败。该能力不开放给插件。

PTY 每块最多 16 KiB，经 Tauri Channel 送入 xterm，写入回调 ACK 后读取下一块；输入/resize 独立且有界，resize 合并。russh 内部仍有非全有界队列，不承诺恶意服务器下进程硬内存限额。

前端 Tab、PaneKey、Session 分离，分屏二叉树只算几何，固定 PaneKey 保持 xterm；每标签最多八窗格，全应用最多 32。generation 隔离迟到输出、剪贴板和连接结果。重连先安全关闭旧 Session，再按序列清空终端状态并开新 Shell，不重放动作/票据；断开保留画面，非连接状态禁输入并停止光标闪烁。

后台窗格及离开终端页后的工作区保持挂载，移出视口并以 visibility 隐藏，使用 inert 和 aria-hidden 禁止交互及辅助技术访问；继续处理输出、协议和 ACK，不重建 Shell。保留可测量的字体布局，避免 display:none 下 xterm DOM 选区刷新反复得到零字符宽度、无法缓存并挤占前台线程；视口外的常规绘制由 xterm 自身暂停。回到前台后重新适配几何与焦点。

状态栏只订阅当前可见窗格，从 SSH 握手读取目标实际算法，从 xterm 读取行列和光标，不额外执行远程命令。HTTP/HTTPS 链接经专用 IPC 校验后交系统浏览器。剪贴板仅用户动作触发，单次最多 2 MiB，大粘贴先确认。窗口 resize 可强制可见普通缓冲到底部，其他布局适配保留用户历史阅读。终端内容、布局与会话不持久恢复。

首跳支持 SOCKS5/HTTP CONNECT，跳板通过嵌套 SSH 逐跳信任。底层转发归 Session 所有，默认回环、公共绑定确认、断线释放，不自动恢复；当前 UI 无管理入口。

rz 经原生选择器发放绑定终端的一次性文件句柄，与普通输入隔离。文件按 64 KiB 读取，每批复验大小和修改时间，使用二进制 IPC 返回前端；最多预读下一块，与当前批次发送重叠。`ZmodemUpload` 将编解码器同步产生的子包合并为有序二进制批次，每批上限 256 KiB，通过主窗口专用 IPC 提交；请求头绑定原终端和文件授权，拒绝拖放授权、过期授权及同一授权的并发写入。Rust 在原 SSH 输入队列中按 16 KiB 分次等待容量，保留普通终端输入的大小限制和输出 ACK。取消先停止读取，再等待在途批次和取消帧按序发送，最后释放文件授权；发送超时或在途授权失效时关闭原会话，隔离未确认的数据。文件载荷不经 JSON 数字数组，不新增 SSH 连接或 SFTP 身份。

`ZmodemUpload` 将所选文件和当前文件进度交给 `TerminalZmodemUpload`，复用 `Modal` 及终端拖放上传样式。`choosing` 状态仅维持协议占用和输入隔离；选择器返回非空文件列表且离开该状态后才挂载 `Modal`，取消选择后的空列表 `finishing` 也不挂载弹窗或触发弹窗关闭后的焦点恢复。每个文件获准接收后以单调时钟计时，传输进度刷新最多每 100 毫秒一次，每秒及阶段变化强制刷新；速度只统计本次发送字节，不将远端已有偏移计入吞吐。文件结束、取消、失败及销毁停止计时，最终确认阶段保留最后一个文件统计并隐藏速度和剩余时间估算。关闭按钮、Esc 和取消按钮共用取消入口，取消中禁用重复操作，原生文件授权释放处理结束后才清除弹窗，释放失败经既有错误通知报告；恢复焦点前复验会话、可见性和其他弹窗。ZMODEM 不提供接收账户和目录，不额外执行远程命令推测。

当前 Shell 拖放使用原生一次性授权，经原 PTY 的固定接收脚本继承真实用户与目录，包括 sudo/su 切换后的身份；不创建其他身份的 SFTP 连接。单个普通文件仅校验路径与元数据并保留原文件句柄，准备阶段不读取载荷或创建副本；文件夹或多选经受限扫描生成临时 tar，打包读取持续检查取消。两种来源都由阻塞工作线程在每块读取时累计 SHA-256，不再预先通读归档；每块及最后一块发送后复验源大小和修改时间。Rust 取得该终端的独占二进制收发租约，接收期间拒绝普通输入，前端清除未发送的旧输入并只订阅进度。SSH 输出在后端路由到有界接收队列，隐藏启动回显、协议和诊断；RETURN 标记后的普通输出重新走既有 WebView ACK，并就地刷新提示符。异常退出、无效协议或无法确认终端恢复时结束原 SSH 会话，避免遗留数据进入 Shell，不影响其他窗格。拒绝链接和特殊文件，与 rz 互斥，不保证断线清理或跨重启恢复。

文件或归档由 Rust 分块读取并直接发送原始二进制，最多两个 4 MiB 分块在途；输入队列最多八个 64 KiB 消息，接收队列最多八个 SSH 数据消息，文件载荷不经过前端或 Base64。接收脚本保存终端设置后启用 raw 模式，每帧为 `D`、七位补零十进制长度及对应载荷，通过 `head -c` 精确读取头部；所有数据确认后发送 `F` 和 64 位小写十六进制 SHA-256，同样精确读取。不在原始终端流上使用 Shell `read`，避免 Bash 4.2 预读缓冲吞入后续二进制字节。使用 GNU `tee -a` 向普通文件追加并向 `wc` 传递完整输入，不要求较新版本的 `--output-error` 参数。普通文件写失败仍排空该帧，再以实际文件长度检查失败；短读或失去帧边界时隔离数据并关闭该会话。ACK 为累计确认字节数，必须匹配在途队列。取消通过帧边界的控制消息处理，先发送完已声明分块，再排空接收；校验和解包进程可单独停止并等待结束。远端 SHA-256 通过后，单文件收紧至 0644 或原 umask 所允许的更严格权限，在私有暂存中重命名，无需再次复制或解包；归档执行解包。整批冲突预检后，由客户端显式允许提交；最终结果再经释放确认和 RETURN 恢复边界交付，保留已提交项目和清理失败的恢复路径。会话关闭事件先于上传 IPC 失败返回时，仍在保留的上传弹窗中显示后端具体原因；组件卸载后不再更新旧弹窗。

接收脚本通过 `id -u`、`id -un` 和 `pwd -P` 返回实际身份与目录；单文件名称经本地校验后作为 Base64 参数传入，不拼接为 Shell 语法。仅这些少量元数据使用 Base64；账户名称查询失败只保留 UID。Rust 从 READY 后以单调时钟计算已用时间，每半秒、阶段变化及确认数据时推送快照，前端不另建计时器；容量和传输阶段的平均速度只统计远端已确认的文件或归档字节。弹窗复用文件传输的时长格式，以平均速度估算剩余数据传输时间，校验和提交不提供时间估算。吞吐仍受 PTY、加密、磁盘及多选归档开销影响，不将 SFTP 的实测速度直接作为此链路保证。

上传元数据中的修改时间使用 Unix 整秒，不在传输层应用时区偏移。`TerminalUploadFile.modified` 从已授权文件句柄读取，rz 通过 ZMODEM 文件 offer 的 `mtime` 发送；拖放归档头取源元数据，单文件在固定接收脚本中通过 GNU `touch -m -d @秒数` 设置暂存文件修改时间，失败返回 `METADATA` 并安全恢复终端。mtime 不包含源创建时间或 Unix ctime。

## SFTP、传输和编辑

SFTP 上传及单文件中转在校验后、提交前调用 `Remote::preserve_modified`，使用源快照中的 mtime。SFTP v3 必须同时发送 atime/mtime，因此保留暂存文件的 atime，仅替换 mtime，并重新读取属性核验。覆盖时原有属主和权限保留逻辑独立执行；时间设置失败不会替换目标。源时间在本地转换为协议支持的 `u32` Unix 秒，缺失或超范围时明确报错。递归上传对普通文件逐个执行，合并目录不恢复目录时间。

普通 Files 租约请求 SFTP 子系统，各传输独立 Channel，请求、扫描和响应有界。Files Store 按 HostId 保存本地浏览状态（目录列表、加载态、待访问路径、请求代号及后退/前进历史），远程状态归各主机连接；活动主机只决定当前展示。异步读取、连接初始化和刷新绑定发起主机，同一栏按请求代号丢弃旧响应，失败保留原目录。主机工作区成功关闭后清除其本地浏览状态并使在途响应失效，状态仅在内存保留。Windows 磁盘枚举通过专用原生接口，不启动 Shell；目录下拉只是规范路径提示，不授予权限。桌面和插件共用 SDK `paths.displayLocalPath`，仅在本地路径的展示与复制时将扩展盘符/UNC 路径转换为普通形式；原生插件传输确认采用相同显示规则。Store、授权、传输及未修改的目录输入继续使用原始路径，不处理远程路径或其他 Windows 命名空间。

`files_switch_user` 仅主窗口可用，通过当前 SSH 账号 sudo 权限运行目标用户外部 sftp-server，不复用其他 Files 租约。候选通道读取成功且原连接无传输/文档才切换；失败释放候选并保留原连接。固定包装、唯一密码提示、无 PTY、超时/关闭清理，sudo 密码只留租约内存；插件只使用登录用户租约。

传输状态为 queued/scanning/running/verifying/completed 或 cancelling/cancelled/failed。默认每主机三个活动任务、可配置 1–6，全局最多 12 活动；降低并发不抢占已开始任务。界面冲突策略为 fail/skip/overwrite，底层还支持 rename；任务不跨进程恢复。

桌面传输快照 `TransferInfo.elapsedSeconds` 使用单调时钟累计每个文件的数据读写阶段；`bytesPerSecond` 以累计已传字节除以累计传输时间计算，不计排队、扫描、校验和提交。上传、下载和插件中转在有界请求排空后、EOF/属性复核及句柄关闭前切换为 verifying 并暂停时钟；下一文件开始数据读写时恢复累计。数据阶段作用域结束或取消请求会停止时钟，防止异常清理改变统计；校验期间及终态的传输用时、平均速度保持固定，前端随既有轮询更新，不按组件挂载时间另建计时器。剩余数据传输时间以 `remainingBytes / bytesPerSecond` 向上取整估算；未知速度、校验和终态分别展示估算中、校验中、零或不可用，不将其作为整体完成承诺。此字段属于桌面 IPC 快照，插件公开传输契约仍使用独立 DTO。

`FilesView` 将当前 HostId 的未完成任务（含窗口外拖放的暂存下载）交给现有 `Modal` 和 `TransferPanel`，进度弹窗通过主窗口 DOM 渲染，不创建额外 Tauri 窗口或 IPC 权限。按任务 ID 的新增打开弹窗，普通快照刷新保持用户的隐藏选择；当前主机任务排空后关闭，已结束的普通任务仍从记录弹窗查看。X/Esc 在点击时冻结弹窗内任务 ID，逐个请求取消并汇总失败，不影响其他主机或之后新增的任务；请求及清理期间禁用重复取消，失败显示安全原因并允许重试。“后台传输”仅隐藏弹窗。离开文件页卸载弹窗，任务和轮询继续由 Files Store 管理。

桌面快照 `TransferInfo.dragExport` 标记 Windows Shell 托管的暂存下载。`files_drag_download` 通过 OLE 的 FileGroupDescriptor/FileContents 交付虚拟文件，Shell 负责最终目标的复制；文件描述符不设置 `FD_PROGRESSUI`，由应用显示下载进度。活动拖放任务参与应用弹窗和取消，目标使用拖放文件夹提示，隐藏内部暂存目录；终态拖放任务仍不进入传输历史。该标记不改变队列、清理、未完成任务计数及退出/关闭/切换身份的保护。原生回归使用真实 Shell 文件夹目标验证字节交付，并观察测试进程是否弹出系统窗口。插件传输使用原独立 DTO，不继承此标记。

上传/下载在目标同目录独占暂存、流式写入并回读 SHA-256，复验源和目标后受控提交。递归不跟随链接，显式文件链接在读取及提交前复核。提交临界区等待结果，取消不撤销已提交内容，清理失败给出恢复路径。Windows 窗口外拖放用 Shell 虚拟文件按需读取，共用传输校验。

SSH 使用 2 MiB 接收窗口和 32 KiB 最大数据包，避免小窗口限制大文件下载及校验回读；终端仍按独立的 16 KiB UI ACK 控制输出。文件页上传/下载、插件上传/服务器间中转及远端 SHA-256 回读共用最多 32 个 32 KiB 分块的有界 SFTP 窗口。文件页本地读写增加 1 MiB 缓冲，降低逐块调度文件 I/O 的开销；摘要和本地写入保持文件偏移顺序。取消和首个 I/O 错误停止提交新请求，排空在途请求、关闭句柄后再清理暂存，不以丢弃传输 Future 代替正常取消。保留源/目标属性复验、SHA-256、覆盖策略及原子提交。服务器间字节经过桌面本机中转，吞吐受各段链路、加密与磁盘影响。

### 编辑器边界

Monaco/worker 本地按需加载，桌面一次打开一个内置或外部文档；底层八文档配额不代表桌面多窗口编辑。内置文本限严格 UTF-8 普通文件 2 MiB。保存核对原始 hash、大小、时间和 uid/gid/mode，暂存后保留并复核基础元数据，使用 OpenSSH posix-rename；失败不降级 unlink 或原地截断。

`editor_open` 绑定唯一文档并创建独立顶层 WebviewWindow。专用 capability 仅允许实际调用窗口绑定文档的加载、dirty、保存、重读、关闭和剪贴板；主窗口只接收摘要，不同步正文。读取/保存/关闭互斥，失败保留草稿。编辑器打开期间阻止所属连接关闭、切用户、数据目录迁移和页面重载；意外关闭没有持久草稿恢复。

Windows 外部编辑下载至独立 `external-edits/edit-*`，属性与哈希校验后才交系统选择器；原生 token 固定远程身份/路径及本地副本，回传须用户确认并复用冲突/原子保存。外部会话持续计入关闭保护，副本结束后保留，不自动恢复授权。二进制不转换编码。

原子替换改变 inode，SFTP v3 无服务端 CAS，ACL/xattr/硬链接及最终检查至 rename 竞态不能完整保证；提交后断线可能未知，须重新核对。插件文件请求另受更小配额和授权根约束，见 SDK。

## 插件和模型

插件包构建时间由统一打包器写入可选 manifest 元数据，仓库校验后随安装快照传给设置列表，由前端按北京时间统一格式化为 `YYYY-MM-DD HH:mm:ss`；精确字段见[包格式](../plugins/PLUGIN_PACKAGE_FORMAT.md#构建时间)。旧包缺少时间时保持未知，不改写安装记录、不推断历史时间，也不改变权限和执行协议。

Host/Rust/TS SDK 5.7.0，UI 4、ABI/wire 1。独立前端在受限 iframe，通过认证 MessageChannel 调用本包 action 和通用平台能力；WASM 无 WASI，受 fuel、内存、消息和并发限额。完整包、权限和生命周期见[插件架构](../plugins/PLUGIN_ARCHITECTURE.md)及[公开 SDK](../plugins/PLUGIN_SDK.md)。

一个安装修订共享有界 VM，每页有可信 owner；资源绑定插件/安装/VM/owner，目标另绑定 SSH 或模型修订。审批保存原 Future/请求，批准或拒绝从原等待点续接，不重跑动作。固定命令、交互会话和任务读取预授权是独立权限，不能互相替代或推断只读；完全访问由宿主首次批准并在当前会话持续有效，撤销不得被迟到批准恢复。

system 来源由宿主从发行内置包写入，仅影响分发和预置授权；上传包默认禁用/未授权，同 ID 不继承来源。构建自动发现完整源码目录，统一校验和安装；单插件记录故障隔离，原件保留。用户明确备份重装后新记录默认禁用且不继承旧授权。库存快照的 `availableBundled` 只列出无安装记录的当前嵌入包；恢复 IPC 用空记录摘要表示预期未安装，仓库再次校验缺失状态并以系统来源安装，拒绝覆盖正常或损坏记录。非空摘要继续绑定原损坏记录并先备份。恢复保留已有配置、重新生成当前系统预置授权且默认禁用，不修改既有卸载标记策略。包尚无密码学签名验证。

Docker 管理页面、Compose、解析和日常容器/镜像命令归 Docker 插件；资产匹配、脱敏、提示词、连续工具循环、计划及按需 Skill 加载归助手。匹配与执行都使用成对对话历史及明确的入口主机上下文，任务需要来源且未另行指定时采用当前工作区；保留运维所需的主机地址和原始匹配 ID，凭据继续脱敏。两个插件复用独立的镜像归档脚本模块，导出使用固定脚本与受限 argv，宿主的普通执行和长任务通道共用严格模板及审批模式校验。助手由模型组合镜像导出/导入、普通传输等工具并复查目标镜像 ID/标签，不在执行器中固定迁移流程。宿主只提供连接/执行/文件/模型/审批等原语，不按插件 ID 提供业务后门。助手工具、任务、局部文件修改、传输、流式脱敏和限额见[助手架构](ASSISTANT_AGENT.md)。

Docker 镜像归档由插件编排本机选择、SFTP 队列及受主机修订绑定的长命令流，使用独立的 `sftp.transfer.preapproved` 与交互预授权，使点击操作后无需逐次确认，不受单次 Execute 的 30 秒限额限制。命令流在 `/tmp/serverdeck-image-<nonce>/` 创建私有目录，导入等待原子上传文件后 load，导出复核标签指向完整 ID 后 save 并等待下载；完成标记绑定随机 nonce。UI 先取消并排空文件传输，再停止命令流；远端脚本跟踪并终止子 CLI，退出时仅删除已知归档并尝试移除空目录，不递归清理未知内容。SSH 断线与异常退出无法保证远端收尾，失败显示暂存位置，Docker daemon 已接受的变更不保证回滚。通用下载原语复用 SFTP 的暂存、双端 SHA-256 和不覆盖提交，并持续校验 owner、安装、权限、SSH 及配置修订；宿主不理解镜像或执行 Docker 专用逻辑。镜像页面按原生传输状态与实际字节数区分传输、校验提交、Docker 加载及清理；字节传完即隐藏吞吐速度，收到已校验的 completed 后才继续下一阶段，清理返回后才报告整体成功。远端 SHA-256 通过 SFTP 回读，可能在字节进度已满后继续占用网络和磁盘。

Docker 工作区的全局统计由 `docker-summary.ts` 独立于缓存页签管理，复用插件已有的 capabilities、images、containers、compose_projects 四种只读查询，不新增宿主原语或权限。每项独立发布结果及错误，刷新批次号在主机、连接、可见性变化和销毁时使旧响应失效；普通页签切换和搜索不触发统计重载。`ResourceView` 仅加载当前列表和按需详情，通过刷新事件在用户刷新、变更成功及镜像传输完成后更新全局统计；不再缓存各页的 Docker 能力信息或提供其详情弹窗。

镜像行内远程传输复用上述归档流：插件从公开主机目录选择其它目标，用现有镜像列表查询取得目标标签快照；冲突由用户明确确认后才开始导出。源 save 成功后开启目标接收流，再调用通用 `transfer_prepare` 的 remote 来源与目标目录，经 Native SFTP 有界窗口中转，不在本机落地完整归档。接收脚本在 load 前复查标签仍指向用户检查的 ID（或仍不存在），源导出在远端对平台、非空配置字段及有序 RootFS 层摘要计算 SHA-256，只将摘要作为 nonce 绑定的元数据传回；load 后以相同规则复核内容再发送完成标记。默认空字段统一省略，兼容 Docker API 的空值展示差异；不比较不同存储实现的显示 ID。带标签镜像核对所选标签，无标签从本次 load 输出取得目标实际 ID 后核对。当前校验针对 inspect 的默认平台，不证明多平台索引中的全部平台一致。取消和失败先关闭并排空传输，再分别停止目标与来源归档流，两端收尾错误均保留并显示主机及暂存目录。失败批次中的末尾输出在报告终态前保存，命令失败不使用日志业务文案；弹窗保留失败状态及原始输出，错误详情只发一次全局通知。源与目标都使用既有 SSH 指纹、主机修订、目录权限和生命周期约束，不新增 SDK 或宿主 Docker 接口；Docker 无原子标签锁，最终复查到 load 间仍有外部并发竞态。

远程模型注册/关键修改先测试，300 秒单次凭证绑定配置、Key 和编辑身份；Key 不回显，更改地址须新输入或明确清除。模型修订变化使旧请求/计划失效。流式传输只承载真实上游增量，由插件解析和最终校验；片段不能批准执行。

本地 Codex/Claude Code 独立授权，由 CLI 管理登录；Native 保存授权/版本和配置摘要，不导入登录秘密。临时目录、会话、有界 I/O、禁用工具/hooks/MCP 及进程取消控制执行面。安装器单并发，从固定官方源校验并原子安装到应用专用目录，不改 PATH 或覆盖用户程序；自动下载覆盖 Windows x64/ARM64，其他平台手动准备。

## 软件更新

桌面组合根注册 Tauri 官方 updater，`update_commands` 持有有界单操作状态、取消信号、已核验的候选更新及内存安装包。前端更新 Store 在 bootstrap 就绪后延迟发起自动检查，关于页展示状态，导航显示更新提示；页面切换不释放下载。仅主窗口获得本应用的窄更新 IPC，不向任何窗口授予 updater 原生安装权限，插件和独立编辑器不能绕过退出协调直接安装。

更新源为 `kse-music/operations` GitHub Releases 的固定 `latest.json`，只接受更高正式版本，安装包 URL 必须精确对应同仓库、同版本的 NSIS 文件。运行期同时检查 Windows x64 和 NSIS 安装标记，开发版、独立 EXE 与其他平台不执行应用内更新，避免覆盖构建目录或错误改变安装范围。请求与重定向限定 HTTPS；更新器强制验证编译内置公钥及签名中的版本。更新说明按纯文本显示并限 64 KiB，安装包限 512 MiB；检查与下载分别有超时及可取消生命周期，普通退出先取消并排空更新请求。下载完成事件不代表校验完成，只有签名校验成功才进入可安装状态。安装包不持久化，进程退出后重新下载。

更新偏好以独立 `software_updates` 设置项保存，格式 v1，字段为自动检查开关、最近尝试与最近成功检查时间；不改变 SQLite schema 或应用主配置 v2。不存在时使用固定 v1 默认值，未知字段及未来版本按需拒绝，不重置原值或阻断主业务启动。所有读写沿用 Application 的有界存储执行器，避免偏好保存与检查记录相互覆盖；失败尝试也计入自动检查的每日限制。

“安装并重启”先由前端复用设置草稿守卫和退出确认，再由 Native 核对已校验包、编辑器操作及目录迁移状态。安装标记不能与目录迁移并发；普通退出处理器先刷新窗口状态、取消更新网络请求、排空 Application，再在阻塞工作中调用官方安装器。Windows updater 成功启动安装器后会直接结束进程，因此提前完成资源排空并在 before-exit 钩子刷新日志；若启动失败，通过原生提示后正常重启当前应用，不把已排空的实例继续当作可用工作台。安装器接管后的失败结果需用户核对，不能宣称安装成功或自动恢复数据库。发布步骤与密钥管理见[更新分发](../release/UPDATES.md)。

## 持久化、日志与退出

当前 SQLite schema 为 11，应用偏好为 v2，模型注册为 v3。模型首次保存时由存储层记录 UTC 注册时间，后续编辑保留原值；历史模型时间为 null，列表按本机时区及界面语言显示时间，null 显示“未知”。数据升级是现行能力，连续 SQL、固定配置转换、迁移历史及备份规则见[数据升级契约](DATA_MIGRATIONS.md)。数据库内保留的兼容数据不自动加载为功能或授权。应用设置不保存密码、私钥、模型 Key 或对话正文。

SQLite/系统库阻塞工作进入有界 `spawn_blocking`；元数据单任务，最多 16 个在途/等待，等待三秒后 BUSY。数据库 busy timeout 五秒，业务连接启用外键，不引入连接池或主动 WAL 模式。

数据根由默认配置位置的 `storage-location.json` 定位。用户主动搬迁时正常退出，再在目标专用暂存复制、核对清单/摘要/数据库并启动确认，随后逐文件核验清理源；链接、非空/嵌套目标拒绝，变化或未知源文件保留。Copied 未确认可回到源，Committed 不回退部分清理的源；系统凭据不复制。Windows 等待源写句柄释放后再快照，持续占用或校验失败保留原数据和失败证据。

迁移 IPC 成功仅表示登记并安排重启，不能显示为搬迁完成；`app_storage_ready` 返回本次启动的新结果用于通知，持久结果留设置页，不在普通启动重复弹出。准备失败解除忙碌并保留草稿。

tracing 只记安全类别，不记敏感载荷，依赖日志默认关闭；数据库升级前以 Info 初始化，之后读取保存级别。队列 512 条，当前及三个轮转文件各 1 MiB，总量 4 MiB，超额日志丢弃不吞业务错误。

确认退出后拒绝新用例，取消并排空安装、插件/VM、模型、上传及本地终端，再释放执行、Ops、Monitor、文件和 SSH/转发，最后等待元数据并刷新日志。取消退出保留原状态，不通过强杀代替正常退出。
