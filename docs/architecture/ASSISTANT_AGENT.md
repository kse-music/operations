# AI 运维助手：工具、文件与运行期任务

## 当前范围

前两阶段复用 Rust/WASM 和 SDK5.2，不引入外部 Agent 框架、运行时或数据库。助手拥有工具目录、模型协议、参数检查、完整证据、局部文件修改、计划和复查；Native 负责真实 SSH/SFTP、模型传输、权限、宿主审批及 owner/安装/VM/目标修订复验。工具声明不能代替授权。

已实现远程文件预览/确认保存、本机上传与服务器间中转。Skill、MCP、步骤依赖/重新规划和跨重启恢复尚未实现。阶段划分见[实施计划](../product/IMPLEMENTATION_PLAN.md#ai-运维智能体演进)，取舍见 [ADR 0033](decisions/0033-assistant-tools-tasks.md)、[ADR 0034](decisions/0034-plugin-file-transfers.md)。

## 工具目录与结果

`plugins/system/assistant/backend/src/tools.rs` 提供工具 ID、名称、read/change 类型、所需平台权限和完整对象的 JSON Schema。固定目录在每个 VM 内缓存复用，不含用户参数或秘密，避免批次解码重复构造消耗燃料。系统提示词附加同一目录，`tools` 插件动作也返回该目录。执行复用公开 `Context::execute/request`，没有助手专用 Native 入口或任意模型 Shell。

| 类型                  | 当前工具                                                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 只读，共 11 项        | diagnostic、capabilities、images、containers、container_details、container_stats、processes、process_details、ports、services、service_details |
| 变更，共 3 项         | remove_untagged_images、container、service                                                                                                     |
| 文件，只读2项/变更2项 | file_read、transfer_prepare / file_edit、transfer；共18项工具                                                                                  |

保留严格 JSON `query / plan / answer` 模型协议，例如：

```json
{ "kind": "query", "requests": [{ "kind": "images" }] }
```

```json
{
  "kind": "plan",
  "summary": "清理查询中全部无标签镜像",
  "actions": [{ "kind": "remove_untagged_images" }]
}
```

```json
{ "kind": "answer", "text": "诊断结论" }
```

`Call<T>` 解码时检查工具及读写类型、完整字段集合，再通过现有 Rust 类型和参数校验；整个模型批次解码完成后才能发出第一项查询。包括无参数枚举在内的未知字段、缺失字段、非法 ID/PID/服务名、查询中的变更及环境变量明文读取均拒绝。`readOnly` 或 `confirmed:true` 不能放宽权限。

计划继续从完整成功查询冻结真实目标，执行原有镜像别名筛选、容器/服务指纹、审批期间命令内状态复验及执行后查询。模型所见结果具有 `tool / hostId / status / request / result`，明细仍按预算脱敏与缩减，完整证据不被压缩。

前端查询记录和执行结果共用 `ToolResult` 的 `tool / status / message` 字段：查询成功为 `succeeded`，传输中为 `running`，变更复查成功为 `verified`，其他为 `failed / unverified / skipped`。查询另有名称及完整记录数，执行另有操作名及冻结对象；文件步骤附加差异或传输预览。Rust、助手 TypeScript 与通用 SDK5.2 类型同步。

## 审批模式与单次计划确认

输入区默认 `request`，可选 `assist`；模式固定在发送时，切换不升级已有任务。`approval_mode` 原语返回owner/VM绑定的opaque策略句柄，助手保存在原任务绑定中，模型不能选择或改写它。新 `operations.read.preapproved` 权限及同名operation须单独声明/授权；内置包按既有系统分发规则预置，上传包仍需用户明确授予。

`request` 读取按原规则确认，计划等待用户点击；`assist` 只免除授权目录文本读取、传输预检和manifest中12条完整固定命令的确认，并在可见页准备好计划后自动发起统一确认。动态PID/容器/服务详情、选定日志等未列入固定清单的SSH命令仍需批准；不相信模型/插件的readOnly声明，不将任意SSH自动判为只读。两模式均没有自动批准写入或独立审批模型。

助手执行前把保存、传输启动或SSH命令（含前后复查）组成 `confirm_operations`。Native仅预检，不执行，生成含实际目标/文件差异的统一确认。批准后在同一个WASM动作中按完整请求摘要及次数消费授权；原文、权限、目录、模型/SSH修订和连接仍逐项复验。新增/修改/重复请求会拒绝并清空剩余集合，授权不能跨动作/owner/VM或重新播放。沿用单次审批60秒有效、动作180秒/96次平台请求、执行100秒后不启动后续步骤等边界；计划传输仍受60 KiB消息上限，过大时明确失败并要求缩小计划。

插件复选框和文字确认移除，`changeConfirmation` 输出固定为null；真实授权只来自宿主。Native确认先展示实际请求/路径，文件差异过大明确标注省略并结合聊天完整预览。见[SDK](../plugins/PLUGIN_SDK.md#审批模式与计划确认52)、[ADR0035](decisions/0035-task-approval-modes.md)。

## 运行期任务

成功 `prepare` 创建任务，ID 沿用预览 ID；`prepare / send / execute` 返回任务快照，`task({id})` 查询快照。快照包含 ID、状态、模型 ID、主机 ID 列表及 Native 时间来源的创建/更新/预览到期时间，不含消息、凭据、内部绑定或执行参数。

| 状态              | 含义                                           |
| ----------------- | ---------------------------------------------- |
| prepared          | 准备成功，尚未发送                             |
| running           | 模型与只读工具循环                             |
| awaiting_approval | 有冻结计划，等待审核；尚未获得 Native 执行授权 |
| executing         | 单次消费计划，核对状态或提交操作               |
| transferring      | 已交给原生队列，传输或取消收尾中               |
| verifying         | 已提交本项操作，正在复查                       |
| succeeded         | 回答完成、计划无目标，或全部操作复查成功       |
| failed            | 协议/查询或变更前检查等已知失败                |
| cancelled         | 未进入变更提交时停止，预览/计划已撤销          |
| unverified        | 变更或复查不确定，须独立核对，不重放           |
| expired           | 未消费预览/计划过期，不能恢复执行              |

状态仅按规定转换，终态不能重新执行。失败或未确认停止后续项并保留逐项结果；取消不改写已有的未知结果。查询按可信 owner 隔离，并通过原模型/SSH 绑定请求 Native 复验。请求不能更换目标或增加执行参数，跨 owner 不可读取或取消任务。

保留准备时刻起五分钟的预览/计划有效期，以及六轮模型调用、十二查询、每轮三项、32 个实际目标和 100 秒后不启动后续步骤的限制。每 VM 最多保留 32 个快照；只淘汰最早更新的终态，全部活动时拒绝新增。到期的遗留 running 记为失败，遗留 executing/verifying 记为未确认；终态可在运行期保留，`expiresAt` 不表示终态结果必须消失。

前端提交期间展示对应处理中状态，动作返回时采用后端快照；异常尝试读取原任务，读取失败保留原错误并标记无法核实的状态。通用 VM 同时只有一个在途动作，传输释放动作后由可见页轮询原生任务，模型处理中暂停轮询，独立取消不经过忙碌 Guest。没有实时事件，状态仅在内存中，不提供任务中心、跨重启恢复或自动重试；关闭页面及撤权沿用既有生命周期。

## 文件与传输

`files.rs` 通过 `file_read {hostId,path,startLine,lines}` 取得≤32 KiB远程 UTF-8 文本，Native按模式与独立预授权确认读取及模型使用风险，复用登录用户SFTP租约和目录授权。模型看到保留原始行号的脱敏结果，每次1–200行；原文留在插件内存，未修改字节不经模型重写。多行秘密脱敏保持原换行与行号。

`file_edit` 仅引用本任务已读文档，单计划一个文件、最多32处局部修改，行号统一基于原文；重叠、越界、重复位置、无实际修改和结果超过32 KiB拒绝。预览显示真实差异、路径和原文摘要；保存只接受冻结内容，纳入Native统一计划确认并复验原文及配置，复用编辑器原子保存和读回复查。保留原换行及未修改内容，不重序列化YAML，也不提供语义/应用校验。非原子服务器只读。

`transfer_prepare` 需要明确 local（运行ServerDeck的本机）或 remote hostId，以及目标已有目录；源/目标须在本次明确匹配范围，歧义不能隐式猜测。Native按读取审批模式检查元数据并冻结端点、大小、覆盖及源/目标属性，`transfer` 只引用返回的ID，由Native统一确认计划后启动。目标已有文件默认拒绝，只有显式覆盖且支持原子替换才允许。

Native在既有队列使用32 KiB缓冲流式传输、同目录临时文件、SHA-256读回和原子提交，源/目标状态变化或撤权拒绝提交；字节不经过JS/WASM/模型，无完整文件落地中转。源和目标会话均参与取消，后台持续及提交前后复验原插件/模型/SSH修订、配置、授权和连接。与既有文件页共享目标变更锁，提交不确定时不报告成功，给出恢复路径（如有），不回放/回滚。

开始后只保留owner、原生句柄和预览等小型任务元数据，释放模型消息/脱敏器。原生任务不因原模型句柄600秒TTL或预览五分钟过期终止，持续执行仍检查冻结的实际目标。状态/取消/关闭只访问自有句柄，原生取消入口不占用或释放其他Guest动作。终态先保存再异步释放，清理中断后可重新读取终态；关闭owner会清理遗留资源。只传单个普通文件，不传目录/链接，不解包，不支持续传或跨重启恢复。协议和SFTP v3/CAS、inode/ACL/xattr限制见[SDK](../plugins/PLUGIN_SDK.md#文件与传输51)。
