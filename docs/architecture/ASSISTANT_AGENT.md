# AI 运维助手：工具、文件与运行期任务

## 当前范围

助手基于 Rust/WASM 和 SDK 5.6，任务保存在运行期内存，不引入外部 Agent 框架。助手拥有工具目录、模型协议、参数检查、完整证据、局部文件修改、计划和复查；Native 负责真实 SSH/SFTP、模型传输、权限、宿主审批及 owner/安装/VM/目标修订复验。工具声明不能代替授权。

助手使用通用的查询、计划、执行、观察、继续推理循环，能够组合命令、文件、传输和镜像工具；Skill 按需加载说明和参考资源。没有匹配 Skill 时仍可组合工具。当前不提供 MCP、并行依赖图执行、运行时 Skill 安装或跨重启恢复。

## 工具目录与结果

`plugins/system/assistant/backend/src/tools.rs` 提供工具 ID、名称、read/change 类型、所需平台权限和完整对象的 JSON Schema。固定目录在每个 VM 内缓存复用，不含用户参数或秘密，避免批次解码重复构造消耗燃料。模型系统提示词附加去重后的工具目录，`tools` 插件动作返回完整校验目录。执行复用公开 `Context::execute/request`，没有助手专用 Native 后门；通用程序和显式 Shell 调用都经相同权限及宿主审批。

| 模型可见工具                               | 作用                                                            |
| ------------------------------------------ | --------------------------------------------------------------- |
| host_query                                 | 明确 hostId，内部 query 选择11种既有主机/Docker/systemd只读查询 |
| remove_untagged_images、container、service | 对计划 hostId 的已查询目标执行受保护的运维变更                  |
| file_read、file_edit                       | 远程文本读取与原子局部修改                                      |
| transfer_prepare、transfer                 | 本机上传或服务器间中转，完成后返回已校验目标 artifactId         |
| command                                    | 明确 hostId、program、args 的远程长任务，核对退出状态           |
| image_save、image_load                     | 独立的归档导出与导入，不包含跨工具迁移编排                      |
| skill_read                                 | 按名称和相对路径读取已打包的 Skill 正文或资源                   |

模型提示词使用12项工具目录。内部严格校验目录保留原有11种单主机只读查询形式；这些 Schema 已包含在 host_query 中，不在模型提示词重复发送。目录包含读写类型、所需权限标识和完整参数；Skill 包内读取不需要额外宿主权限，其他调用仍逐项通过 Native 权限检查。目录和 Skill 都不能授予权限。

保留严格 JSON `query / plan / answer / clarify` 模型协议，例如：

```json
{
  "kind": "query",
  "requests": [{ "kind": "host_query", "hostId": "已匹配主机ID", "query": { "kind": "images" } }]
}
```

```json
{
  "kind": "plan",
  "hostId": "已匹配主机ID",
  "summary": "清理查询中全部无标签镜像",
  "actions": [{ "kind": "remove_untagged_images" }]
}
```

```json
{ "kind": "answer", "outcome": "informational", "text": "诊断结论" }
```

最终 answer 使用 completed / incomplete / informational 区分目标完成、未完成和普通说明，省略时按普通说明处理；不能因为前面某项执行成功就自动将整个目标记为成功。completed 至少需要实际成功的工具证据（包括准备阶段已获取的主机上下文），所有必要步骤及业务目标是否满足仍须依据结果判断。

`Call<T>` 解码时检查工具及读写类型、完整字段集合，再通过现有 Rust 类型和参数校验；整个模型批次解码完成后才能发出第一项查询。包括无参数枚举在内的未知字段、缺失字段、非法 ID/PID/服务名、查询中的变更及环境变量明文读取均拒绝。`readOnly` 或 `confirmed:true` 不能放宽权限。

计划继续从完整成功查询冻结真实目标，执行原有镜像别名筛选、容器/服务指纹、审批期间命令内状态复验及执行后查询。每批变更成功后释放旧文档句柄并清空旧查询证据，后续读取或目标冻结必须重新查询，不能用变更前的缓存验证结果。证据按 hostId 隔离，多主机计划明确 hostId，不从排序后的主机列表隐式选择目标。模型所见结果具有 `tool / hostId / status / request / result`；先选取最多 20 条完整记录构造模型副本，再对所选原值脱敏并按预算缩减，避免对不会发送的全部记录重复复制、脱敏。完整统计与内部证据不被压缩。资源采样按完整挂载路径索引匹配 df 行，保留带空格、Unicode 路径和最长后缀语义，避免挂载点与 df 行逐对遍历耗尽 WASM fuel。

前端查询记录和执行结果共用 `ToolResult` 的 `tool / status / message` 字段：查询成功为 `succeeded`，传输中为 `running`，变更复查成功为 `verified`，其他为 `failed / unverified / skipped`。查询另有名称及完整记录数，执行另有操作名及冻结对象；文件步骤附加差异或传输预览。Rust 与助手 TypeScript 同步；通用平台请求复用 SDK5.6 类型。

## 审批模式与单次计划确认

输入区提供默认 `request`、`assist` 和 `full`，模式固定在发送时，切换不升级已有任务；退出full会立即撤销Native策略并使原full计划失效，等待宿主确认后才能提交新请求，失败需重试撤销。`approval_mode` 返回owner/VM绑定的opaque策略句柄，助手保存在原任务绑定中，模型不能选择或改写它。读取预授权、参数化读取和完全访问使用各自独立permission及operation；内置包按分发规则预置，上传包必须明确授予新增权限。

`request` 读取按原规则确认，计划等待用户点击；`assist` 自动处理授权目录文本、传输预检、13条完整固定查询/采样、5条带严格参数的读取模板（进程、容器和systemd详情），以及1条受限镜像导出模板。普通执行和长任务流共用相同的固定脚本/完整 argv 预授权；风险操作与未知命令请求批准，在可见页准备好计划后自动发起一次统一确认。Native不相信readOnly声明，不以Shell通配符放宽。`full` 首次请求必须经可信宿主确认，随后同一会话持续复用授权，无计时过期，在已授予范围内自动处理读取、写入、SSH及传输；切换模式、新建对话、关闭会话、撤权或插件停止/升级后失效，隐藏后返回保留授权，不增加基础权限或功能。

文件保存、传输启动及既有运维变更执行前将实际请求（含前后复查）组成 `confirm_operations`。Native仅预检，不执行，生成含实际目标/文件差异的统一确认。按模式授权后在同一个WASM动作中按完整请求摘要及次数消费授权；原文、权限、目录、模型/SSH修订和连接仍逐项复验。新增/修改/重复请求会拒绝并清空剩余集合，授权不能跨动作/owner/VM或重新播放。沿用单次审批60秒有效、动作180秒/96次普通平台请求（模型轮询及进度发布另限1024次）、执行100秒后不启动后续步骤等边界；计划传输仍受60 KiB消息上限，过大时明确失败并要求缩小计划。

command、image_save 和 image_load 使用受主机绑定的长命令流，每项由 Native 按冻结审批模式授权。image_save 使用共享的固定导出脚本，独立 argv 仅含任务标识、完整镜像 ID、所选引用的 SHA-256 和归档文件名。脚本从该镜像实际 RepoTags/ID 中匹配引用，导出前后核对 ID，只写入自身私有临时目录并持有至传输收尾。assist 中匹配已授予模板时无需额外弹窗；脚本、参数或目标变化不继承授权。image_load、未知命令及目标写入继续按现有风险规则批准。它们不复用跨动作的批量授权，也不获得交互预授权。`changeConfirmation` 输出固定为 null；真实授权只来自宿主。见[SDK](../plugins/PLUGIN_SDK.md#审批模式与计划确认)。

## 流式回答

助手UI每次发送先创建Native进度句柄，作为 `progressId` 传给prepare并保存在原Pending；资产匹配仍完整处理内部结构，后续回答与计划说明通过SDK5.4模型流获取真实增量。Native仅处理SSE/本地CLI文本及运行期资源，不理解助手JSON。WASM逐片解析顶层answer/text/summary字符串、解码跨片转义与代理对，经既有Redactor处理后发布显示文本，不发布工具参数或查询JSON。未结束ASCII词和自定义秘密前缀先保留，避免拆片短暂泄露；最终结构仍经过原query/plan/answer及工具/原文验证，不以预览授权执行。

前端通过原owner的控制通道约250ms读取进度，绕过占用中的动作队列；新修订替换当前预览，完成后以完整回答替换一次。中断或停止保留已显示片段及明确状态，片段不进入后续对话历史，也不开放执行。切换对话/模型、卸载与停止立即停止读取，迟到结果按版本丢弃；不等待可能悬挂的旧读请求阻塞新会话。进度读取故障会提示并取消当前模型工作，不伪装成完整结果。

模型流与文本进度使用独立有界资源，绑定插件/owner/VM，关闭页面、撤权、升级/停止时取消并等待收尾；隐藏且已授权保留后台任务时继续生成，返回页面可读当前预览。Full授权生命周期保持会话内有效。预算和公开字段见[SDK](../plugins/PLUGIN_SDK.md#模型流与文本进度)。

## 运行期任务

成功 `prepare` 创建任务，ID 沿用预览 ID；`prepare / send / execute` 返回任务快照，`task({id})` 查询快照。快照包含 ID、状态、模型 ID、主机 ID 列表及 Native 时间来源的创建/更新/预览到期时间，不含消息、凭据、内部绑定或执行参数。

| 状态              | 含义                                           |
| ----------------- | ---------------------------------------------- |
| prepared          | 准备成功，尚未发送                             |
| running           | 模型与只读工具循环                             |
| awaiting_approval | 有冻结计划，等待审核；尚未获得 Native 执行授权 |
| executing         | 单次消费计划，核对状态或提交操作               |
| transferring      | 已交给原生队列，传输或取消收尾中               |
| verifying         | 已提交本项操作，正在复查                       |
| answered          | 文字回答结束，不代表运维任务已经执行           |
| needs_input       | 等待用户补充信息或选择实际查询到的候选         |
| succeeded         | 必要操作完成、复查后，智能体确认目标完成       |
| failed            | 协议/查询或变更前检查等已知失败                |
| cancelled         | 未进入变更提交时停止，预览/计划已撤销          |
| unverified        | 变更或复查不确定，须独立核对，不重放           |
| expired           | 未消费预览/计划过期，不能恢复执行              |

状态仅按规定转换，终态不能重新执行。失败或未确认停止后续项并保留逐项结果；取消不改写已有的未知结果。查询按可信 owner 隔离，并通过原模型/SSH 绑定请求 Native 复验。请求不能更换目标或增加执行参数，跨 owner 不可读取或取消任务。

每批新计划从生成时起五分钟有效，原模型/SSH绑定仍按平台有效期复验，不自动续期授权。单任务最多32轮模型推理、64次只读工具和32批变更，每轮最多3个查询，每个运维批次最多32个实际目标。每个 WASM 动作最多处理6轮推理，达到切片边界后仅返回可继续状态；整个任务的计数不会因切片或变更执行而重置；Token 用量累计所有当前任务推理轮次的实际返回值，任一轮缺失则不显示合计。既有运维批次保留100秒后不启动后续步骤的限制。每 VM 最多保留 32 个快照；只淘汰最早更新的终态，全部活动时拒绝新增。到期的遗留 running 记为失败，遗留 executing/verifying 记为未确认；终态可在运行期保留，`expiresAt` 不表示终态结果必须消失。

`Memory` 由 owner 作用域下的运行期会话持有，保存消息、累计限额、分主机证据、文件、归档和当前工具任务。成功执行返回 continuation，前端在可见页调用一次性 resume，原任务继续推理；新计划按原审批模式再次授权，失败或未确认不继续。本任务中的执行结果经过脱敏后会发送给所选模型，用于继续推理；这不保证覆盖全部业务秘密，使用前应审核目标及命令。过程记录保留已执行工具的目标与实际结果，不能重放已消费计划。取消动作会关闭传输并排空，再释放生产归档的命令流；排空失败时保留句柄供后续取消清理，不先删除仍在使用的文件。前端提交期间展示对应处理中状态，动作返回时采用后端快照；异常尝试读取原任务，读取失败保留原错误并标记无法核实的状态。通用 VM 同时只有一个在途动作，传输释放动作后由可见页轮询原生任务，模型处理中暂停轮询，独立取消不经过忙碌 Guest。没有实时事件，状态仅在内存中，不提供任务中心、跨重启恢复或自动重试；关闭页面及撤权沿用既有生命周期。

## 文件与传输

`files.rs` 通过 `file_read {hostId,path,startLine,lines}` 取得≤32 KiB远程 UTF-8 文本，Native按模式与独立预授权确认读取及模型使用风险，复用登录用户SFTP租约和目录授权。模型看到保留原始行号的脱敏结果，每次1–200行；原文留在插件内存，未修改字节不经模型重写。多行秘密脱敏保持原换行与行号。

硬件问题在准备阶段复用系统采样，提供CPU型号、核数、内存等证据。`/proc`、`/sys`等动态内容不作为可编辑文档使用；远程属性未变化但实际字节数与报告大小不符时，Native返回`TEXT_SIZE_MISMATCH`并释放读取句柄，不创建文档。助手仅将这类`file_read`错误作为脱敏的失败观察交给模型继续回答或补充查询；模型/主机修订冲突、权限拒绝与取消仍终止原任务，普通文件读取前后属性校验和保存冲突保护不变。

`file_edit` 仅引用本任务已读文档，单计划一个文件、最多32处局部修改，行号统一基于原文；重叠、越界、重复位置、无实际修改和结果超过32 KiB拒绝。预览显示真实差异、路径和原文摘要；保存只接受冻结内容，纳入Native统一计划确认并复验原文及配置，复用编辑器原子保存和读回复查。保留原换行及未修改内容，不重序列化YAML，也不提供语义/应用校验。非原子服务器只读。

`transfer_prepare` 的源支持 local（运行ServerDeck的本机）、remote hostId/完整文件路径，或本任务已返回的 archiveId/artifactId（`source:{kind:"artifact",artifactId}`）。句柄只在原任务资源表中解析为真实主机和路径，再调用公开传输原语，不新增 Native 专用工具或权限。目标 path 必须是已有目录，文件名沿用源文件名；不能传入新目录或带文件名的目标路径。解析后的源/目标仍须在本次明确匹配范围，歧义不能隐式猜测。Native按读取审批模式检查元数据并冻结端点、大小、覆盖及源/目标属性，`transfer` 只引用返回的ID，由Native按模式授权固定计划后启动。目标已有文件默认拒绝，只有显式覆盖且支持原子替换才允许。Native 分别返回源文件缺失、目标目录缺失或目标不是目录的错误，并保留原 SFTP 原因链。仅这些未启动传输的只读路径预检失败作为含请求的失败观察交回模型，可修正参数或补充查询；原导出流和成功步骤继续保留。权限拒绝、修订失效、取消、提交及复查失败仍终止任务，不能自动重放已完成变更。

Native在既有队列使用32 KiB缓冲流式传输、同目录临时文件、SHA-256读回和原子提交，源/目标状态变化或撤权拒绝提交；字节不经过JS/WASM/模型，无完整文件落地中转。源和目标会话均参与取消，后台持续及提交前后复验原插件/模型/SSH修订、配置、授权和连接。与既有文件页共享目标变更锁，提交不确定时不报告成功，给出恢复路径（如有），不回放/回滚。

开始后只保留owner、原生句柄和预览等小型任务元数据，释放模型消息/脱敏器。原生任务不因原模型句柄600秒TTL或预览五分钟过期终止，持续执行仍检查冻结的实际目标。状态/取消/关闭只访问自有句柄，原生取消入口不占用或释放其他Guest动作。终态先保存再异步释放，清理中断后可重新读取终态；关闭owner会清理遗留资源。只传单个普通文件，不传目录/链接，不解包，不支持续传或跨重启恢复。协议和SFTP v3/CAS、inode/ACL/xattr限制见[SDK](../plugins/PLUGIN_SDK.md#文件与传输)。

## 命令、镜像与跨工具资源

command 使用独立 program/args 构造经过完整 argv 引号处理的命令流，模型不能用 readOnly 字段跳过批准。可以在权限范围内选择远程程序或显式 Shell；不自动安装软件、提权或关闭 SSH 验证。命令流使用当前任务随机 nonce 的退出标记，只有实际退出码为0才确认命令执行完成；这仅核验进程结果，业务目标需要后续查询。输出有界并脱敏，截断或非 UTF-8 输出不能当成完整证据。

image_save 要求本任务已成功查询来源完整镜像清单，冻结完整 ID 和引用，复用 `plugins/system/image_archive.rs` 的私有暂存、前后标签复验和归档脚本。成功返回 archiveId 和真实路径，传输优先引用 archiveId 而不让模型重写源路径；生产命令流在任务结束前持有文件，供后续普通传输使用。归档是任务临时资源，持久保存须先复制到用户指定位置。

普通 transfer 完成后只有在状态 completed、字节数一致及 SHA-256 合法时，才登记 artifactId、目标主机、实际路径和哈希。image_load 只接受本任务成功传输到该目标的 artifactId，要求先查询目标 images；执行时再次校验归档哈希和同名标签原状态，导入后核对完整 ID 和标签。同名标签可能替换，不自动更新容器。目标传输文件按通用传输契约保留，需要删除时另用经过审批的 command 处理准确路径。

镜像迁移由模型依次组合 host_query、image_save、transfer_prepare、transfer、image_load 等工具；执行器不包含专用迁移入口或按问题匹配的执行分支。主机匹配以登记资产、当前工作区及最多六轮成对对话判断涉及的主机。任务需要来源而用户未指定其他来源时，当前工作区主机就是默认来源；澄清只细化原任务的目标或参数，保留仍相关的来源。历史主机不是永久执行范围，独立新问题不机械继承旧目标。

首次匹配保留原始名称/IP命中的 explicitHostIds；有历史的关联问题通过独立匹配请求消除指代，不因本轮只提到一端就丢弃另一端。匹配历史与执行阶段使用相同的脱敏和完整轮次预算策略，不复用上一任务的原始输出或失效句柄。准备上下文同时保留已匹配主机的登记地址、端口、用户名、hostId、entryHostId 及当前问题的 explicitHostIds。

地址脱敏保留来自可信宿主登记信息的主机地址：匹配阶段为登记目录地址，执行阶段仅为本任务已绑定主机地址；保留规则按任务隔离，不从模型、远端输出或历史声明中扩展。界面仍对其他地址和邮箱脱敏，密码、令牌、私钥及自定义值的脱敏优先于地址保留。需要隐藏某个已登记地址时，自定义值仍可覆盖。不能因脱敏占位符相同就视为同一主机或要求重复提供已明确的信息，没有歧义时不索要内部 hostId。

所有长任务受原 owner、模型、SSH及权限绑定校验。只有完成结果可供下一步消费；取消、断线、绑定到期和未知结果停止后续操作，不回放或回滚已提交变更。命令流需页面保持可见，隐藏会停止流；断线或异常退出仍可能留下远端暂存。通用命令无法保证任意程序的孙进程或 daemon 侧效果都被撤销。

## Skill 发现与按需加载

插件的 `skills/<name>/SKILL.md` 是独立资源目录。构建脚本自动扫描并生成目录，不按问题新增 Rust 分支。初始系统消息只附名称和 description；模型通过 skill_read 显式读取 SKILL.md，再按需读取引用的相对资源，正文和参考资料才进入后续模型上下文。每次推理的工具目录仍随系统消息发送，Skill 正文不会预先全量注入。

Skill frontmatter 当前读取 name、description，支持单行字符串及缩进多行说明；名称与目录一致，为小写字母、数字和单横线，其他元数据不产生执行授权。不提供完整 YAML 语义或 allowed-tools 授权。资源限 UTF-8 文本，最多32个 Skill、每个最多128个资源、单资源32KiB、总资源256KiB。构建拒绝链接/重解析点；运行时仅按已打包资源精确查找，拒绝绝对路径、反斜线和 . / .. 路径段，不能读取任意宿主文件。

内置 remote-operations 和 docker-images 提供可复用经验，不是执行器中的固定工作流。脚本资源只作为文本按需读取，需要运行时通过普通 command 等工具及同样审批；没有自动脚本执行桥。新增/修改 Skill 资源后重新构建插件即可生效，不需要修改工具实现；当前不提供运行时安装、自定义 Skill 管理页或 MCP。能力缺失仍须增加可复用基础工具，Skill 不能凭空提供新权限或执行能力。

## 验收要求

针对候选产物验证批次预检、越权参数、目标/模型修订、owner 隔离、计划过期、防重放、取消和未知结果。通用循环验证无 Skill 的新组合、按需 Skill 正文/资源、跨工具结果引用、重新审批、累计限额和已完成步骤不重放；文件验证覆盖差异、原文冲突、单文件上传/中转、SHA-256、撤权和提交不确定；流式验证覆盖拆片脱敏、断流、取消和迟到片段隔离。真实模型账号、远端服务及原生平台检查按[发布检查表](../release/RELEASE_CHECKLIST.md)执行，测试夹具不能替代真实环境。
