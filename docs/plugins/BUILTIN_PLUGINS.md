# 系统内置插件

`plugins/system`的完整源码目录由构建工具自动扫描、打包及生成Rust嵌入注册表；不维护插件名白名单。新增完整目录后重新构建客户端即可进入分发和管理列表，失败的构建不能伪装已发现成功。

| 源码      | 功能归属                                                                         |
| --------- | -------------------------------------------------------------------------------- |
| assistant | 资产匹配、上下文选择/脱敏、工具目录、文件修改/传输、运行期任务、计划和执行后复查 |
| docker    | Docker能力检测、容器/镜像与Compose项目管理、详情/环境变量、日志、Shell           |

两者都是独立SDK5消费者，仅依赖公开SDK和普通库，无私有application/core/Tauri依赖。容器不是另一套宿主API：插件通过目标宿主的SSH运行docker命令，自己生成参数与解析结果。前提是该主机工具存在且SSH用户有相应权限；平台不自动安装远端工具或提权。

当前助手包 2.3.1、Docker 包 2.2.6。插件详情按「基本信息、插件配置」排列；基本信息中的权限与访问范围用于查看平台能力和排查拒绝原因，内置插件由系统预置、只读展示，上传插件仍需显式授权。助手配置将本地来源与远程模型分组，当前绑定、未保存提示和保存操作集中在底部；CLI 安装/授权及模型凭据在平台模型管理中维护。Docker 无独立配置项，配置页提供说明，主机页保留容器/镜像统计、搜索与表格；十一条固定查询覆盖列表、详情、资源、按需环境变量、Compose 项目/服务、启动配置快照和 Compose 配置读取，端口和挂载合并为 Compose YAML 启动配置，打开启动配置直接显示变量值并免逐次确认，容器详情固定标题/关闭按钮及分类标签、内容独立滚动，Compose 选项按实际能力检测，日志和 Shell 通过独立交互会话授权直接打开，容器启动/停止/删除、镜像删除及Compose项目启停/重启保留宿主一次“确认/取消”，无需输入目标 ID，正文以对象名称、真实主机和操作影响说明，不展示执行详情或命令脚本。

三个标签页采用约 320px 搜索框及“刷新”按钮。“Docker信息”展示版本、运行平台和 daemon 操作系统。容器列表工具栏提供清空容器日志及重启已退出容器，行内提供单容器重启，均由宿主确认；范围及清理限制见[Docker插件说明](../../plugins/system/docker/README.md)。

Compose项目管理提供已有项目发现、服务容器状态、项目日志及整组启动/停止/重启；不重新部署或删除项目。执行配置来自远端当前服务标签，相关边界见[Docker插件说明](../../plugins/system/docker/README.md)。

旧契约或损坏的安装记录会在“设置 → 插件”显示“部分插件未加载”，其他功能继续使用，原记录和数据保留。有对应当前内置包时可选择“备份并重装”：确认后保存 `packages/<ID>/record-backup-*.json`，保留原版本文件及配置，重新安装的插件默认禁用，检查配置后再启用。旧权限不沿用。没有内置替代包的上传插件需备份检查并使用当前 SDK 重新构建，不自动转成系统插件。

系统首次分发使用统一包校验/仓库，预置声明权限及必要文件根；用户上传默认禁用/未授权。source仅影响分发及授权管理，执行/审批/资源规则一致。现有系统版本仅按既有较高版本发行规则更新，保留启停选择、用户配置和卸载记录；不把上传同ID包改成系统包。

`plugins/system/packages`为可重建产物；compat不用于新源码。命令与目录结构见[开发指南](PLUGIN_DEVELOPMENT.md)，能力边界见[SDK](PLUGIN_SDK.md)。MySQL巡检作为外部工程从下载开发包独立构建，通过界面上传；不加入内置注册。

2026-11-09 已移除 Nginx 内置源码和分发；已有用户安装与配置保留，可在插件管理中显式卸载。
