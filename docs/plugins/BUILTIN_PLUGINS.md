# 系统内置插件

`plugins/system`的完整源码目录由构建工具自动扫描、打包及生成Rust嵌入注册表；不维护插件名白名单。新增完整目录后重新构建客户端即可进入分发和管理列表，失败的构建不能伪装已发现成功。

| 源码      | 功能归属                                                            |
| --------- | ------------------------------------------------------------------- |
| assistant | 资产匹配、上下文选择/脱敏、模型提示词、工具循环、计划和执行后复查   |
| docker    | Docker能力检测、容器/镜像管理、详情/环境变量、日志、Shell、端口探测 |
| nginx     | 宿主机/容器Nginx检测、配置校验/编辑/重载、日志，bind挂载写入保护    |

三者都是独立SDK5消费者，仅依赖公开SDK和普通库，无私有application/core/Tauri依赖。容器不是另一套宿主API：插件通过目标宿主的SSH运行docker命令，自己生成参数与解析结果。前提是该主机工具存在且SSH用户有相应权限；平台不自动安装远端工具或提权。

旧契约或损坏的安装记录会在“设置 → 插件”显示“部分插件未加载”，其他功能继续使用，原记录和数据保留。有对应当前内置包时可选择“备份并重装”：确认后保存 `packages/<ID>/record-backup-*.json`，保留原版本文件及配置，重新安装的插件默认禁用，检查配置后再启用。旧权限不沿用。没有内置替代包的上传插件需备份检查并使用当前 SDK 重新构建，不自动转成系统插件。

系统首次分发使用统一包校验/仓库，预置声明权限及必要文件根；用户上传默认禁用/未授权。source仅影响分发及授权管理，执行/审批/资源规则一致。现有系统版本仅按既有较高版本发行规则更新，保留启停选择、用户配置和卸载记录；不把上传同ID包改成系统包。

`plugins/system/packages`为可重建产物；compat不用于新源码。命令与目录结构见[开发指南](PLUGIN_DEVELOPMENT.md)，能力边界见[SDK](PLUGIN_SDK.md)。MySQL巡检作为外部工程从下载开发包独立构建，通过界面上传；不加入内置注册。
