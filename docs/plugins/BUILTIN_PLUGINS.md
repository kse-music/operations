# 系统内置插件

`plugins/system/` 下的完整源码目录由构建工具自动扫描、打包并生成 Rust 嵌入注册表，无插件名白名单。新增目录后重新构建客户端才能分发，运行中的客户端不监听源码热安装。

| 源码        | 功能                                                                      |
| ----------- | ------------------------------------------------------------------------- |
| `assistant` | 资产匹配、上下文与脱敏、工具目录、文件修改和传输、运行期任务、计划与复查  |
| `docker`    | Docker 检测、容器/镜像/Compose 管理、详情/启动配置/环境变量、日志与 Shell |

两者均为独立 SDK 消费者，只依赖公开 SDK 和普通库。业务命令、解析和提示词归插件；宿主只提供连接、执行、文件、模型、授权和生命周期。版本以各插件 `manifest.json` 为准。

## 入口与管理

插件功能从主机工具栏进入，只展示已启用且有功能页的包。“设置 → 插件”负责安装、升级、启停、权限、配置和卸载；详情按“基本信息、插件配置”排列。工作区的插件设置使用独立弹窗，关闭保留业务页状态。

助手配置从本地CLI和远程模型中选择已就绪项，选中后立即保存绑定，失败恢复原选项并提示，不自动选择替代模型；CLI 安装/授权和远程模型凭据由平台模型管理维护。Docker 无独立配置项。

系统首次分发使用统一包校验和仓库，默认启用并预置声明权限及必要目录，权限只读展示；升级保留用户启停、配置和卸载选择。用户上传默认禁用、未授权，同 ID 不能获得系统来源。来源只影响分发与授权管理，执行、审批、资源配额和目标复验相同。

单插件不受支持的契约或损坏记录会在管理页显示诊断，原数据保留，其他插件继续工作。有对应当前内置包时可明确选择“备份并重装”：先保存 `packages/<ID>/record-backup-*.json`，保留原载荷与配置，新记录默认禁用且不继承旧授权。没有内置替代包时，使用当前 SDK 重新构建上传包，不自动转换来源。

## Docker 行为边界

固定列表、详情、资源、环境变量和 Compose 配置读取使用完整命令预授权，日志/Shell 使用独立交互预授权。上传安装时两种权限都需自行核对授权；交互预授权允许任意流/终端命令，不代表只读。变更由可信宿主确认真实对象、主机和影响，不自动安装工具或提权。

启动配置以只读 Compose YAML 展示端口、挂载及可恢复参数：Compose 来源读取当前项目配置，普通容器按 inspect 转换并显示未转换项；不保证恢复创建时配置或独立部署。配置可显示环境变量值，切换/关闭清除；内联 secrets/configs 隐藏。Compose 项目只管理已创建容器及其日志，支持整组启停/重启，不重新部署或删除数据卷。

容器工具栏的重启仅处理当前主机的 exited 容器，不受搜索过滤影响；行内重启只针对该容器。日志清理仅截断当前 Docker 数据目录中路径核验通过的普通 json-file 当前日志，拒绝链接/异常路径，保留轮转文件，其他驱动跳过。批量结果显示计数，失败或超时可能部分完成，须刷新核对，不自动重试。

日志/Shell 弹窗自有流和 PTY 随关闭或隐藏释放，不关闭共享主机连接。日志缓存有界，翻阅历史不停止接收，恢复跟随后定位最新；Shell 的字号、查找和清屏不重建远端 PTY。

## 构建与扩展

`plugins/system/packages/` 为可重建产物。第三方插件从独立开发包构建，通过界面上传，不加入内置注册。目录、构建和安装见[开发指南](PLUGIN_DEVELOPMENT.md)，能力和安全见[公开 SDK](PLUGIN_SDK.md)及[安全边界](PLUGIN_SECURITY.md)。
