# 系统内置标准插件

## 当前范围（2026-11-05）

系统仅分发 Docker 管理和 AI 运维助手两个独立标准 WASM 插件。系统服务及其监控、进程端口、systemd 和服务日志界面已完整移除，旧标准系统视图不再兼容；AI 和独立插件仍使用的通用后端能力保留。

| 插件 ID                       | 独立源码                   | 功能        | 预置权限                                                            |
| ----------------------------- | -------------------------- | ----------- | ------------------------------------------------------------------- |
| `cn.hiboot.plugins.docker`    | `plugins/system/docker`    | Docker 管理 | `ui.contribute`, `system.read`, `system.manage`, `logs.read`        |
| `cn.hiboot.plugins.assistant` | `plugins/system/assistant` | AI 运维助手 | `ui.contribute`, `assistant.use`, `settings.read`, `settings.write` |

Docker 包为 1.5.1，助手包为 1.6.0，要求 Host API ^4.0.0，Rust SDK 与前端 SDK 均为 4.0.0。WASM ABI/wire/包格式/manifest schemaVersion 仍为 1，UI 为 v4。保留未使用被删界面合同的旧包，见[API 版本策略](PLUGIN_API_VERSIONING.md)。

镜像删除统一在可信宿主弹窗核对主机、账号地址及冻结的完整镜像 ID，点击“确认删除”即可，无需输入完整目标。取消或关闭不执行，不强制删除、不删除卷；其他容器与系统操作继续保留原有确认规则。

内置 AI 的在途回答、查询和已批准执行随主机工作区保留，切换页面/设置/其他主机继续，返回显示结果；关闭所属主机标签才清理本页工作。全局入口归属自身标签；手动停止、模型变更、撤权和原有超时仍有效。隐藏页面不能启动新的执行审批，上传同 ID 包没有此后台续接行为。

内置 AI 助手通过 SSH 进行有界只读工具查询，生成固定目标计划；在可信宿主核对主机、完整清单和确认文字后执行并逐项复查。支持清理 tag 为 `<none>` 且无其他标签的镜像、已查询容器及 systemd 服务操作；镜像完整清单包含 `image ls --all`，不遗漏中间无标签镜像。执行前复验，删除不强制、不顺带清理父镜像或卷。失败/未知停止后续项目，取消不保证撤销在途远端操作；单主机、最多32项，十分钟单次计划。模型绑定、升级保留设置及上传插件边界保持，详见[AI 使用指南](../guides/AI_ASSISTANT.md)。

Docker 采用容器/镜像分类、真实状态摘要、精简列和分组操作；日志在当前容器弹窗查看，Shell 直接进入弹窗终端并聚焦输入，关闭时释放自身 PTY。其他危险操作继续目标确认。AI 只保留全宽对话、固定输入区和问题建议；模型选择统一放到插件设置的“绑定模型”中并持久保存，聊天页没有模型栏和上下文面板。建议只填写草稿，直接发送，SSH 指纹及命令执行继续审核。

插件设置按“配置在前、管理信息在后”排版，宽屏显示辅助列，内置预置权限默认折叠。模型绑定改用单选列表，同时显示名称、模型 ID、Key 状态和当前保存值，候选列表较长时独立滚动；选择后点击保存才生效。Docker 采用紧凑摘要、表格行距和粘性表头；容器日志弹窗内提供暂停、过滤、复制及导出，AI 欢迎建议和输入区适配短窗口。

## 使用入口

顶部提供主机运维、资产管理、插件和设置，不再提供独立运维工具模块。插件菜单中的插件管理统一提供安装、升级、卸载及全部安装身份的详情、启停、权限和配置，包含禁用、未授权或无功能页面的包。插件功能从当前主机工作区 SSH/SFTP 右侧平铺的工具按钮进入，仅列启用且有功能页面的插件，固定当前主机，不重复选择主机；功能页“插件设置”打开同一设置标签，返回设备标签保留功能及草稿。全局搜索可打开 AI，相关工作区归属主机运维；内置 AI 助手以全资产目录参与匹配，匹配/发送直接进行；宿主仅按问题采集命中主机的相关来源，先统计后限量发送明细，并在聊天提示中说明省略；自动脱敏固定开启，无右侧配置面板。

每台主机保留一个设备标签，按插件/贡献/主机缓存页面、草稿与结果。隐藏时停止交互及日志、释放 WASM VM，返回时重新绑定并激活，准备完成后才开放界面。草稿仅保留在当前运行内；旧资源句柄须重新获取，停用插件不关闭共享终端或停止远端服务。

## 源码、构建和加载

每个 `plugins/system/<name>` 拥有 frontend、backend、manifest、UI JSON、测试和独立 Cargo.lock。公开 TypeScript/Vue SDK 提供共享状态、能力客户端和公共 UI；宿主只保留原生基础服务、管理和权限桥。

执行 `npm run plugins:build`，或 `node tools/build-plugin.mjs plugins/system/docker .local/docker.sdplugin`，使用与上传包相同的编译和打包器生成 WASM/UI/JS/CSS 与摘要。标准发行资产位于 `plugins/system/packages/*.sdplugin`，属于本地生成文件，不纳入 Git；提交插件源码、清单和锁文件。桌面 `dev/build`（包括 Tauri 入口）会自动生成两份内置包，CI 在 Rust 检查和测试前显式生成。独立运行相关 Cargo 命令或直接读取包的验收脚本前，先执行 `npm run plugins:build`，插件或 SDK 源码变化后同样需重新生成。

首次构建需安装 `wasm32-unknown-unknown` 目标，并按[开发准备](../../README.md#开发)分别下载两个插件锁定的 Cargo 依赖；实际插件编译继续使用 `--offline --locked`，不在编译阶段隐式下载。包在 Rust 编译时通过 `include_bytes!` 嵌入应用，最终安装器携带生成的内置插件。独立分发包保存为 CI/Release 产物。宿主验证安装代、授权和摘要后将包内 JS/CSS 加载到不透明来源 iframe，禁止直接访问父 DOM、原生 IPC 和外部网络。

AI ToolInvoke 经不可变单次票据、真实 WASM、Host 类型化能力与原有审批执行；Guest 不取得模型 Key、私有 SSH 租约或任意 IPC 名称。独立插件可使用 SDK 公共监控、系统查询、日志和容器终端能力；危险操作继续核对目标和确认。主机密钥、连接配置一致性、取消、速率、资源配额和失败诊断保持。

旧 UI v1 表单和 v2/v3 的保留工具继续兼容，组合服务器兼容源在 `plugins/compat/server/frontend`。插件图标仍从 manifest.icon 读取，两个标准包各自声明；上传同样支持，未指定或未知名称使用 boxes。

## 升级、旧数据与存储

旧 resources/processes/logs/network 的 system 记录及当前/旧域名 services 身份在启动时退役；依赖被删系统标准视图的上传包同样归档，原 payload、设置和授权不删除。仅 backup 不兼容时，保存原记录及独立包后退出活动回滚。归档中的 reason.json 说明升级要求。

版本升级只更新较低版本的 system 安装，复用标准仓库和备份，保留启停、设置、卸载墓碑及上传源；同版本不重装，也不降级。预置权限只读，上传权限仍需显式授权。所有插件适用于所有主机，实际使用时绑定入口主机；不会自动提权。

启动时在读取新 SDK 元数据前，将已删除内置身份（含旧域名）和声明已移除权限的旧安装记录原子移至 `plugins/retired/<id>-removed-<uuid>`，不再注册或允许激活。记录、payload、配置和既有数据库历史不清空，不重启旧计划；依赖这些已删除接口的上传包需修改后重新安装。新安装不能重新注册已删除内置身份。该归档兼容代码不包含调度或执行实现。

Windows 默认仓库在 `%APPDATA%/cn.hiboot.desktop/plugins`：system 为系统包，upload 为上传内容，packages 保存当前安装记录，data 保存插件设置。仓库源码 `plugins/upload` 与应用安装仓库不同，不被启动扫描。应用身份迁移仍沿用既有安全目录检查，不覆盖已有新目录或用户上传包。
