# 磁盘容量误报修复（2026-11-03）

后续截图明确暴露了文档门户、GVFS 和 GNOME 剪贴板挂载。下述前端修复不能覆盖后端未标记为 pseudo 的文件系统；本次已补齐后端分类，复现、完整链路验证及新版产物见 [桌面虚拟挂载验证](VALIDATION_DESKTOP_MOUNTS.md)。

## 原因与修改

进入服务器管理后出现的通用 `df 未返回该挂载点` 气泡，可以由正常缺少容量记录的伪文件系统、只读镜像或重复挂载触发。后端本来已将这些项目排除在持久盘容量异常统计之外，默认磁盘列表也将它们隐藏，但 MonitorView 的通知订阅遍历全部挂载点，造成显示口径不一致。

MonitorView 现在使用同一个 persistentDisks 集合决定默认列表和磁盘错误通知。勾选查看全部挂载只改变列表，不将正常的容量缺失升级成错误。真实持久盘及独立容器 overlay 的故障仍会通知，并包含挂载路径；整体采集错误、部分指标不可用状态、采集警告及原始不可用数据继续保留，没有伪造容量或修改远端采集命令。

主要文件为 `apps/desktop/src/views/MonitorView.vue`、`apps/desktop/src/components/monitor.test.ts`、`tools/ui-server-e2e.mjs`；架构和使用说明同步更新。
