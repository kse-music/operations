# Agentless Linux 监控阶段验收

2026-11-01。基于现有 SSH/SFTP 工作区实现；保留 PRD、用户数据和原有代码，未初始化 Git。验证环境：Windows x64、Rust 1.97.1、Tauri 2/WebView2、Vue 3/TypeScript、russh 0.65.0。服务器为用户授权的 Ubuntu 24.04.4 / OpenSSH 9.6p1；其他客户端和发行版尚未实机验收。

## 已完成

- 系统主机名、发行版、内核、CPU 型号/在线核心数、架构、Uptime、负载、时区和远端当前时间。
- /proc/stat 连续差分的总体/每核心 CPU 与 iowait，1/5/15 分钟负载，短期 CPU 趋势；首次、回退、热插拔和恢复后的无效区间显示待计算。
- MemAvailable 口径的内存总量/已用/可用/比例，Swap 容量/使用情况；老内核近似口径显式标注。
- mountinfo + df 挂载/文件系统/设备/容量/比例，中文和空格路径、重复挂载、伪文件系统、只读镜像及容器标识；不可用挂载保留原因，持久盘使用率达到 90% 显示高占用。
- /proc/net/dev 接口累计收发、ip 地址、按远端 uptime 差值计算的收发速度和合计趋势；接口名+ifindex、回退/重建/新增/异常速率均重新建立基线。
- 每 HostId 单一 Tokio 采样任务，最多 8 台；3/5/10/30 秒设置持久化并应用到现有任务。页面隐藏暂停，恢复清空差分基线，停止/退出等待取消并释放独立监控租约。
- Monitor 工作区、主机详情/右键/终端入口，概览卡片、每核详情、挂载和接口表、四张连续更新的趋势图；失败不显示假 0，旧样本标过期。

趋势采用 Vue SVG，未新增 ECharts 或大型时序数据库。历史只存内存，最多 600 点且裁剪至最近 30 分钟；只保留 CPU/内存与非 lo 接口收发合计，不累积所有每核/每接口历史。页面每秒读取 revision，快照未变化返回 null。

采样是固定、只读、无用户字符串插入的 SSH exec；沿用原有密码/私钥/Agent、路由和严格主机密钥校验，未知指纹仍先确认，变化仍阻断。不向用户 Shell 注入采集命令、不安装 Agent、不修改远端配置。生产采集不依赖 Python；原生测试的 Python 仅用于独立核对。

## 原生 WebView2 → 真实 Linux

`npm run test:terminal -- --monitor`：**16 项通过**（11 项既有真实终端基线 + 5 组监控验收）。目标身份沿用已可信核对的指纹；测试密码通过隐藏输入只在进程内传递，不写脚本、命令参数、数据库或日志。

1. Linux Shell 独立读取 /proc/stat 和 /proc/net/dev 连续样本，并运行 top、free -b、df -P -k -T /；Monitor 通过实际 UI/IPC 采样。首个 CPU/网络样本为待计算。
2. 内存总量 **33,589,186,560 字节**、根分区容量 **223,210,463,232 字节**与工具完全一致。CPU 为 Monitor **1.152%**、独立 proc 差分 **0.629%**、top **0.800%**；可用内存相差 **4,108,288 字节**，属于不同采样时刻的变化。
3. 网卡名称和累计收发与 /proc/net/dev 对照，速率有限且非负；每接口差分的精确数值由可控测试断言。不同观察窗口的 CPU 只采用明确的容差，不声称实时工具读数应逐位相同。
4. 四张趋势图连续更新，SVG 节点标记在更新后仍存在；设置 5 秒实际应用到原任务，再恢复原配置。重复打开使用同一 SessionId；离页后暂停，4 秒观察期历史长度和 revision 不变。
5. 返回页面恢复原任务；停止后 monitor_snapshot 返回 NOT_FOUND，同一 Transport 的交互式 Shell 继续执行标记命令。

实际 Linux 的 3 个 FUSE 用户挂载没有可用容量，界面保留明确错误并显示 partial，没有显示容量 0；根、/home、/work 等普通文件系统正常。这是分项失败的实际验证，不把 partial 冒充全部正常。

## 复现

```powershell
cargo test --workspace --offline
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline -- -D warnings
npm run typecheck
npm run lint
npm run format:check
npm test
node tools/tauri.mjs build --debug --no-bundle
```

原生验收需设置 SERVERDECK_TEST_HOST、SERVERDECK_TEST_USER 和可信核对的 SERVERDECK_TEST_PIN，再安全输入密码：

```powershell
$testSecret = Read-Host 'SSH test password' -AsSecureString
$env:SERVERDECK_TEST_PASSWORD = [System.Net.NetworkCredential]::new('', $testSecret).Password
try { npm run test:terminal -- --monitor }
finally { Remove-Item Env:SERVERDECK_TEST_PASSWORD }
```

`--monitor` 单独运行，不与 advanced/sftp 验收混用。工具只在 `.local/terminal-e2e` 隔离 EXE/数据库/调试端口中操作，正常 Debug 构建不开 CDP。受限沙箱禁止 loopback 或 Vitest 缓存重命名时，需要正常本地进程执行权限。

## 尚未验证和已知限制

- 已验证 Windows→该 Ubuntu；macOS/Linux 客户端、Debian/Rocky/AlmaLinux/CentOS 实机矩阵、20 会话和长期重协商/整进程内存仍待发布门禁。普通 SSH/SFTP 工作区的既有自动化已回归，不以本轮单机测试声称覆盖所有服务器。
- 固定脚本要求非交互 POSIX Shell、Linux procfs 和常见 GNU coreutils；iproute2 缺失时地址不可用，df/timeout 缺失或不兼容时容量明确不可用。非交互 Shell 额外打印 banner 会使严格采集协议失败，不靠猜测剥离输出。
- 采集代表 SSH 账号可见的命名空间；不实现 cgroup 配额指标、容器内部逐容器监控或完整挂载别名容量汇总。虚拟接口合计可能重复计入同一流量，UI 已说明。
- CPU busy 排除 iowait，top 常见汇总应比较 100−idle−iowait；网络以远端 uptime 而非本地轮询间隔计时。超短/超过 120 秒间隔、boot_id 或 ifindex 不可用时差分未知。
- 采样间隔是采集完成后的等待值；单次 exec 限 8 秒，df 限 4 秒，慢/异常服务器会降低有效采样频率。在途采集可在隐藏页面后完成一次，随后暂停。Channel 关闭不等同于能立即终止服务器上处于不可中断 I/O 的内核任务。
- 上限为 8 台监控主机、共享全应用 32 个 SSH Session；单次 2 MiB、1024 核、256 接口、2048 挂载，超限明确提示。历史没有落盘、跨重启恢复、告警通知或长期时序数据库。
- 本轮没有新增第三方依赖，既有 RSA/平台依赖与开发工具链安全告警仍需发布前跟进；Monaco 原有大 chunk 提示保留，监控模块约 12.5 KiB 按需加载。

后续优先补齐发行版/客户端兼容矩阵、受限账号场景和长期资源/吞吐验证，再按 PRD 单独启动整合发布阶段；本轮不扩展 Docker、批量命令或自动化。
