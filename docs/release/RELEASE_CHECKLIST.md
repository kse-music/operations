# ServerDeck 发布检查表

本表用于当前候选产物的发布验收。所有项目须针对同一版本和明确环境实际执行，未填写结果的项目保持待验；源码可构建不代表稳定版已经验收。当前支持范围见[产品基线](../product/PRD.md)，安全边界见[安全说明](SECURITY.md)。

## 发布门禁

- [ ] 上传修改时间：针对候选 Release 核对终端单文件拖放、多选/目录拖放、rz 和 SFTP 上传，使用已知旧日期、空文件及中文名称，按 Unix 秒核对远端实际 mtime；覆盖上传仍保留原目标权限和属主，SFTP 目录合并不保证目录时间。覆盖 Bash 4.2/GNU coreutils 8.22、sudo/su、时区显示差异；设置时间失败或服务器忽略时间属性时保留原目标并安全恢复终端，不显示上传成功。已有错误日期不自动改写。

- [ ] 固定候选提交、Cargo 工作区版本、锁文件、工具链与目标平台，构建当前安装器，生成摘要清单。
- [ ] 在 Windows x64 完成实际安装、启动、正常退出、重装、升级和默认保留数据的卸载；分别检查 WebView2、凭据库、Agent、选择器、原生拖放、输入法、高 DPI 和物理多屏。
- [ ] 若分发 macOS/Linux 或其他架构，独立完成对应构建、凭据/Agent、文件交互、安装卸载及窗口/高 DPI 验收；macOS 检查签名和公证。未验收平台不声明支持。
- [ ] 完成主机 → SSH → SFTP → Docker/助手 → 关闭/重启的真实链路，并验证加载、空、失败、取消、撤权和配置变更。
- [ ] 按[数据升级契约](../architecture/DATA_MIGRATIONS.md)检查所有支持版本、跨版本、WAL、并发、备份失败、事务回滚/重试、未来版本拒绝及数据/关联/秘密引用保留；安装器升级也须实测。
- [ ] 完成 Rust/前端/构建工具检查，以及插件开发包在仓库外的构建、上传、启停、权限与卸载验收。
- [ ] 对最终锁定依赖运行 npm/Cargo 审计，核对 RSA、GLib 和维护风险；未解决风险形成明确发布处置，不用 ignore 或旧结果替代。
- [ ] 为最终安装器落实发布者签名和可信分发渠道；SHA-256 不能代替签名。没有签名的产物明确说明状态。
- [ ] 测量当前进程树的冷启动、空闲内存和 20 个活动 SSH 终端，工程目标为三秒内可交互、空闲内存尽量控制在 150 MB；未达到时修复或明确调整目标，不能擅自标为通过。
- [ ] 完成 24 小时监控/日志/终端/传输并发、断线重连、睡眠/网络切换及百次启动退出，检查泄漏、资源释放和未知结果保护。
- [ ] 复核第三方许可证、许可原文完整性、安装资源及发布包内容；[依赖清单](DEPENDENCY_INVENTORY.md)和[第三方声明](THIRD_PARTY_NOTICES.txt)是输入，不等于人工复核完成。
- [ ] 验收记录明确候选提交、平台、命令、结果、失败和限制，随 QA/发布产物保存；所有阻断问题关闭后再发布。

## 版本来源与更新

- [ ] 软件更新：按[更新分发](UPDATES.md)检查同一候选版本的公开清单、版本固定下载地址、公钥及签名版本，实际从旧版安装升级；覆盖取消确认保留会话、下载中断/取消/重试、错误签名/错误版本拒绝、资源排空、重启与数据保留。GitHub Secret、草稿上传及国内目标网络下载须分别核对，未实测不得标为通过。

只修改根目录 [Cargo.toml](../../Cargo.toml) 的 `[workspace.package].version`。Rust 平台包继承工作区版本，Tauri 使用 Cargo 包版本，私有 npm 工程不重复声明。SDK、插件包、数据库 schema 和配置格式独立管理。

桌面 dev/build 自动检查版本来源，并通过 `cargo update --workspace` 同步工作区锁记录，保留锁定的第三方依赖；将生成的 `Cargo.lock` 一并提交。准备失败停止。关于页发布时间由本次前端打包生成，按北京时间显示，不随重新打开变化。

## 构建和产物

输出磁盘至少有 10 GiB 空闲；原生构建统一复用根 `target/`，保持 `.cargo/config.toml` 的缓存和调试信息设置。重新构建前正常退出正在使用构建输出的应用；原生 QA 使用复制后的 EXE，不强杀进程或整删缓存。

```powershell
npm ci
rustup target add wasm32-unknown-unknown
npm run plugins:fetch
npm run plugins:build
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
npm run test:build
npm run format:check
npm run lint
npm run typecheck
npm test
npm audit --audit-level=moderate
cargo audit --deny unsound
node tools/tauri.mjs build --bundles nsis
node tools/release-manifest.mjs
```

审计返回非零时须检查原因并保留报告，不能视为通过。测试需要系统凭据服务或授权服务器时按下节单独执行。

| 产物         | 路径                                                                      |
| ------------ | ------------------------------------------------------------------------- |
| Windows NSIS | `target/release/bundle/nsis/ServerDeck_<版本>_x64-setup.exe`              |
| Release 程序 | `target/release/serverdeck-desktop.exe`                                   |
| 校验与清单   | `.local/release-qa/SHA256SUMS`、`.local/release-qa/release-manifest.json` |
| 调试程序     | `target/debug/serverdeck-desktop.exe`                                     |

这些是本机构建路径，不能当作下载地址。调试程序可运行 `node tools/tauri.mjs build --debug --no-bundle`；已有相配的当前 Release 程序时，`node tools/tauri.mjs bundle --bundles nsis` 只重新生成安装包。

前端构建会嵌入 `serverdeck-plugin-development-kit.zip`。SDK、工具和文档修改后，检查 ZIP 内容完整，并从客户端重新下载，在仓库外构建、上传样例验证。不要修改锁文件来绕过构建失败，也不要删除数据库排查编译故障。

## 原生验收

- [ ] RSA 私钥：针对候选 EXE 与已授权服务器，验证原 OpenSSH RSA 私钥的文件选择、粘贴、加密口令、测试后保存及重新打开连接；覆盖 SHA-256/512、错误口令、未授权公钥和仅支持 SHA-1 的服务器拒绝。检查最终锁文件仍使用修复 RUSTSEC-2023-0071 的 RSA 版本，不能用协议夹具替代真实服务器及安装产物验收。

- [ ] Docker 镜像远程传输：针对候选插件包与两个已授权测试主机，检查行内入口、目标选择排除来源、自动连接与指纹审核、空目标/同 ID/冲突确认、确认后标签变化拒绝，以及带标签/无标签的内容核对。覆盖经典存储与 containerd 存储间显示 ID 不同但配置及层一致的导入，以及内容不同拒绝、空默认配置字段差异、无标签目标实际 ID 解析、同一轮输出与失败事件、错误详情只通知一次。实测经本机中转、SHA-256、目标自动加载、MB/MB/s 与校验/加载/清理阶段；覆盖源打包失败、目标空间/权限不足、校验失败、取消、隐藏/关闭、断线及两端清理失败。确认无自动重试、不更新已有容器，错误保留两端恢复路径；界面与 Shell 夹具不能替代真实 SSH/SFTP/Docker 验收。

- [ ] 固定三栏：第一栏首页/本地终端/设置与第二栏始终可见，检查主机树、本地会话列表、设置分类和第三栏联动；覆盖切换后 SSH/本地会话与分屏不重建、草稿保留、保存/迁移时禁止离开、退出未保存保护、插件配置 owner 与活动状态，以及最小窗口/超大字号下滚动和操作可达。

- [ ] 浏览器默认右键菜单：针对候选 EXE 与安装产物，检查主窗口空白、输入框、设置页面、Docker/助手及上传插件 iframe、独立文本编辑窗口，覆盖 Shift+右键、键盘菜单键与页面重新加载；不得出现返回、刷新、另存为或打印菜单。主机、工作区标签、会话、终端、SFTP 和编辑器的业务菜单，以及键盘、选择与剪贴板操作保持可用。macOS/Linux 须分别验收。

- [ ] 一体化标题栏：针对候选 EXE 与安装产物，核验深色/浅色/系统主题、鼠标拖动、双击最大化/还原、边缘缩放、最小化及恢复、系统快捷键与贴靠行为；覆盖最小窗口、超大字号、显示缩放与多显示器。新关闭按钮和 Alt+F4 均须进入现有退出确认，取消保留连接/任务/草稿，确认后排空资源；独立编辑器与插件不获得主窗口控制权限。macOS/Linux 须独立验收，触控和笔输入未实测不得宣称通过。

- [ ] 通用运维智能体：针对候选产物及已授权测试主机，验证无 Skill 的跨工具新组合、Skill 摘要/正文/资源按需加载、按模式逐批授权和累计限额；核对真实命令、文件局部修改、镜像 save、普通 SHA-256 传输、load 与业务复查。覆盖跨主机目标、伪造资源引用、未知结果、取消/断线、撤权、句柄到期、清理失败后重试及不重放已完成步骤。命令退出码不能替代业务验收，单元模型夹具不能替代真实模型和原生链路。
- [ ] 智能体自动审批与后台：针对候选产物核对普通不覆盖传输、可信单标签归档到空目标的导入自动执行；删除、覆盖、未知来源/命令仍确认。切换至SFTP或其他工作区后保留命令流、归档及连续任务，高风险计划等待返回；关闭工作区、撤权、断线时取消并排空，未知结果不重放。
- [ ] 传输吞吐：文件页使用 MiB/s，插件镜像传输使用 MB/s（十进制），比较时统一单位。在可控延迟和实际目标网络上比较串行与有界窗口上传、下载及中转，核对目标读回 SHA-256、动态长度文件、在途请求及提交前校验阶段取消、句柄关闭与暂存清理。针对 Release 候选产物，在同一主机、目录和大文件上分别测量千兆内网上传/下载，目标为数据传输阶段接近 100 MB/s，单独记录校验及整体耗时，并检查终端 ACK 背压。协议夹具的性能比值不能替代实际千兆链路、桌面中转路径和端点磁盘/CPU 测量。

- [ ] Windows 管理员本地终端：普通权限启动宿主，从本地会话列表的“新建会话”选择普通或管理员内嵌会话，取消菜单不创建会话，侧栏无独立提权入口；分别核验宿主/普通 Shell 未提权和管理员 Shell 已提权。验收 UAC 取消及重试、分屏/复制/重连重新授权、输入/输出/resize/ACK、关闭单窗格与退出、主程序或代理意外结束时的进程回收；确认插件和其他窗口不能调用提权 IPC。须针对候选 EXE 与安装产物实测，自动化协议检查不代替 UAC 验收。
- [ ] Windows 手动保存本地会话：针对候选 EXE 与安装产物，用重命名弹窗的“保存”分别保存多个不同目录的会话，覆盖双击、右键及本地 Ctrl+S 打开弹窗，取消不写入且菜单没有独立“保存”。核验中文、空格、方括号等路径、各窗格布局、再次保存只更新目标、之后改目录/布局或退出不自动保存；普通新建/复制/新增分屏从主目录启动。重启只加载保存列表，点选才启动，未启动条目改名不创建 Shell；关闭保留条目，取消保存不关闭 Shell。目录失效回退主目录但保留快照，管理员窗格重新经 UAC 授权；核验写入失败保留草稿、旧自动目录不再影响启动、损坏及未来版本记录拒绝覆盖。

- [ ] 文件页传输弹窗和计时：核验路径分行、全宽进度条、两列统计和窄屏单列、新任务自动弹出、多任务滚动、页头数量入口、X/Esc 取消当前弹窗任务并等待清理、部分取消失败可重试、后台传输只隐藏、轮询不重复弹出、全部结束自动收起及历史重试。覆盖主机隔离、确认后打开、上传/下载的已用时间、平均速度估算的剩余时间、排队及零速度、校验和失败状态；字节传完即显示校验中，校验、关闭句柄和提交不增加传输用时或改变平均速度，多文件任务恢复累计，未经校验提交不得计为完成；切换主机或工具不重置计时，历史记录固定最终传输用时。核验普通下载和 Windows 外拖均使用应用进度，描述符不请求系统复制进度，外拖暂存仍受活动任务和退出保护；针对候选程序在 Windows 验收实际桌面/资源管理器拖放、取消及最终文件结果。覆盖小时进位、窄窗口换行和中英文，不将数据传输预计时间当作校验及提交的倒计时。

- [ ] 终端二进制拖放：在候选 Release 验证普通用户、sudo/su 后的身份与当前目录，全部字节值、中文和空目录、同名文件/目录/链接拒绝、权限失败、SHA-256 失败；传输、校验和解包期间取消后终端设置恢复且可继续输入，提交边界保留已提交项目。确认文件载荷不经过前端或 Base64，协议及命令回显不进入终端显示，进度只按远端确认字节推进；断线、关闭、重连、无效帧及恢复失败不把旧二进制数据发送给 Shell 或新会话，其他窗格不受影响。通过 `node tools/terminal-drop-e2e.mjs --release --throughput` 验证真实 Linux PTY；还须用 Bash 4.2、GNU coreutils 8.22、tar 1.26 的旧 Shell 与工具组合验证正常上传、取消和写盘失败后的排空及终端恢复；同一入口同时验证生产 SSH 引擎到隔离 OpenSSH 的完整上传、校验及取消链路。可将 `SERVERDECK_TEST_DROP_TOOLS` 设置为隔离旧版命令目录、`SERVERDECK_TEST_DROP_SHELL` 设置为旧 Shell 启动器的 WSL 绝对路径（仅用于测试，不替换系统命令）。设置 `SERVERDECK_TEST_DROP_LARGE=1` 后以 `--release` 完整传输 5 GiB 单文件，确认准备不读取或复制载荷、分块累计摘要且远端校验一致；覆盖最后一块读取后源变化、零字节、特殊文件名及严格 umask。另核验多选仍保留归档结构与准备期间取消。以同一服务器、文件和磁盘实测终端与 SFTP 的数据阶段及多选归档/校验总耗时；隔离自动化不代替目标机器速度验收。

桌面和系统凭据验收使用隔离目录；涉及远程变更的测试须先授权测试主机与资源范围。原生 E2E 使用复制的 EXE、测试进程专用 loopback 调试端口及独立凭据，普通应用不开放调试端口。

```powershell
npm run test:native
node tools/native-titlebar-e2e.mjs
npm run test:terminal-latency -- --profile
cargo test -p serverdeck-security native_store_roundtrip_update_and_delete -- --ignored
```

本地终端延迟入口构建隔离的 Release EXE 并恢复根目录的正常构建配置，通过真实 WebView2、ConPTY 和带写出时间的 loopback HTTP 日志，比较 1/8/16 个空闲会话及 3/15 个后台输出会话。须检查全部前台日志标记到达、所有后台生产者实际输出并结束，以及隐藏焦点隔离、历史、切页和输入恢复。指标和可选 CPU 剖析保存在 `.local/qa/terminal-latency/`；剖析在延迟采样结束后执行。DOM 就绪及下一帧调度机会不是物理屏幕呈现时间，不替代 SSH、UAC、安装器或其他平台验收。复用历史 EXE 时仅接受该 QA 目录内的 `--exe` 副本。

SSH 测试从进程环境读取 `SERVERDECK_TEST_HOST`、`SERVERDECK_TEST_USER`、`SERVERDECK_TEST_PIN`、`SERVERDECK_TEST_PASSWORD`。PIN 通过带外渠道核对；密码通过隐藏输入仅放入本次进程环境，不进入命令行、文件或日志，使用后清除。先阅读测试入口的前置条件和实际操作，不能把只读检查视为对远端变更的授权。

| 范围                       | 入口                                  |
| -------------------------- | ------------------------------------- |
| SSH 真实终端               | `npm run test:terminal`               |
| 分屏、标签、路由与底层转发 | `npm run test:terminal -- --advanced` |
| SFTP、传输与编辑           | `npm run test:terminal -- --sftp`     |
| Docker 与宿主运维服务      | `npm run test:terminal -- --ops`      |
| 主机工作区与插件流程       | `npm run test:terminal -- --product`  |

测试入口在 `tools/`，插件和协议夹具在 `tests/fixtures/`；按用例检查实际覆盖范围，测试夹具不等同于真实模型账号或真实 Docker/外部服务。终端端到端输出位于 `.local/terminal-e2e/`，桌面验收位于 `.local/native-e2e/`。诊断输出须去敏，保留当前候选产物的必要证据。

## 安装版复验

将候选安装器装入专属 QA 目录。使用隔离且没有主机/凭据的测试配置，禁止清除实际用户数据来满足前置条件。以下占位路径替换为实际值：

```powershell
node tools/release-startup-bench.mjs <installed-serverdeck-desktop.exe> <artifact-directory>
node tools/native-terminal-e2e.mjs --release --installed-exe <installed-serverdeck-desktop.exe> --release-qa
```

安装版可组合 `--advanced`、`--sftp`、`--ops` 复验模块；`--exit-transfer` 检查传输中的确认退出。`--modules-only` 不算完整产品回归，短时脚本不能代替 24 小时稳定性门禁。确认退出后核对所有进程和资源释放，不把 kill 当正常退出。CI 生成候选产物不代替签名、可信发布或各平台原生验收。
