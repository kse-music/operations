# ServerDeck 阶段 13A：插件系统 Codex 顺序开发任务

> 适用范围：ServerDeck 桌面客户端插件系统（Plugin Runtime + Plugin SDK）。不包含远程 Rust Agent、AI Copilot、在线插件市场。
>
> 执行方式：按 13A-1 → 13A-2 → 13A-3 → 13A-4 → 13A-5 顺序实施。每个任务完成并通过阶段验收后再进入下一项。若 Codex 一次处理整份文件，也必须逐阶段实现、验证、记录，遇到阻断性设计问题暂停并报告，不得跳过测试假装完成。

## 统一执行规则（每个阶段均适用）

1. 开始前阅读 `AGENTS.md`、`docs/product/PRD.md`、`docs/architecture/ARCHITECTURE.md`、`docs/product/IMPLEMENTATION_PLAN.md` 和当前代码；文件不存在时说明并基于现状补齐必要文档。
2. 必须修改实际代码，交付可运行功能；不以 Mock 页面、占位实现或文档替代功能。
3. 优先复用现有 SSH、SFTP、主机上下文、任务系统、Tauri IPC 和 UI 组件；不要重新实现第二套。
4. 插件系统与远程 Rust Agent 完全解耦；未安装 Agent 时仍能工作。
5. 默认拒绝权限。插件不得读取 SSH 密码、私钥、API Key，也不得直接访问 Tauri 原生权限或 Rust 内部 Session。
6. 禁止把不可信原生动态库加载到桌面主进程。任何第三方代码执行必须有清晰隔离边界、资源限制和故障处理。
7. 关键模块添加自动化测试；执行可用的 `cargo fmt --check`、`cargo check --workspace`、`cargo test --workspace`、`cargo clippy --workspace`、前端类型检查及构建。环境不支持的检查必须注明。
8. 更新架构、API、权限和开发进度文档；记录重要设计决策及已知限制。
9. 每阶段输出：实现清单、修改文件、测试结果、未完成项、风险、下一阶段依赖。完成本阶段后停止，不提前开发下一阶段。
10. 不执行未经用户授权的真实服务器破坏性操作；集成测试使用隔离的测试服务器或容器。

## 13A-1：插件包协议与安装管理

**目标：** 形成无需执行插件代码也能安全识别、校验、安装、卸载和管理插件元数据的基础设施。

**开发任务：**

1. 检查现有 Cargo Workspace 和 Tauri 架构，建立插件领域模型、插件清单解析、安装仓库和插件状态持久化模块。按需建立 `plugin-core` 等 crate，不机械创建空 crate。
2. 定义版本化 `manifest.json`：插件 ID、名称、版本、作者、描述、API 版本范围、入口文件、权限声明、UI 贡献声明、兼容平台及文件校验信息。提供 JSON Schema 或等价严格校验。
3. 定义本地插件包格式（例如 `.sdplugin`），包含 manifest、受限运行时入口、静态 UI 资源；禁止绝对路径、`..` 路径穿越、符号链接逃逸、重复冲突路径、压缩炸弹及超额包大小。
4. 实现本地安装、列举、启用状态持久化、禁用、卸载、重复安装处理、版本检查、升级前备份和失败回滚的基础流程。此阶段启用仅改变状态，不运行第三方代码。
5. 校验完整性及来源信息。建立可信发布者/签名验证的接口和信任策略；未实现签名验证时，只允许明确标记的本地开发模式安装，不能声称插件可信。
6. 定义插件存储目录、每插件独立数据目录、插件配置与缓存的清理策略；卸载默认保留用户数据并允许明确选择清除。
7. 建立 Rust API 与 Tauri IPC（安装、列表、详情、启停状态、卸载），可使用简单测试入口验证，完整管理 UI 留到 13A-4。

**验收：** 能安装一个不含可执行代码的测试插件包，正确读取 manifest、持久化安装状态、拒绝非法包、卸载后不残留可执行入口；升级失败能够回滚。自动化测试覆盖路径穿越、版本不兼容、重复 ID、超大包和损坏包。

**交付文档：** `docs/plugins/PLUGIN_ARCHITECTURE.md`、`docs/plugins/PLUGIN_PACKAGE_FORMAT.md`、`docs/architecture/DECISIONS.md`。

## 13A-2：隔离运行时与插件生命周期

**目标：** 在不赋予插件桌面主进程权限的前提下，真实运行第三方插件逻辑。

**开发任务：**

1. 基于项目现状选择一个明确的插件后端运行模型，优先评估 WASM/WASI 沙箱；如选择独立子进程，必须论证 OS 级隔离、文件系统/网络限制、资源上限和跨平台成本。不得把普通 Node 子进程直接视为安全沙箱。
2. 设计版本化插件 Host ↔ Guest 消息协议，包括启动、激活、停用、健康状态、错误、取消和退出；规定消息大小与超时。
3. 实现运行时管理器：按需加载、启动、激活、停用、卸载时清理、异常隔离、崩溃状态报告及安全重启策略。
4. 实现资源配额：内存、执行时间、并发、消息量、任务数；阻止插件无限循环或消息洪泛拖垮桌面客户端。
5. 插件默认无法访问宿主文件系统、网络、进程环境变量、Tauri IPC 或秘密存储；只允许通过后续能力 API 访问授权功能。
6. 实现最小 `hello-world` 后端插件：激活时返回固定诊断信息，停用后资源释放；这是运行时测试插件，不是伪造业务能力。
7. 对接 13A-1 的插件元数据和启停状态，保证插件禁用后不会被调用。

**验收：** 安装的真实插件能够在隔离运行时启动并响应协议；模拟崩溃、死循环、超时、超大消息、重复激活、禁用和卸载均不会导致主应用崩溃或残留失控任务。证明隔离边界，记录尚未实现的安全保障。

**交付文档：** 更新 `docs/plugins/PLUGIN_ARCHITECTURE.md`，新增 `docs/plugins/PLUGIN_RUNTIME.md`。

## 13A-3：权限模型、受控能力 API 与 Plugin SDK

**目标：** 让插件安全复用 ServerDeck 已有的 SSH、SFTP、主机和任务能力，而非直接接触内部实现。

**开发任务：**

1. 设计并实现默认拒绝的权限模型。最小权限集合：`hosts.read`、`ssh.execute`、`sftp.read`、`sftp.write`、`ui.contribute`、`settings.read`、`settings.write`、`tasks.create`。权限名称、范围和版本必须可扩展。
2. 权限在 Rust Host 侧逐请求校验，不能只依赖前端隐藏按钮；授权应绑定插件身份、版本/发布者、目标主机范围和具体操作类型。升级新增权限需要重新授权。
3. 建立 Host Capability API：读取经脱敏的当前主机上下文、受控执行远程命令、远程文件读写、插件隔离设置、通知、可取消任务。使用既有 SSH/SFTP 连接管理器，避免重复连接池。
4. 对命令执行和写文件设置独立的高风险确认机制。必须区分“允许使用能力”和“允许本次改变服务器状态”；不得仅凭插件声明 `ssh.execute` 就允许任意危险命令静默执行。
5. 实现 API 请求取消、超时、输出大小限制、背压、错误码和权限拒绝事件。禁止返回明文凭据、私钥、SSH Agent 原始句柄。
6. 提供版本化 Plugin SDK（与选定运行时匹配的 Rust 或 TypeScript 接口），包含类型定义、示例、API 兼容检查和错误处理规范。
7. 编写权限矩阵测试：未授权、撤销授权、主机范围越界、伪造插件 ID、升级增加权限、并发调用、关闭会话后的请求。

**验收：** 示例插件能在用户授权后读取当前主机基本信息并执行一个只读诊断命令；未授权或越权调用被 Rust 后端拒绝；任何插件不能直接获取 SSH 凭据；关闭插件后正在运行的能力调用按策略取消或安全结束。

**交付文档：** `docs/plugins/PLUGIN_SDK.md`、`docs/plugins/PLUGIN_SECURITY.md`、`docs/plugins/PLUGIN_API_VERSIONING.md`。

## 13A-4：插件管理 UI 与工作区扩展点

**目标：** 用户能够通过桌面界面管理插件，插件能够以受控方式贡献工作区视图与命令。

**开发任务：**

1. 实现插件管理页：已安装列表、详情、版本、来源、权限、状态、安装本地包、启用、禁用、卸载、升级提示、错误信息。
2. 安装前展示插件身份、发布者/签名验证结果、所需权限、兼容性和风险；不可信开发包必须显著提示。
3. 实现 UI 扩展点：主机工作区页面、导航项、主机右键菜单、命令面板项、插件设置页。使用稳定贡献声明，不允许插件直接修改主应用组件树。
4. 插件 UI 采用隔离的渲染方案及受控消息桥，实施 CSP、导航/资源来源限制、消息校验和 API 权限限制；禁止直接暴露 Tauri 原生命令。
5. 实现扩展点生命周期：启用注册、禁用撤销、插件崩溃错误态、切换主机更新上下文、卸载清理菜单与视图。
6. 支持暗色/亮色主题和基础国际化；插件 UI 应使用明确的样式约定，但不能假定插件可以任意访问宿主 DOM。
7. 提供一个简单的官方 UI 示例插件，展示当前主机的脱敏信息，并通过 13A-3 的 API 进行只读操作。

**验收：** 用户无需修改主程序代码即可安装示例插件并在工作区打开其视图；禁用/卸载后扩展点消失；权限变更能反映到 UI 与后端；恶意 UI 消息不能调用未授权 Tauri API。

**交付文档：** `docs/plugins/PLUGIN_UI_EXTENSION.md`、`docs/plugins/PLUGIN_DEVELOPMENT.md`。

## 13A-5：Nginx 官方插件、端到端验证与发布准备

**目标：** 通过一个真实业务插件验证前四阶段形成的插件平台可用于专业运维场景。

**开发任务：**

1. 使用公开 Plugin SDK 开发独立的 `Nginx Manager` 官方示例插件；不得引用 ServerDeck 私有 Rust crate 或内部未公开 IPC。
2. 在用户选定的 Linux 主机上检测 Nginx 是否存在，查看版本、服务状态和配置路径。处理发行版差异及权限不足。
3. 使用授权 SFTP 能力读取配置文件；支持受控编辑、未保存提示、外部修改冲突检测及保存失败处理。
4. 提供 `nginx -t` 配置验证，展示真实 stdout/stderr、退出码和错误信息；不允许将失败结果伪装为通过。
5. 允许用户明确确认后重新加载 Nginx；在重新加载前提示风险，优先要求成功执行配置验证。不得自动提权或在未经授权时修改系统服务。
6. 查看用户有权限访问的指定 Nginx 日志，支持有限缓存的实时输出、暂停、搜索和取消。
7. 插件可以独立打包、安装、启用、禁用、升级、卸载；卸载不删除服务器上的 Nginx 配置或日志。
8. 完成插件平台全链路测试：包验证 → 安装 → 权限授权 → 运行时激活 → UI 注册 → SSH/SFTP 调用 → 禁用 → 升级 → 卸载。
9. 执行安全与可靠性检查：权限绕过、消息伪造、主机切换、连接断开、插件崩溃、资源泄漏、兼容性及回归测试。
10. 更新完整开发文档、示例插件源码、安装说明、API 版本与兼容性说明，并记录尚未支持的场景。

**验收：** 在隔离测试 Linux 主机上，通过安装的 Nginx 插件完成真实检测、查看配置、验证配置及经确认的重载；整个过程中不需要修改 ServerDeck 核心代码。所有关键失败场景有明确反馈，核心 SSH/SFTP 功能无回归。

**交付文档：** `docs/plugins/PLUGIN_DEVELOPMENT.md`、`docs/plugins/PLUGIN_SECURITY.md`、`docs/validation/plugins/PLUGIN_TEST_REPORT.md`、插件示例 README。

## 最终阶段验收与停止规则

13A-5 完成后，对照以上五个任务输出完成矩阵，逐项标记“已实现且已验证 / 已实现但未验证 / 部分实现 / 未实现”，附测试证据。不得把“有代码”直接当作“通过验收”。
