# 1. 项目背景

## 1.1 产品概述

ServerDeck 是一款基于 Rust 开发的轻量级服务器运维桌面客户端。

产品面向软件开发人员、Linux 运维人员、DevOps 工程师和中小型技术团队，集成 SSH 终端、SFTP 文件管理、服务器资源监控、远程命令执行等能力，并逐步增加 Docker、日志分析、网络诊断、批量运维和自动化等功能。

ServerDeck 采用 Local-First（本地优先）设计，核心能力不依赖云端服务。

首个版本以 Agentless（无需在远程服务器安装 Agent）方式工作，通过 SSH 和 SFTP 管理 Linux 服务器。

## 1.2 产品定位

**产品定位：现代化、一体化、轻量级的服务器运维工作台。**

参考产品：

- SecureCRT：成熟的终端与会话管理能力。
- Xshell：SSH 连接和多会话操作体验。
- Xftp：远程文件管理。
- FinalShell：SSH、文件和资源监控整合。
- Termius：现代化连接管理与客户端体验。
- 1Panel：服务器管理能力和功能组织方式。

ServerDeck 不以完整复制上述产品为目标，而是重点优化服务器日常运维操作的连续性。

## 1.3 产品目标

1. 减少 SSH、SFTP、监控和其他运维工具之间的切换。
2. 提供稳定、流畅、现代化的跨平台终端。
3. 让服务器管理围绕统一的主机上下文展开。
4. 降低多服务器日常运维操作成本。
5. 保持本地优先、模块化和较低资源占用。
6. 为未来增加商业授权、团队功能和插件生态预留扩展空间。

## 1.4 目标用户

### 个人开发者

管理 1～20 台 Linux 服务器，日常需要 SSH、文件上传下载、Docker、日志查看等功能。

### DevOps 工程师

管理 10～100 台服务器，希望集中维护连接配置、快速切换服务器并简化重复操作。

### 小型技术团队

需要共享操作流程、统一服务器管理方式，未来可能需要团队权限和操作审计。

MVP 首先满足前两类用户的日常使用需求。

# 2. 产品设计原则

## 2.1 核心原则

### 一台服务器，一个工作区

用户选中一台服务器后，该服务器相关的终端、文件、资源监控和快捷操作使用统一主机上下文。

### 本地优先

服务器配置、连接历史、用户偏好等数据优先保存在本地。

MVP 不需要用户注册或登录云端账号。

### Agentless 优先

远程 Linux 服务器无需安装额外程序即可使用基础能力。

### 安全优先

服务器认证信息、私钥及远程操作必须受到保护。

### 模块化

SSH、SFTP、监控、存储、自动化等模块应保持清晰边界。

### 不为了功能数量牺牲核心体验

终端可靠性、连接稳定性、文件传输正确性优先于扩展功能数量。

# 4. 整体界面需求

## 4.1 主窗口布局

采用“顶部大模块 + 左侧模块菜单 + 中央工作区标签”的两级导航布局。

主要区域：

**顶部：**

- 保留系统标题栏及窗口控制。应用内容顶部为功能模块栏，左侧显示 ServerDeck，右侧提供主机运维、运维工具、资产管理、插件；“设置”独立贴齐顶栏最右侧，不显示重复版本信息。
- 顶部模块菜单及工作区标签通过文字和背景区分选中状态，不显示选中项的强调色横线。
- 点击顶部大模块只切换模块高亮和左侧菜单，中央保留当前已打开的页面：终端继续显示终端，设置或其他功能也保持原内容；尚未打开页面时继续显示欢迎页。不显示“请选择功能”提示卡片，不清空当前页面，不自动选择默认页或恢复另一个页面。点击左侧功能、已打开标签、搜索或快捷入口时才切换中央页面并同步所属模块；已有连接与后台任务继续运行。

**左侧：**

- 左侧仅显示当前模块的菜单：主机运维包含主机管理、本地终端及主机树；运维工具只列已安装插件名称，包含 AI、批量、自动运维及网络诊断等标准插件；资产管理包含安全凭据、模型管理、备份恢复；设置包含通用、终端、快捷键、工作区与连接、插件管理、关于。插件管理归属设置，任务中心独立位于底部状态栏。
- “设置”模块的左侧菜单依次为“通用、终端、快捷键、工作区与连接、插件管理、关于”，原设置页内分类提升为侧栏菜单，不再显示重复分类 Tab。各分类分别打开并复用工作区标签，共用一份草稿；切换菜单、页面标签或其他页面保留草稿，统一保存全部分类，校验失败自动打开无效字段所属菜单并聚焦。关闭全部设置分类标签后释放草稿。“关于”位于该菜单末尾，点击后在中央工作区打开独立页面，合并展示产品说明、实际应用版本、技术栈和本地环境（IPC 状态、SQLite 版本、数据目录、日志目录），提供“重新检查”并显示读取中与后端未就绪状态；不再提供独立本地环境菜单，使用现有工作区标签切换与关闭，不再使用弹窗；重复点击复用同一个关于标签，菜单同步选中状态。其他模块不显示此入口，侧栏底部不再常驻。切换或关闭关于页面不关闭已有终端和后台任务。版本由本地后端提供，初始化中或不可用时明确提示状态。
- “主机管理”为无图标、不可点击的静态标题，不触发导航或连接；主机配置的增删改查集中在工作区主机树，不提供独立配置列表页。
- 主机列表仅在主机运维模块中显示，切换其他模块时隐藏并保留搜索、分组等状态。全局工具在各自页面内明确选择目标，不跟随主机树执行。
- 主机列表
- 主机总数显示在静态标题“全部主机”后，随主机新增/删除刷新，不随搜索变化；主导航“主机管理”不再显示终端数量徽标。
- “本地设备 / 本地终端”固定在“全部主机”标题上方，搜索框紧接“全部主机”标题下方；三者均不随列表滚动。进入欢迎页、切换远程主机或搜索后本地入口始终显示。点击“本地终端”显式打开本地终端，已有会话复用；当前远程主机工具显示在中央工具栏右侧。
- 主机分组
- 在线连接状态
- 左侧菜单顶部显示当前模块入口或名称及收起按钮；收起后，在主机和全局工具的工作区标签栏均可重新展开。顶部模块栏始终可见，保留原侧栏宽度偏好及拖动/键盘调整。
- 主机搜索（输入框内保留搜索图标）
- 在文件夹上右键新建主机

**中央：**

- 页面统一铺满中央显示区域，沿用现有响应式内边距；各设置分类和关于页不使用独立的固定最大宽度及水平居中限制。
- 一级标签切换已打开的主机工作区；独立工具拥有自己的导航标签。
- 当前远程主机的 SSH 终端、SFTP 文件和工具下拉菜单位于中央工具栏右侧；工具紧接 SFTP，按插件名称显示已启用插件，每个插件一项，未启用项隐藏。点击打开当前主机的对应插件页面，没有 UI 的包进入自身设置。本地设备只提供本地终端。
- Shell 会话标签、新建会话和主机工具菜单位于终端内容上方的紧凑工具栏，会话多时独立横向滚动；窄窗口允许菜单换行并在自身区域横向滚动。会话右键、重命名、拖动、关闭及终端内分屏保留。
- 移除终端旁的文件面板及其开合状态，SFTP 菜单和终端右键文件入口统一打开完整文件页；终端入口继续传递来源目录和窗格。切换工具保留各主机已有文件连接、路径、传输和终端会话。关闭设备工作区会关闭该设备的全部终端会话；指纹验证和危险操作确认继续沿用。

**底部：**

- 当前连接状态
- 操作提示
- 底部状态栏提供单个“任务中心”按钮，以弹窗查看文件传输、网络与批量任务、自动化状态；运维工具菜单不再显示任务中心。全局搜索及原任务快捷键（默认 Ctrl+Shift+J，保留用户配置）打开同一弹窗，不创建工作区标签或改变当前模块和页面。关闭按钮及 Esc 关闭弹窗，不取消任务或关闭终端；重试传输、查看结果时关闭弹窗并跳转原工具，停止后台命令及暂停计划继续确认具体目标。

## 4.2 工作区

每台服务器对应一个逻辑工作区。

应用启动后只显示欢迎页，终端会话及分屏列表为空，不自动打开终端或创建本地 Shell。终端标签和分屏仅保留在本次运行内，不自动保存或跨重启恢复，也不读取旧版已保存的终端布局。用户点击本地终端或主机时创建一个新会话；同一次运行内再次点击则复用已有会话。

工作区可包含：

1. Terminal
2. Files
3. 服务器管理（资源监控与 Linux 运维）

服务器管理提供标准服务器插件入口，各插件贡献资源概览、磁盘、网络、Docker 容器、镜像、进程、监听端口、systemd 服务、日志九类功能；插件页每次仅显示当前分类。概览提供 CPU、内存、Swap、负载与两张趋势图，系统信息、核心明细、采集警告及运维详情按需弹窗。进程详情展示常用字段，完整状态默认折叠。列表限制高度并在表内滚动，窄窗口分类条可横向滚动；选中项使用背景与文字高亮，不添加下划线。

服务器功能由五个独立标准 WASM 插件提供：资源监控（概览、磁盘、网络）、Docker（容器、镜像）、进程与端口、systemd 服务、日志。内置与上传使用同一标准包、仓库、运行时和能力校验。插件管理列表仅卸载；各自页内设置启停和权限，页面铺满可用区域，来源只在自身页展示。全部插件不再设置主机白名单，能力适用于所有主机，实际操作仍绑定当前目标。内置包新安装默认启用，声明权限和必要操作/目录预置且不可修改，已有禁用选择保留；上传包默认禁用且需显式授予能力和路径，上传相同 ID 不获得系统权限。卸载后重启不恢复。工具下拉只显示已启用插件，进程/日志联动仍寻找兼容提供者。危险操作逐次确认；禁用清理自身资源，不停止远端工作负载、共享连接或已有终端。

同一服务器允许创建多个终端会话。

默认会话名称按主机独立计数，本地设备单独计数。只要该设备仍有未关闭会话，新会话继续递增，已分配编号固定；例如打开会话 1、2、3，删除 2 后显示 1、3，再新增为 4。该设备的最后一个会话成功关闭后重置计数，重新打开从会话 1 开始；关闭失败则保留原编号和计数。拖动、自定义名称及其他设备的编号不受影响，重启后首次创建会话从 1 开始。

允许同时打开多台服务器。

切换服务器时，已经建立的终端会话默认保持连接。

主动点击主机树或已有主机的 Shell 工作区标签时，直接进入并连接当前选中的空闲 Shell，无需再点击窗格“连接”；没有 Shell 会话时新建一个。已连接或连接中的会话继续复用，不因重复点击创建会话；多会话/分屏仅连接当前选中的窗格。启动时不恢复终端布局或连接远端；从主菜单返回已有主机工作区或自动切换相邻标签不启动连接，SFTP/监控等工具仍恢复本次运行内的原上下文。认证失败保留错误和显式重试，首次主机指纹确认继续执行。

2026-11-02 布局调整：日常操作先进入主机工作区，再选择工具。每台主机保留最近使用的工具、服务器管理分类、终端会话和远端文件路径；从主机列表或已打开的一级标签切回时恢复该主机上下文，不将其他主机的功能标签改成新目标。

批量运维、自动化和网络诊断是全局独立工具，在功能内部显式选择目标或诊断来源。全局工具标签保持打开时，切换主机后再返回应保留其草稿和目标。终端操作菜单中的“诊断连接异常”和自动化快捷入口可显式预填目标，但不自动执行。主机功能入口位于中央工具栏右侧，终端上方保留会话和主机工具菜单，不重复显示主机连接信息及诊断入口；终端窗格也不保留常驻信息/按钮栏，主机信息可在终端操作菜单中查看，连接状态仍由会话标签显示。关闭设备工作区标签会关闭该设备的全部终端会话及分屏，成功后移除标签；失败时保留未关闭会话与工作区并提示错误。其他设备、SFTP 连接、后台传输和任务不受影响；关闭最后一个工作区显示欢迎页。

自动运维的“常用模板”采用纵向折叠抽屉列表，每个模板默认收起，仅显示名称及展开箭头；点击标题展开完整正文和“使用模板”按钮，再次点击收起，各模板独立控制。支持键盘 Enter/空格展开收起，长正文可滚动。使用模板仍只打开保留完整正文和参数的编辑草稿，不自动保存或执行。

## 4.3 标签页

支持：

- 创建标签页
- 关闭标签页
- 重命名标签页
- 拖动调整顺序
- 标签页右键菜单
- 关闭所有终端会话标签
- 重新连接
- 标签页状态提示

一级工作区标签的右键菜单提供“关闭、关闭右侧、关闭其它、关闭所有”，以右键点击的标签为基准，右键本身不切换当前页。无右侧标签或其他标签时禁用对应操作；范围内每个设备工作区都先关闭其全部终端会话及分屏，失败的工作区保留，其他目标继续关闭。关闭全部成功后显示欢迎页，保留文件连接、后台传输和任务。标签关闭按钮、中键与右键菜单使用相同逻辑，关闭期间避免同一目标重复提交。菜单支持点击外部或 Esc 收起，以及 Shift+F10 / 菜单键打开。

关闭最后一个标签页时，不应自动删除主机配置。

工作区标签栏不提供独立的“打开本地工作区”图标按钮。欢迎页保留“打开本地终端”入口；已有本地工作区继续通过对应标签切换，主机栏展开入口保持可用。

退出应用时应清理活动连接和后台任务。

## 4.4 UI 风格

- 默认深色主题。
- 支持浅色主题。
- 布局紧凑但不拥挤。
- 使用清晰的图标和状态颜色。
- 支持用户调整侧边栏宽度。
- 支持调整终端字体大小。
- 支持窗口大小和布局偏好持久化。

推荐采用 Vue 3 + TypeScript + Pinia。

可以选择成熟 UI 组件库，但必须保持统一视觉规范。

应用支持：

- 单实例策略，第二次启动聚焦已有窗口。
- 应用配置初始化。
- SQLite 数据库初始化和迁移。

2026-11-03 错误提示统一：所有页面、终端窗格、弹窗和表单校验的错误文案只在右下角气泡显示，不再在页头、表单或任务详情中重复显示。气泡支持手动关闭，同一条正在显示的错误去重；轮询得到未变化的错误时不反复弹出。弹窗打开时气泡仍须可见、可关闭。气泡文字可用鼠标拖动选中，并通过 Ctrl+C 复制；长文案换行和弹窗内提示同样支持。连接/任务失败状态、重试入口、监控样本过期标记、主机密钥确认及危险操作风险确认保留；终端、日志及命令结果的原始输出仍作为业务数据保留。

未来可增加托盘常驻功能，但不属于 MVP 必需范围。

退出前应：

1. 终止正在运行的监控采样任务。
2. 关闭 SSH 连接。
3. 停止或取消后台传输。
4. 保存非敏感应用状态。
5. 释放资源。

存在未完成文件传输时，应提示用户，避免静默中断。

# 6. M02：主机连接管理

## 6.1 新建主机

支持填写：

| 字段 | 说明 |
|---|---|
| 名称 | 用户自定义名称，可选 |
| 地址 | IP 或域名 |
| 端口 | 默认 22 |
| 用户名 | SSH 登录用户 |
| 认证方式 | 密码、私钥、SSH Agent |
| 凭据引用 | 引用安全凭据存储 |
| 连接超时 | 默认 15 秒，可配置 |

主机名称可留空（仅空白也视为未填写）。未填写时，主机树以地址作为显示名称：SSH 端口为 22 时只显示 IP / 域名，其他端口显示 `地址:端口`；IPv6 非默认端口使用 `[地址]:端口`。填写名称时优先显示自定义名称。

主机表单不再提供分组选择。新建主机使用右键目标文件夹作为归属，从根目录或欢迎页新建则直接归属根目录；编辑时保留原文件夹，移动主机通过树内拖动完成。保存失败保留草稿和明确错误，不回退到根目录。

2026-11-03：主机管理移除标签、备注和收藏功能。新建/编辑表单不再提供这些字段，主机树不显示收藏标记或标签/收藏筛选；搜索仅匹配名称、地址和用户名。旧数据库与备份中的对应字段兼容保留，编辑其他配置时不清空历史数据。

地址必须符合合法 IP 或主机名格式。

端口范围为 1～65535。

## 6.2 主机文件夹

支持：

- 默认显示不可删除或重命名的“根目录”，已有未分组主机直接显示其中
- 将已有分组保留为根目录下的文件夹，支持创建多级子文件夹
- 编辑文件夹名称；沿用现有名称全局唯一约束
- 删除文件夹前确认，主机和子文件夹保留并移动到父目录
- 将主机拖动到任意文件夹或根目录
- 展开和折叠文件夹，搜索结果显示完整祖先路径
- 按名称、地址和用户名搜索

文件夹关系持久化并纳入备份/恢复，父目录缺失或循环必须拒绝，不通过名称或缩进伪造层级。根目录为内置树节点，不写入一条可被删除的普通文件夹数据。

## 6.3 主机操作

主机配置统一在工作区主机树管理。移除顶部管理分组、刷新、新建按钮及其整条工具栏，原三点工具面板和排序设置也不恢复，列表沿用默认名称顺序。“全部主机”右侧常驻“导入 OpenSSH”和“导出配置”图标按钮，下方依次为搜索框和主机树；固定区域不随列表滚动。未加载目录或操作进行中禁用导入/导出，空目录加载成功后可用。主机行展示名称、地址和连接状态，单击恢复该主机工作区。

主机行不再显示编辑和删除图标，包括悬停与键盘焦点状态；编辑/删除统一由右键菜单进入，名称区域不再预留行内操作按钮空间。右键菜单按目标类型提供操作：根目录提供“新建主机、新建文件夹”；普通文件夹另提供“重命名文件夹、删除文件夹”；主机提供“连接主机、编辑主机、复制主机、删除主机”，不提供新建文件夹。复制主机在原文件夹生成独立配置副本，保留连接参数和凭据引用，不覆盖原主机或自动连接。

打开右键菜单本身不改变选中主机、连接或当前工作区，所有动作绑定右键目标。空白区域、本地设备和主机节点不提供新建文件夹；根目录不能删除或重命名。支持 Shift+F10/菜单键打开、方向键选择、Esc/Tab 关闭及焦点恢复，菜单限制在可见窗口内；切换模块、窗口失焦/缩放或列表滚动时关闭。管理操作不自动连接；仅显式“连接主机”或原左键行为进入连接流程。主机和文件夹删除均先确认，失败保留数据并提示原因。终端及文件页面各自的菜单不受影响。

删除主机时必须显示确认提示。

## 6.4 连接状态

每台主机至少包含以下状态：

- 未连接
- 连接中
- 已连接
- 正在重连
- 连接失败

状态应准确反映真实连接生命周期。

不得仅依靠 TCP 建立成功就认定 SSH 登录成功。

## 6.5 连接复用

同一主机允许多个逻辑会话。

基础设计：

- 主机配置与活动连接分离。
- 一个 SSH Transport 可复用多个 Channel。
- 不同终端拥有独立 PTY Channel。
- 允许根据认证及安全上下文建立多个 Transport。
- 单个终端异常不应导致其他独立终端全部关闭。

## 6.6 OpenSSH Config

支持导入常见字段：

- Host
- HostName
- Port
- User
- IdentityFile
- ProxyJump（具备支持能力时）
- 其他常见字段按兼容范围处理

导入时显示预览，允许选择主机。

不得直接覆盖已有主机。

对于尚不支持的 SSH Config 配置项，应明确提示，而不是静默忽略后错误连接。

# 7. M03：SSH 终端

此模块是整个产品最关键的模块。

## 7.1 基础能力

必须支持：

- SSH 连接。
- 交互式 Shell。
- PTY 分配。
- 终端窗口大小同步。
- UTF-8 文本。
- ANSI 控制序列。
- 256 色和 True Color。
- 鼠标交互。
- Ctrl+C、Ctrl+Z 等组合键。
- 复制和粘贴。
- 文本选择。
- 终端滚动。
- 会话断开提示。
- 手动重新连接。

终端渲染优先使用 xterm.js。

SSH 终端支持 `rz` 的 ZMODEM 上传：识别远端握手后自动打开原生多文件选择器，用户选择后通过当前终端通道上传到远端命令指定的位置。显示进度，支持取消、中文文件名、二进制及空文件；取消选择结束握手，断线或重连不得继续读取旧选择或向新会话发送数据。传输期间隔离普通输入与粘贴，Ctrl+C / Ctrl+X 可取消。每批最多 100 个普通文件，单文件小于 4 GiB；远端拒收或同名跳过必须如实提示。当前不提供 `sz` 下载，下载使用 SFTP。

## 7.2 多终端

支持：

- 多标签终端。
- 同一主机多个 Shell。
- 同时连接不同主机。
- 水平和垂直分屏。
- 分屏拖拽调整大小。
- 独立滚动区域。

每个终端必须具有唯一 Session ID。

终端工作区采用紧凑布局：会话栏左侧显示可横向滚动的会话标签及新建按钮，右侧显示 SSH、SFTP 与工具下拉菜单，窄窗口可换行；分屏、重命名、关闭其他/右侧会话及保存布局不提供常驻图标按钮。会话页签右键菜单从上到下固定为“复制、重命名、关闭所有、关闭”，移除“关闭其它”操作。复制按右键点中的页签所属主机新建并切换到一个独立会话，本地页签则新建本地 Shell；不复制原运行会话、分屏或历史命令，沿用连接验证和窗格数量限制。关闭所有关闭该主机的全部会话及其分屏；关闭仅作用于右键目标。批量关闭不影响其他主机（含本地设备）的会话；失败的页签保留并显示错误，其他目标继续关闭；标签和分屏仅保留在本次运行内。新建/分屏快捷键继续可用。移除终端窗格内常驻的主机名称、账号端点、状态和按钮栏，终端画面紧接会话栏。连接/重新连接、复制/粘贴、查找、跨工具入口、端口转发、导出和关闭通过终端内容区的右键菜单使用；开启快捷粘贴时普通右键仍粘贴，Shift+右键、Shift+F10 或菜单键打开操作菜单。不跨重启恢复终端标签或分屏；错误及主机密钥确认继续显示。

关闭某一个终端不能错误关闭其他终端。

## 7.3 终端设置

支持：

- 字体
- 字号
- 行高
- 光标样式
- 光标闪烁
- 滚动缓冲区大小
- 主题配色
- 粘贴确认策略
- 选中即复制、右键即粘贴：在“设置 → 终端”的“终端显示与输入”中提供一个联动开关，默认关闭，保存后对已打开的终端生效；仅终端内容区处理右键，继续保留连接状态、单次大小和大文本确认保护。

桌面端复制与粘贴通过原生系统剪贴板接口读取/写入纯文本，终端右键、菜单、快捷键和选中即复制统一使用该接口，文件路径、诊断/批量结果、自动化输出与日志复制也保持一致。Windows 桌面端不再触发网页剪贴板授权提示；不自动读取剪贴板、不回退网页 Clipboard API，纯浏览器预览明确不可用。2 MiB 粘贴上限、大文本/多行确认、Bracketed Paste 和断线/重连保护继续有效。

终端内容区支持 Ctrl+鼠标滚轮调整字号：向上滚动放大、向下滚动缩小，每次调整 1，范围 10–32。沿用全局终端字号设置并保存，已打开的终端同步更新并适配 PTY 尺寸；普通滚轮保留终端滚动和鼠标上报，不缩放整个界面。连续滚动合并尚未保存的目标字号，保存失败沿用错误气泡并保留已保存字号。

## 7.4 快捷键

建议默认快捷键：

| 操作 | 快捷键 |
|---|---|
| 新建终端 | Ctrl+Shift+T |
| 关闭当前标签 | Ctrl+W |
| 下一个标签 | Ctrl+Tab |
| 上一个标签 | Ctrl+Shift+Tab |
| 查找 | Ctrl+F |
| 复制 | Ctrl+Shift+C |
| 粘贴 | Ctrl+Shift+V |
| 放大字体 | Ctrl++ |
| 缩小字体 | Ctrl+- |

在 macOS 上应适配平台习惯。

终端应用快捷键不得无意拦截远程程序依赖的按键。

## 7.5 断线重连

SSH 连接异常断开后：

1. 显示断开原因。
2. 标记连接状态。
3. 提供重新连接按钮。
4. 保留本地终端历史显示内容。
5. 重连后创建新的远程 Shell 会话。

不得假装恢复已经失效的远程 Shell、进程状态或交互上下文。

默认不自动重新执行用户之前输入的命令。

## 7.6 终端安全

- 默认启用 SSH 主机密钥校验。
- 首次连接显示主机密钥指纹。
- 主机密钥发生变化时必须阻止静默连接。
- 禁止自动接受发生变化的主机密钥。
- 禁止把密码和私钥记录到应用日志。
- 密码输入不得回显。
- 大文本粘贴应提供可配置确认。
- 支持终端 Bracketed Paste 行为。

## 7.7 性能要求

- 大量终端输出不得导致 UI 长时间无响应。
- 终端输出必须使用流式传输。
- 有限缓冲与背压控制必须明确。
- 关闭会话后必须取消对应异步任务。
- 终端 resize 不应导致 Shell 重启。
- 高并发会话不能使用一个全局锁串行处理所有输出。

# 8. M04：认证与凭据管理

## 8.1 认证方式

支持：

1. 用户名 + 密码。
2. SSH 私钥。
3. SSH Agent。

私钥格式和加密算法应在技术选型阶段验证兼容性。

不应为了支持更多算法而降低安全标准。

## 8.2 凭据存储

主机信息保存在 SQLite。

密码、私钥口令和其他秘密信息通过操作系统安全存储机制管理，或采用具备明确密钥管理方案的加密保险库。

不得将明文密码保存在 SQLite、JSON 配置或日志中。

主机配置只保存 Credential ID 或安全引用。

## 8.3 SSH 主机信任

应独立维护可信主机密钥信息，并考虑与用户现有 OpenSSH known_hosts 配置的兼容。

必须区分：

- 首次连接未知主机。
- 已信任且密钥匹配。
- 已信任但密钥发生变化。
- 不支持的主机密钥算法。

## 8.4 凭据使用

用户打开已保存主机时：

1. 获取主机配置。
2. 根据凭据引用获取所需认证信息。
3. 建立 SSH 连接。
4. 不向前端发送不必要的明文秘密。
5. 在不再需要时释放敏感信息。

# 9. M05：SFTP 文件管理

## 9.1 页面布局

采用双栏布局：

左侧：本地文件系统。

支持调整左右宽度。

也允许切换到仅远程文件视图。

## 9.2 文件浏览

支持：

- 目录导航
- 返回上级目录
- 刷新
- 路径输入
- 文件排序
- 显示文件大小
- 显示修改时间
- 显示文件权限
- 新建目录
- 重命名
- 删除
- 搜索当前目录文件名

MVP 不实现远程全文内容搜索。

## 9.3 文件传输

支持：

- 上传文件
- 下载文件
- 批量上传
- 批量下载
- 递归目录传输
- 拖放上传
- 传输进度
- 当前速度
- 已传输字节
- 取消任务
- 失败提示

- 跳过
- 覆盖
- 重命名

## 9.5 远程文本编辑

支持：

- 打开 UTF-8 文本文件。
- 编辑内容。
- 保存到远程服务器。
- 检测保存前文件是否被外部修改。
- 保存失败提示。
- 常见文件权限问题提示。

编辑器可采用 Monaco。

对二进制文件、超大文件和无法正确解码的文件，应阻止直接文本编辑或显示明确警告。

优先采用临时文件写入、校验及安全替换策略；需要考虑权限、属主和跨文件系统限制。

## 9.6 删除操作

删除文件或目录必须确认。

递归删除需要二次确认或明确标识危险范围。

不得使用拼接未经转义的 Shell 命令实现普通 SFTP 删除操作。

# 10. M06：服务器资源监控

## 10.1 工作模式

MVP 通过 SSH 远程命令采集 Linux 服务器资源信息。

不要求服务器安装 Agent。

支持常见 Linux 发行版，优先兼容：

- Ubuntu
- Debian
- Rocky Linux
- CentOS
- AlmaLinux

## 10.2 监控指标

| 指标 | 说明 |
|---|---|
| CPU | 总体使用率 |
| 内存 | 总量、已用、可用、使用率 |
| Swap | 总量和使用情况 |
| 系统负载 | 1、5、15 分钟 |
| 磁盘 | 挂载点、总量、剩余、使用率 |
| 网络 | 接口收发速率 |
| 运行时间 | 系统 Uptime |
| 系统信息 | 主机名、发行版、内核、架构 |

## 10.3 采样规则

默认采样间隔：3 秒。

支持：

- 3 秒
- 5 秒
- 10 秒
- 30 秒

当监控页面不可见时，应降低采样频率或暂停非必要采样。

采样失败不得影响正常 SSH 终端使用。

## 10.4 指标计算

CPU 使用率需要根据连续采样的 CPU 时间差计算，不能直接把 `/proc/stat` 累计值作为百分比。

网络速率根据连续采样的接口字节计数器计算。

对于第一次采样，应显示待计算状态。

应处理计数器异常、接口消失和时间间隔过短等情况。

## 10.5 历史数据

MVP 保存当前会话内有限的监控历史，用于绘制短时趋势图。

例如保留最近 30 分钟的样本。

不实现长期时序数据库。

关闭程序后无需保留完整指标历史。

## 10.6 监控失败

当出现：

- SSH 连接断开。
- 远程命令不可用。
- 权限不足。
- 数据格式不兼容。

必须显示明确错误。

不得将采集失败显示为 CPU 0% 或内存 0%。

## 11.2 功能要求

## 11.3 命令属性

| 命令内容 | 实际 Shell 命令 |

# 14. 非功能需求

## 14.1 性能

以下作为 MVP 的工程目标，需在明确测试机器和测试条件下验证。

- 冷启动目标：3 秒内可交互。
- 空闲内存目标：尽量控制在 150MB 以内。
- 支持同时维护至少 20 个活动 SSH 终端会话。
- 正常终端输入应无明显额外卡顿。
- 文件传输不得阻塞终端交互。
- 监控采样不得阻塞文件传输。

注意：WebView、操作系统、终端缓冲区、运行环境会影响内存和启动时间，因此目标不能作为未经测试的性能承诺。

## 14.2 稳定性

- SSH 连接错误不导致应用崩溃。
- 单个终端错误不影响其他终端。
- SFTP 操作失败不影响已有终端。
- 远程监控异常不影响 SSH 会话。
- 后台任务必须可取消。
- 不允许无限增长的异步队列。

## 14.3 安全性

- 默认进行 SSH 主机密钥验证。
- 敏感信息不得明文持久化。
- 不允许绕过连接安全校验。
- 不直接拼接不可信输入生成 Shell 命令。
- 前端不能无约束执行任意本地系统命令。
- Tauri 权限应按最小权限原则配置。
- 文件传输遵循目标权限限制。
- 不私自上传用户服务器信息。
- 自动更新如果实施，必须使用可信签名与安全更新机制。

## 14.4 兼容性

首个开发目标为 Windows 11 x64。

架构应具备 Windows、macOS、Linux 适配能力，但未经完整测试的平台不得宣称已经正式支持。

## 16.1 技术选型

| 层次 | 技术 |

| 桌面框架 | Tauri 2 |

SSH 和 SFTP 库选型必须先完成可运行的技术验证，验证范围包括私钥认证、PTY、多 Channel、主机密钥校验及跨平台支持。

## 16.2 工程结构

```text
serverdeck/
├── apps/
│   └── desktop/
│       ├── src/
│       │   ├── components/
│       │   ├── views/
│       │   ├── stores/
│       │   ├── composables/
│       │   ├── services/
│       │   ├── types/
│       │   └── styles/

│

│   ├── storage/
│   └── security/
│
├── tests/
├── docs/
└── Cargo.toml
```

以 Cargo Workspace 管理 Rust 工程。

## 16.3 核心设计

Rust Core 不直接依赖 Vue 组件。

前端不得直接负责真实 SSH 连接管理。

各模块的职责如下：

**core**

领域模型、基础类型、错误定义。

**application**

业务用例、Session 生命周期、任务调度和模块协调。

**ssh**

SSH 连接、认证、PTY、Channel、重连。

**sftp**

远程文件操作、传输队列、进度事件。

**monitor**

远程资源采集、指标计算和采样控制。

**storage**

SQLite 数据访问、迁移、非敏感配置持久化。

**security**

凭据访问、主机信任、敏感信息处理。

## 16.4 IPC 通信

普通业务操作使用 Tauri Command：

```text
host_create
host_update
host_delete
host_list
ssh_connect
ssh_disconnect
terminal_create
terminal_resize
sftp_list_directory
transfer_create
transfer_cancel
monitor_start
monitor_stop
```

上述名称是推荐接口契约，最终应与 Rust 和 TypeScript 类型定义保持一致。

终端持续输出使用流式消息机制。

文件传输使用独立任务状态和进度事件。

监控数据使用独立采样事件。

不应把高频终端消息和普通业务操作混在同一个全局同步处理队列中。

## 16.5 生命周期

应用必须明确管理：

- SSH Connection
- SSH Channel
- Terminal Session
- File Transfer Task
- Monitor Task
- Window / Tab

关闭窗口、标签或主机连接时，只能释放与其实际所有权对应的资源。

应避免共享 Connection 被单个标签错误关闭。

# 17. 交互流程

## 17.1 首次连接

1. 用户打开 ServerDeck。
2. 点击新建主机。
3. 填写 IP、端口、用户名、认证方式。
4. 点击测试连接或连接。
5. 如为未知主机，显示主机密钥指纹确认。
6. 验证凭据并建立 SSH。
7. 创建 PTY。
8. 打开终端标签。
9. 用户可进一步打开文件或监控视图。

## 17.2 文件上传

1. 用户选择主机。
2. 打开 Files。
3. 选择本地文件。
4. 选择远程目标路径。
5. 发起上传。
6. 展示进度、速度、目标路径和状态。
7. 成功后刷新远程目录。
8. 失败时保留错误信息并允许重新执行。

## 17.3 监控

1. 用户选择主机。
2. 打开 Monitor。
3. 检查远程 Linux 能力。
4. 采集 CPU、内存、磁盘和网络数据。
5. 周期性更新图表。
6. 关闭视图后停止或降低采样频率。
7. 连接断开时显示采样中断。

# 18. 验收标准

## 18.1 SSH 验收

- 使用密码可以登录测试 Linux 服务器。
- 使用私钥可以登录。
- 不正确的凭据显示明确错误。
- 首次连接能确认主机指纹。
- 主机密钥变化会被检测。
- `vim`、`top` 等交互程序正常工作。
- `Ctrl+C` 可中断前台命令。
- 调整窗口大小可以同步 PTY。
- 多个终端并行操作不互相干扰。
- SSH 断开不会导致程序崩溃。

## 18.2 SFTP 验收

- 可以浏览远程目录。
- 可以上传和下载文件。
- 文件内容通过哈希校验保持一致。
- 中文文件名正常显示。
- 文件名包含空格及特殊字符时操作正常。
- 文件权限不足时有明确提示。
- 可以取消传输。
- 大文件传输不阻塞界面。
- 已确认删除的目标正确，未选中文件不受影响。

## 18.3 监控验收

- CPU 使用率计算合理。
- 内存统计与 Linux 系统指标基本一致。
- 磁盘容量与系统查询结果一致。
- 网络速率为采样差值计算。
- 监控失败不会显示伪造的正常指标。
- 停止监控后没有持续后台采样任务。
- 监控开启时 SSH 终端仍可正常交互。

## 18.4 数据与安全验收

- 重启应用后主机配置保留。
- 重启应用后分组保留。
- 数据库中不出现明文 SSH 密码。
- 日志中不出现明文私钥和密码。
- 导出的默认备份不包含秘密凭据。
- 非法输入不导致程序异常退出。

# 22. 开发约束

Codex 实施本项目时，应遵循：

1. 优先保证核心功能正确，不得以模拟数据冒充已实现的真实服务能力。
2. 代码使用 Rust、TypeScript，保持统一项目风格。

7. 敏感信息不可写入普通日志。

9. 关键模块必须提供自动化测试。
10. 每完成一个开发阶段，都要进行构建、测试和真实功能验证。
11. 不得未经确认就增加 PRD 范围之外的大型模块。
12. 不得为了快速实现而牺牲数据安全和基础连接可靠性。

# 24. 后续技术决策原则

1. 当前问题。

4. 性能与维护成本。
5. 推荐方案。
6. 验证方式。

未经验证的设计假设不得描述为已经完成的功能。
