# 网络诊断与多服务器批量运维验收

2026-11-02。按用户授权继续 PRD 的 P1 网络/批量范围，复用现有主机、凭据、严格 SSH 信任、Operations/Files 租约和 SFTP 任务。未初始化 Git、重置主机数据、修改 PRD 或开始后续自动化阶段。

## 交付行为

- Network 按 Ping、TCP、DNS、Traceroute、MTR、接口、连接状态、SSH 延迟组织；明确标识本机或远端 HostId/SessionId，提供开始、独立停止、总时限、实时文本、退出码/原因、复制和导出。Ping 不通不会把主机标为宕机。
- 本机使用 Tokio DNS/TCP 和系统目录中的受管工具；Windows 为 ping/tracert/ipconfig/netstat，不开放任意本地命令。远端为经过验证的固定 exec 模板，MTR raw 输出逐跳结果；缺少工具或权限明确失败，不自动安装或提权。
- SSH 延迟通过已有可信连接上的固定 exec 测量 Channel+Shell 往返，明确包含远端调度，不冒充握手、认证时延或纯 TCP RTT。DNS 返回系统解析器的地址结果，不是完整 DNS 记录浏览器。
- 批量命令选择 1–32 主机，先连接并逐台核对未知指纹，再预览全部目标的名称、地址、端口、用户名、HostId 和完整命令，输入目标数量确认。预览冻结输入和 SessionId；不使用随后改变的勾选项或命令。
- 默认并发 3、可设 1–8，每台超时 1–3600 秒；全局最多 8 个诊断/批量活动槽，最多 4 个未结束批次。逐台保留 HostId/SessionId、stdout/stderr、退出码、时间、错误及进度，结果不会混入其他主机。
- “取消未执行目标”保留在途命令继续；另有“请求停止全部”。超时、断线和请求停止的远端命令标为 uncertain，不把 TERM/Channel close 视作进程必已停止；不自动重试、提权、重连执行或回放命令。
- 单文件分发使用真实 Rust SFTP 队列，支持每台进度、并发、冲突/跳过/改名/覆盖确认、取消，以及已结束失败目标的预览重试。沿用临时文件、源变化检查、回读 SHA-256、安全提交；重试沿用原冲突策略，需要改变策略时新建批次。
- 文件取消后等待清理/提交屏障再释放批量槽，最多等待 35 秒；未确认的清理保留 SFTP 队列/恢复路径。页面关闭后任务继续，退出评审检查未完成任务并请求取消；进程重启不恢复执行。
- 诊断最多 16 条历史，每条文本 256 KiB；批量最多 8 批历史，每台 stdout/stderr 各 32 KiB，按 UTF-8 字符边界裁剪并显示丢弃量。revision 快照只向前端发送变化记录，Rust 查询在异步 IPC 工作线程执行；没有输出自动落盘或云上传。

SQLite 仍为 v4。任务历史、命令和输出只在当前进程内，不新增数据库表、持久任务总线、日志数据库或定时调度器。

## 原生实机验收

环境：Windows x64、Rust 1.97.1、Tauri 2/WebView2、russh 0.65.0；用户授权的 Ubuntu 24.04.4/OpenSSH 9.6p1，Docker 29.9.2。全程使用普通 SSH 账号已获授权的 Docker 权限；未 su/sudo、修改宿主 sshd、安装远端 Agent、拉取镜像或改现有业务容器。

`npm run test:terminal -- --network-batch`：**18 项通过**，包含原有 11 项真实 SSH 基线和以下 7 组：

1. 本机 Ping、DNS localhost、到临时回环监听的 TCP、Traceroute 回环、接口、连接状态；实际下载并解析来源为 local 的 JSON，中文 Windows 输出无替换乱码。
2. 远端八种工具均完成，包括 **MTR 和 Traceroute**，不是跳过或伪造结果；固定 SSH exec 返回实测往返时间。两个持续 Ping 独立取消；停止一个不影响另一个或原 SSH。存在任务时实际退出入口要求确认，选择继续使用后任务仍可控制。
3. 创建两个独立 Linux SSH 容器，分别有主机密钥、文件系统、hostname 和回环映射端口。临时 Ed25519 公钥认证，预览指纹与通过已可信宿主 SSH 取得的实际指纹一致后确认。统一命令在一台成功、另一台返回 7，逐台 hostname/中文/stdout/stderr/退出码和 UI 归属正确，实际下载的批量 JSON 与目标结果一致。
4. 并发 1、每台 1 秒，先运行的命令超时为 uncertain，排队目标取消且没有执行；独立检查远端 attempt 标记，只有已执行目标有一次记录，没有自动重试。测试不假定超时进程必已停止。
5. **1 MiB** 单文件分发到两台，文件名含中文、空格、引号、分号、美元符号，目标目录为中文空格路径。每台传输完成字节数正确，随后在两台独立执行 sha256sum，与本地 SHA-256 完全一致。
6. 冲突 fail 策略明确失败，显式覆盖后成功；不存在的目录导致失败，明确创建目录后，通过 UI 预览仅重试一个原失败目标并成功。**64 MiB** 文件在已有传输进度时请求停止：一个目标未执行取消、另一个结果未确认且实际 SFTP 状态为 cancelled，未留下恢复路径；清理等待后队列无活动任务。
7. 清理只移除 UUID 所属容器/镜像、目录/文件、测试 Host/凭据、密钥和转发；原主机 SSH Shell 继续执行标记命令。最终隔离 SQLite user_version=4，hosts/credentials/secret_gc 均为 0。

证据目录：`.local/terminal-e2e/1793549098561-9eb0e14f-fec9-4867-ac71-3cbf3e1c36f0`，包括 `result.json`、`network-remote.json`、`network-export.json`、`batch-partial.json`、`batch-export.json`、`batch-files.json`、`batch-timeout.json`、`batch-cancel.json`、`network.png`、`batch.png`、`network-batch-cleanup.json`（cleaned=true）。截图经过查看，UI 文本为真实 IPC 结果。

测试容器使用当前宿主 OpenSSH/依赖库构造一次性镜像，不依赖下载镜像。容器有 CPU/内存/PID 限额、no-new-privileges，只给 sshd 所需能力，不挂载 Docker Socket；仅各自生成的主机密钥目录只读挂载。配置/账户只属于测试容器，容器 root 不代表宿主 SSH root 登录。标识、标签、路径先记录并校验所有权后清理，不 prune 或遍历删除其他资源。未完成创建时也按相同 UUID 清理。

## 复现

```powershell
cargo test --workspace --offline
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline -- -D warnings
npm run typecheck
npm run lint
npm run format:check
npm test
node tools/tauri.mjs build --debug --no-bundle
```

原生套件需要已授权的 Ubuntu x64/OpenSSH/Docker 环境及本机 ssh-keygen。设置 SERVERDECK_TEST_HOST、SERVERDECK_TEST_USER 和独立可信核对的 SERVERDECK_TEST_PIN，然后隐藏输入密码：

```powershell
$testSecret = Read-Host 'SSH test password' -AsSecureString
$env:SERVERDECK_TEST_PASSWORD = [System.Net.NetworkCredential]::new('', $testSecret).Password
try { npm run test:terminal -- --network-batch }
finally { Remove-Item Env:SERVERDECK_TEST_PASSWORD }
```

套件与 advanced/sftp/monitor/ops 分别运行，使用 `.local/terminal-e2e` 内独立 EXE、数据库、凭据引用及 loopback CDP；不开放正式应用的调试端口。密码不传参数、不写文件或日志。受限沙箱禁止 ICMP、loopback 或测试缓存重命名时，需要正常本地进程权限。

## 限制与下一步依赖

- 实机为 Windows→一台 Ubuntu 宿主上的两个独立 Linux SSH 容器，不代表多机房、复杂路由、其他发行版、macOS/Linux 客户端矩阵已通过。容器共享宿主内核，未模拟物理网络丢包、长时抖动或完整公网路径。
- Windows 本机 MTR 明确不支持，选择远端已安装工具；Linux/macOS 本机受管程序路径已实现但未实机验收。其他 OEM 代码页、UTF-8 本地环境和全部语言输出仍需矩阵；本次验证中文 Windows 代码页及增量边界。
- 远端依赖 Linux 常用工具：ping、getent、traceroute/tracepath、mtr、ip、ss；远端 TCP 依赖 Python。工具缺失、权限/原始套接字受限会失败，不自动安装或申请管理员权限。DNS 只显示地址解析，暂不含自选 DNS、MX/TXT 等记录和 DNSSEC。
- SSH exec RTT 包含 Channel/调度，不测初次登录、密钥交换或认证耗时。Traceroute 最多 16 跳；连续探测在次数/总时限后停止，不是无限监控。所有失败保留执行来源，不更新主机“宕机”状态。
- 命令不是事务：执行可有副作用，超时或网络中断可能已经提交，TERM 也不保证杀死子进程树或不可中断 I/O。没有自动回滚/重试；取消未执行任务不会撤销已执行动作。
- 批量文件仅单普通文件，不含多源目录树、断点续传或跨进程恢复；符号链接源拒绝。重试保持原冲突策略，不绕过覆盖确认。异常网络可能留临时文件，SFTP 恢复路径和未确认状态保留，不能保证立即清理。
- 业务输出缓存有界，不等同于进程 RSS 或依赖内部队列的硬配额；尚未做 32 目标长时间压测、20 会话或完整恶意服务端内存基准。复制使用系统 Clipboard API，跨平台剪贴板权限矩阵仍待验证。
- 既有 RSA/平台依赖 RustSec 告警及 Monaco 大 chunk 提示保留。下一步建议完成发行版/客户端、真实多宿主网络、长时负载、安全依赖和安装包发布门禁；不提前实现定时、无人值守或批量配置模板。
