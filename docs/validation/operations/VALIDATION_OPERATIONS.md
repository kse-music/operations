# Linux 运维阶段验收

2026-11-01。基于当前主机工作区、SSH、SFTP 和 Monitor 继续实施；没有覆盖既有主机配置，没有初始化 Git。PRD 的 Docker/日志/运维 P1 范围由用户明确追加授权，本阶段不扩展批量自动化、云端、Agent 或完整 IDE。

## 已完成的真实能力

- 主机详情、右键菜单、终端和主导航进入同一 Linux 运维工作区，沿用 HostId、系统凭据库、主机密钥信任和代理/跳板路由。Operations 租约与 PTY、SFTP、Monitor 分开管理，可共享已认证 Transport。
- Docker CLI 检测、客户端/服务端版本、Daemon 状态、容器和镜像列表、容器状态/名称/镜像/端口/运行时间、详情/挂载/环境/资源，启动、停止、重启、删除容器和删除镜像。固定连接 Unix Socket，清除 Docker context/Host/TLS 环境覆盖，不启用 TCP API。
- 状态修改均确认完整目标；容器/镜像使用完整 ID，删除不带 force 或删除卷选项。容器所有环境变量值默认遮蔽，显式确认后才读取展示；inspect 返回前经 Rust 白名单筛选，不把原始 Cmd/Labels 等额外内容传到页面。
- 独立容器 Shell 走原有真实 xterm/PTY 生命周期，执行固定的 docker exec -it /bin/sh 或 /bin/bash，遵循容器配置的用户，不自动切换 root。布局恢复不保存、重放容器动作。
- Docker 日志、主动指定的绝对路径文件和服务 journal 支持最近 N 行、实时跟踪、暂停/继续、关键词过滤、复制与导出可见文本；Docker/journal 保留来源时间戳，文件日志不虚构事件时间。每标签最多 1 MiB/5000 行，全局最多 8 标签，关闭标签、换主机或离页停止对应流。
- ps/proc 进程列表、PID/用户/CPU/内存/运行时间/命令名称、排序、搜索、详情及 TERM/KILL/INT/HUP。CPU 是 ps 的进程生命周期均值，界面明确标注。信号先持有 pidfd，再核对 boot_id/start_ticks，避免 PID 复用；缺少 Python/pidfd 时明确失败。
- ss 的 TCP/UDP 监听、地址/端口、权限允许的 PID/进程名和搜索；缺少进程信息保留未知。TCP 连通性检测明确选择本地 Tokio 或远端 Python，不自动扫描端口。
- systemd 系统/当前用户范围的列表、状态、详情、启动/停止/重启、启用/禁用自启和 journal 快捷入口。不支持、权限不足、非零退出和网络错误均显示原因，不自动 sudo/su，不安装远端软件。
- 本地反馈仅保留本进程内最多 100 条时间/HostId/目标/动作/结果，不默认记录敏感输出，不写 SQLite。SQLite schema 仍为 v4，无新增业务迁移。

## 复现

```powershell
cargo test --workspace --offline
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline -- -D warnings
npm run typecheck
npm run lint
npm run format:check
npm test
node tools/tauri.mjs build --debug --no-bundle
```

原生验收需有权限且适合准备隔离测试资源的 Linux，已有可用 /bin/sh 的本地 Docker 镜像，以及用户级 systemd。设置 SERVERDECK_TEST_HOST、SERVERDECK_TEST_USER 和可信核对的 SERVERDECK_TEST_PIN，再输入密码：

```powershell
$testSecret = Read-Host 'SSH test password' -AsSecureString
$env:SERVERDECK_TEST_PASSWORD = [System.Net.NetworkCredential]::new('', $testSecret).Password
try { npm run test:terminal -- --ops }
finally { Remove-Item Env:SERVERDECK_TEST_PASSWORD }
```

`--ops` 单独运行，不与 monitor/sftp/advanced 混用；先构建嵌入资源的真实应用。工具使用 `.local/terminal-e2e` 内的隔离 EXE、数据库、系统凭据引用和 loopback CDP，不开启正式应用的调试端口。沙箱禁止 loopback 或测试缓存重命名时，需要正常本地进程权限。

## 尚未验证、风险和下一步依赖

- 实机范围为 Windows → 当前 Ubuntu/Docker 29.9.2。macOS/Linux 客户端、其他发行版/Docker 版本、rootless Socket 实机矩阵仍待验证。系统级 systemd 列表已读取，成功修改仅在专属用户级单元验收，不宣称已验证生产系统服务变更。
- 依赖 SSH 账号原有权限及远端 Docker CLI、ps、ss、systemd/journal 工具。信号要求 Python 和 Linux pidfd；远端 TCP probe 要求 Python。缺少能力会失败，不自动安装/提权。用户服务自启还取决于用户管理器/linger，应用不更改 linger。
- exec 最多 8 个在途、等待 3 秒、执行 30 秒、stdout 2 MiB/stderr 16 KiB、解析最多 10000 行；超大主机可能触发明确限额。写操作在当前服务内串行，等待 3 秒；尚未开展长期吞吐、20 会话或整个进程内存测量。
- 超时/断线后的远端动作可能已提交，反馈标明失败或结果未确认，不声称事务回滚或自动重试。需要重新查询后由用户决定。未完整模拟真实 Docker/systemd 写操作执行瞬间的网络故障；协议层已覆盖超时和硬断线。
- 日志会裁剪最旧缓存，导出只含当前可见/过滤文本，不是完整会话录制。暂停依靠 SSH 背压，不保证远端应用无限保留输出。TERM/close 已在当前 OpenSSH 验证释放进程，其他 SSH 服务端对 signal 的支持仍待兼容性验证，不承诺立即终止不可中断内核 I/O。
- 复制采用真实系统 Clipboard API，完整跨平台剪贴板权限矩阵未自动化；文件导出已实际下载校验。操作反馈不持久化，不作为审计系统。
- RustSec 既有 RSA 和平台依赖告警仍是发布风险；未增加 ignore，也未放开本地 RSA 私钥签名。下一步应补齐客户端/发行版矩阵、系统级服务隔离验收及发布安全/性能门禁，不提前扩展业务范围。
