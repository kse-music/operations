# 点击主机直接连接 Shell 验收

日期：2026-11-02。范围为修复恢复的 Shell 被选中后仍需要额外按“连接”的问题。

主机树后续改为双击打开，见[对应验证](#2026-11-11-主机树双击打开)；以下保留原点击行为的历史证据。

## 原因与已完成行为

恢复元数据会创建 idle、connectRequested=false 的窗格。原 App 的 navigate 只为本地空闲窗格设置连接请求，setContext 对已有主机工作区只激活导航，因此新进入和已有工作区两条路径都可能停留在未连接状态。

- 主机树显式选择、已有远程主机 Shell 标签激活以及 Shell 工具选择，现在复用 navigate 连接当前选中的空闲窗格，不需要再次点击窗格“连接”；没有 Shell 会话时创建一个。
- 保留当前工具和最近会话，SFTP/监控等工具不因主机选择切成 Shell。已连接、连接中或等待指纹的会话继续复用，不断开或重复创建；多标签/分屏只发起当前窗格，不连接全部恢复布局。
- 启动 restore 本身仍只恢复元数据。从主菜单返回已有工作区或自动选择相邻标签不会新增连接请求，本地空工作区保持原恢复行为。失败保留错误和显式重试，首次主机密钥确认继续等待用户决定。
- 空闲状态显示改为“未连接”，避免将所有空闲场景都描述成必须点击连接按钮。

- `apps/desktop/src/types/terminal.ts`：更新 idle 显示文案。
- `apps/desktop/src/App.test.ts`：覆盖恢复后首次/已有工作区点击、远程 Shell 标签、只连接当前分屏、重复点击复用、连接中/等待指纹/已连接/失败状态、已有空工作区的显式创建及主菜单边界。
- `apps/desktop/src/components/terminal-clipboard.test.ts`：复用现有真实 TerminalPane 组件测试夹具，验证空闲时不发请求、显式请求仅调用 open 一次、真实组件展示指纹确认且不自动信任。服务返回和 xterm 为单元测试边界，不计为真实 SSH 验收。
