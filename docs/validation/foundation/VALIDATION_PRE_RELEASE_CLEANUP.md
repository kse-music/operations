## 2026-11-09 本机缺失字号配置导致启动失败

本机日常数据库的 `user_version=9`、只读 `quick_check=ok`，但 `application_settings.app_config` 缺少当前必填字段 `interfaceFontSize`。当前 Rust `Database::verify_file` 在原库备份上复现配置解码失败，源错误为缺少该字段；Tauri setup 只展示外层“本地存储操作失败”。这是严格配置契约拒绝不完整开发期配置，无数据库损坏证据。

本次仅修复本机数据，没有修改应用源码或增加旧配置兼容逻辑。先通过 SQLite backup 保存原库，在副本加入 `interfaceFontSize=standard`，用当前 Rust 代码验证并重新打开；再在事务内核对日常库与备份一致，仅补入该字段。逐表及配置断言确认其余偏好、表结构、版本、主机和凭据记录保持不变，原更新时间保留。原始备份与一次性脚本留在 `.local/qa/startup-config-20261109/`，不纳入版本控制。

实际验证：

- 根 `target/` 离线锁定编译 `serverdeck-storage` 一次性诊断程序成功；构建前 D 盘空闲约 165 GiB。复制 EXE 至 QA 后执行，原始配置失败原因与修复副本接受/重开断言通过，临时 example 源码已移出应用目录。
- 修复事务核对完整 SQL 数据；将新增字段还原于内存副本后，与原库备份逐字 SQL 导出相同。修复后的 `quick_check=ok`。
- 从 QA 复制的现有 Debug EXE 使用真实日常目录启动 Windows/WebView2，界面显示“本地后端已就绪”；`app_bootstrap` 返回 schema 9、标准字号和预期日常目录。经正常退出流程返回退出码 0。
- 启动退出后再次核对：所有非设置表和结构未变化，其余应用偏好保持原值。正常启动沿用内置分发流程，新增 Nginx 已分发标记；除此以外没有其他设置键变化。

首次原生验证缺少开发模式 `devUrl` 的 Vite 服务；随后发现沙箱内服务无法被沙箱外原生进程访问。将临时 Vite 服务启动到同一本机环境后，完整验证通过，测试后已关闭服务。初轮页面就绪超时不计为通过。

## 排查后保留的能力

- OpenSSH 导入仍创建路径型私钥引用，SSH 认证实际读取该路径，因此保留这条功能链；源码中遗留的 legacy 命名不代表没有当前调用。
- 设置中的数据目录迁移是用户主动使用的功能，状态机还承担复制验证、未完成启动回退和源数据保护，不能按关键词删除。
- OpenAI compatible 是当前模型服务的协议适配；通用 AI 分析/逐条命令审核仍有当前公开 API/SDK 调用，与内置 SSH 智能体的严格工具协议分开。
- 取消、失败回滚、未知版本拒绝、主机指纹/权限/摘要/路径检查和操作审批都是当前安全边界。
- 为保持现有 schema 9 结构和原始数据，SQL 的 tags 列与历史附加表不自动删除；运行时代码不再读写 tags。没有清库、重置配置、删除旧目录或 OS 凭据。
