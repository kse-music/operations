# AI 运维助手

内置助手默认关联全部已登记主机，根据问题自动匹配并连接相关主机。从主机工作区进入时，入口主机作为“当前主机”和首次追问的匹配线索，仍可直接提问其他主机，无需切换分析模式。不同主机的提问草稿/对话分别保留，已发起的处理随主机工作区保留，切换页面、插件、设置或另一主机不会停止回答。已发出的外部请求可能产生费用。

## 后台处理与关闭主机（2026-11-05）

从主机工具打开的内置 AI 助手归属该主机工作区。只要主机标签仍打开，已经开始的匹配、连接、上下文准备、模型回答和工具查询可以在切页后继续；返回时显示已完成结果和仍有效的计划，保留原有超时、停止及模型/连接版本校验。全局搜索打开的助手归属自己的工作区标签，关闭该标签时停止。

关闭所属主机标签会撤销该页面的根请求、排队输入及计划，晚到结果不会恢复已关闭页面；其他主机的请求保留。用户点击“停止”、更改绑定模型、撤权、禁用、升级或退出应用仍会撤销相应工作。已批准并提交的远端变更按原规则安全收尾，停止后续操作，不能承诺回滚。

后台只续接已在可见页面开始的流程。隐藏页面不能发起新问题或新执行审批；需要变更时返回助手审核，已经确认的执行与复查可继续完成。上传插件及其他插件仍遵循隐藏时释放交互资源的规则。助手包版本为1.5.1。

入口：当前主机右上角 **AI 运维助手** 按钮；全局分析可通过全局搜索打开助手。配置统一从 **插件 → 插件管理 → AI 运维助手** 或功能页“插件设置”进入。内置助手现在通过 SSH 工具查询主机、生成计划，并在宿主确认后执行和复查；智能体运行于 ServerDeck，不需要在主机上安装常驻 Agent。

## SSH 智能体：查询、计划、确认、执行与复查（2026-11-05）

例如提问“查询当前主机的 Docker 镜像，删除 tag 为 `<none>` 的镜像，确认后执行并复查”。助手先查询真实镜像清单，再显示查询记录和执行计划，列出每个固定镜像 ID；此时没有发生删除。点击“审核执行计划”，在宿主的“确认 AI 运维计划”弹窗中核对主机与全部目标，输入本次计划的确认文字后执行，只需这一处变更确认。取消或不确认都不会执行。

| 能力           | 当前范围                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 自动只读查询   | Docker 镜像/容器/详情/资源，主机能力、负载/内存/磁盘、进程/详情、监听端口、systemd 列表/详情；仍可使用按问题采集的上下文  |
| 生成和执行计划 | 清理全部 tag 为 `<none>` 且没有其他标签的镜像；启动/停止/重启/删除已查询容器；启动/停止/重启/启用/禁用已查询 systemd 服务 |
| 结果复查       | 删除后确认目标消失；启动/停止读取实际状态；重启还核对启动时间变化；服务启停用核对 UnitFileState                           |

无标签清理从宿主保存的完整查询中筛选并按 ID 去重，同 ID 存在其他标签时不纳入；不把模型收到的摘要当作完整列表。超过 32 个操作会要求缩小范围，不会静默截短。执行只使用已批准 ID，不包含确认后新出现的镜像；每项执行前重查状态，删除命令还通过 SSH 再读 RepoTags，使用 `docker image rm --no-prune`，不强制删除、不删除卷或顺带清理父镜像。镜像被引用导致删除失败时不强制重试。Docker CLI 行为参考[镜像列表](https://docs.docker.com/reference/cli/docker/image/ls/)与[镜像删除](https://docs.docker.com/reference/cli/docker/image/rm/)。

计划十分钟有效、单次消费，绑定单台主机的 SSH 连接身份及模型版本。状态、连接、配置或绑定模型改变后需重新生成。发生失败或无法确认结果时停止后续操作，逐项展示“已执行并复查 / 失败 / 结果未确认 / 未执行”。执行中可停止后续操作；已提交的远端操作允许安全收尾，不能承诺撤销，界面保留未确认结果。执行结果在本地复查展示，不自动发送回模型。

每轮最多三个、最多十二次模型申请查询、六轮模型调用和 150 秒查询预算；计划准备还会读取目标详情。执行调度预算 100 秒，在途操作与复查按原有单次超时收尾。工具结果脱敏后按 20 条/8 KiB 摘要发送，明确总数和省略，实际请求仍受 96 KiB 限制；Token 累加全部轮次，任一轮缺失用量时不显示不完整合计。

目前自动操作限于明确的一台主机，多主机继续只分析；任意 Shell、脚本、提权、文件删除、按其他条件筛选镜像或指定镜像子集尚未作为智能体操作开放。无法表达的操作应要求补充或说明限制，不能改成范围更大的清理。模型不遵守智能体 JSON 协议时明确提示降回原有分析/受控命令建议。上传插件与旧原生 AI IPC 保持原有合同，不继承内置助手的工具循环权限。以下逐条命令说明适用于兼容路径。

## 配置与使用

1. 在 **资产管理 → 模型管理** 点击“注册模型”，填写便于识别的名称、OpenAI 兼容 API 的 Base URL、服务实际提供的模型 ID 和 API Key。地址包含服务要求的 `/v1`，应用追加 `/chat/completions`。点击“测试连接”，通过后才能保存；失败显示原因且不会创建模型。列表可查看、编辑和删除模型，名称不能重复，最多 100 个。
2. 每个模型的 Key 独立使用系统凭据库，SQLite 只保存随机引用。编辑时留空保留已有 Key，勾选清除可删除 Key；更换地址须重新输入或明确清除 Key，避免原 Key 被发送给新服务。凭据库不可用时拒绝秘密写入，不退化为明文。删除模型须单独确认，清理失败会明确提示并保留待清理记录。
3. 默认要求 HTTPS。局域网 HTTP 需显式勾选允许，Key 和上下文会明文传输。禁止 URL 用户密码、查询串、片段和重定向；不使用环境代理，不自动重试。
4. 输入/输出单价可分别填写，单位为 USD/百万 Token。留空显示费用未知，不内置可能过期的价格。
5. 在 **插件 → 插件管理 → AI 运维助手 → 绑定模型** 选择已注册模型，点击“保存模型绑定”；所有主机共用此绑定，无需再次填写地址或 Key。绑定保存于插件自己的配置，重启和插件升级后保留。聊天页不再显示模型选择、Key 状态、刷新或管理模型栏。未绑定、绑定模型已删除、缺少 Key 或配置读取失败时禁用发送并提示处理路径，不会自动改用其他模型。模型设置页提供“管理模型”和“刷新模型列表”。

原来的单模型配置自动事务转换为名为“默认模型”的注册项，保留原地址、模型参数和系统 Key 引用，不需要重新输入 Key。模型管理与助手共享当前运行内的列表；编辑/删除会更新列表并撤销该模型的预览、在途请求和未消费命令建议，修改插件模型绑定也会清空当前对话。预览及发送均绑定所选模型 ID/版本，其他模型不受影响。旧版本不识别新的模型列表，请避免同时用旧版界面修改 AI 配置。

模型绑定在设置主区域显示，运行状态、权限与插件信息放在辅助区域，窄窗口下配置优先排列。点击模型行的单选项选择，可同时查看名称、模型 ID 与 Key 是否配置；上方“当前绑定”始终显示已保存值，选择后点击“保存模型绑定”才生效。列表较长时可在候选区域滚动，底部保存操作保持可见；选择“未绑定模型”并保存可暂停助手。内置预置权限默认折叠，展开后仍可查看完整范围。

连接测试实际调用同一 Chat Completions 接口，固定发送 `ServerDeck connection test. Reply OK.`，最大输出 256 Token、`stream=false`、`store=false`，不含服务器数据或对话历史，也不提供工具。测试可能产生少量费用。只有 HTTP、认证及非空文本协议响应均有效且未返回工具调用才通过；测试回答不会渲染或成为命令建议。测试不写数据库或系统凭据库，待保存时才写 Key。

通过后返回后端生成的单次测试 ID，五分钟有效，绑定模型 ID/编辑版本、完整配置及 Key 的 SHA-256 摘要，仅保留在本次运行内存，最多 32 个；重启后失效。新增模型、编辑配置或替换 Key 时，后端也要求当前配置的测试结果，不能仅解除前端禁用绕过。改名称或只清除已有 Key 不要求重新连接。修改配置/Key、失败保存或过期后需重新测试；修改地址不会使用原 Key 进行测试，必须重新输入。测试使用与诊断请求相同的单并发、8 秒连接/60 秒总超时、重定向/代理/重试限制，退出会取消。关闭测试窗口会清空前端输入并忽略晚到结果，已发送的请求仍可能完成并计费。

使用 [OpenAI Chat Completions 协议](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，发送 `messages`、`max_completion_tokens`、`stream=false` 和 `store=false`。兼容服务须支持这些字段。当前仅实现 OpenAI 兼容适配器，`ModelProvider` 预留其他协议适配边界。

## 对话与发送

完成插件模型绑定后，聊天区输入问题后点击“发送”，或按 Enter；Shift + Enter 换行，输入法组词不会触发发送。系统分发的内置助手直接完成主机匹配与消息发送，不弹出外发确认或预览。宿主根据实际安装来源识别系统内置助手；上传插件即使使用同名或相同 ID，仍需原有外发审核。等待时可以“停止”，错误显示在对应消息中且不自动重试；“重新编辑”只恢复草稿。命令建议仍需独立审核，危险变更还需核对确认短语。

聊天区显示用户消息和 Markdown 回答，支持标题、粗体、列表、表格、引用和代码块。HTML 作为文字显示，不执行脚本；图片仅显示替代文字，不自动请求外部资源；链接只接受 HTTP(S)，其余协议无跳转。回答中的代码块不会自动变成执行请求。

连续追问携带当前会话最近六轮完整问题/回答，最多 48 KiB，仅有 user/assistant 两种历史角色；大回答截短后附省略标识。界面保留最多二十轮，旧轮移除时撤销其命令建议。失败和取消的轮次、原始服务器上下文、命令审批数据和执行输出不会自动带入历史。每次请求重新读取当前授权的上下文，并对问题、历史及上下文一起脱敏。

编辑草稿保留对话；点击“新对话”、更改模型绑定、模型版本变化、宿主上下文变化会清空当前会话并撤销旧建议/请求。所有资产属于同一会话，自动命中不同主机不会清空历史；回答按消息标注命中主机。对话只在当前页面内存保留，关闭页面即清空，不写数据库、备份、localStorage 或日志。当前回答完整返回后渲染，不提供流式输出。

## 自动关联与连接主机

助手默认关联资产管理中的全部主机，没有“当前服务器”选择框。进入页面只读取本地资产目录，不批量连接。每次发送重新加载资产，优先按问题中的名称、地址、端口、用户名或“继续/这台”等追问匹配；不能直接匹配时，调用所选模型从脱敏后的最小资产目录中返回已登记 ID。目录仅含 ID、名称、地址、端口、用户名和分组，不含密码、凭据引用、私钥路径或 SSH 高级配置。服务器日志与命令输出不参与路由。

仅连接命中主机，复用有效连接；使用资产已有认证配置与 SSH 主机密钥验证，不改变其他运维页面当前主机。首次连接仍需在聊天区内核对并信任真实指纹，完成后重新发送。任一命中主机连接失败，在消息中显示“命中主机「名称」（地址:端口）连接不上：原因”，不调用后续诊断模型或冒充成功。同名/同地址不明确时要求在问题中补充线索；资产列表问题与普通知识问题可不建立连接。

一次最多命中八台；每台连接等待最多 120 秒，按顺序连接，可停止。超过范围需缩小问题范围。多台命中后将已授权上下文按主机归属一起分析；多主机回答中的命令仅供人工审阅，没有应用内执行入口，避免命令被推测分配到某台服务器。单主机回答保留逐条命令审核。

语义匹配可能先产生一次额外模型请求，遵循相同单并发、超时、取消、脱敏和无工具规则；聊天消息的 Token 合计仅为后续分析响应的用量，不含匹配调用。停止会取消匹配请求、关闭本次新建的未完成连接，不关闭已有连接；关闭失败会明确提示。已连接成功的运维会话继续由现有连接管理维护。

## 授权上下文与脱敏

全资产目录用于主机匹配，诊断请求只附带命中主机的元数据。内置助手由宿主按当前问题选择以下来源，不会每轮读取全部数据。模糊追问沿用最近用户问题的领域；明确切换话题时重新选择。普通问候不采集远端运维数据，通用健康排查读取指标及进程摘要。领域识别使用本地规则，未识别的问题不会自动扩大到全量采集。

| 内置范围     | 实际来源与范围                                                                        |
| ------------ | ------------------------------------------------------------------------------------- |
| 服务器信息   | 已验证 SSH 端点；指标问题才附带固定采集器的系统信息                                   |
| 当前监控指标 | 在同一运维连接上临时采集两次，计算 CPU/网络速率；无需先启动监控，不创建后台监控任务   |
| 进程状态     | 固定 ps 查询，发送总数及 CPU 排名前列；不读取环境或完整启动参数                       |
| Docker 状态  | 固定本机 Docker socket 的容器列表；统计全部、运行中及各状态数量，有限容器明细         |
| systemd/端口 | 仅相关问题读取 system 作用域服务列表或监听端口；发送统计及有限明细                    |
| 系统日志     | 仅日志问题读取 journal 最近 100 行/最多 32 KiB，脱敏后外发末尾最多 4 KiB，不跟随/提权 |

列表明细最多 12 条且合计 4 KiB，每个长字段最多保留 256 字节并标注省略；统计基于完整成功查询。指标只发送聚合 CPU、前 8 项磁盘和网卡，省略数量单独标注。Docker 容器数不等于 Compose/Swarm 服务数。容器日志不自动猜测目标，缺少日志时提示到对应容器查看。

Docker、journal 或采样不可用时，模型收到明确的不可用标记/失败原因，聊天“上下文与响应提示”展示脱敏警告，不将失败当作数量为零。连接失效或资产身份变化仍拒绝发送。完整脱敏请求按实际 JSON 字节限制为 96 KiB；超预算先省略明细、保留各主机统计和失败，再按完整轮次移除最旧历史，并明确标注。必要内容仍超限时提示缩小问题/主机范围或新建对话。

IP、邮箱、常见密码/Token/API Key/Authorization/Cookie、JWT、私钥和带密码 URL 的自动脱敏固定开启，当前 API Key 始终移除。没有自定义脱敏输入框；自动脱敏仍可能遗漏业务敏感内容。数据先脱敏再截短，上下文及读取失败提示在外发和显示前均脱敏。上传插件及旧原生 IPC 保留原来的显式 selection 契约，本节按需采集和自动摘要仅适用于系统内置助手。

底层沿用匹配→连接→prepare→send：匹配冻结模型版本，准备阶段核验命中连接仍属于当前登记端点，并冻结模型 ID/版本、脱敏请求和全部实际连接；直接发送动作完成后半程，没有 UI 审批页面。每个准备快照五分钟有效且单次消费，版本或任一连接变化时拒绝发送；调用模型前仍从同一注册模型取凭据。取消准备阶段会拒绝晚到快照并停止后续模型发送，已开始的只读采集可能先完成；取消模型请求不保证服务端停止处理。

聊天消息显示模型实际返回的 Token 合计，缺失时不伪造。后端保留 Token/费用估算契约，聊天区不展示费用审批。

## 兼容路径：逐条命令审核与执行

智能体计划对同一目标只允许一项操作；重启使用 restart，不接受先 stop 再 start 的同目标链，避免前置状态变化后只执行了停机步骤。

分析通过受限 Markdown 节点渲染，命令作为文本展示；不执行 HTML，不解释远程数据中的角色、权限或工具指令。模型返回 `tool_calls`/`function_call` 会整体拒绝；格式错误、截断或超过 8 条命令时仅显示文本，不开放执行。

后端按固定规则决定执行范围，不采信模型的风险分类：

| 类型     | 允许范围                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 只读诊断 | `uptime`、`free -m`、`df -h`、`ps -eo pid=,user=,pcpu=,pmem=,etimes=,comm= --sort=-pcpu`、`docker ps -a --no-trunc`、`ss -lntup` |
| 系统变更 | `systemctl start/stop/restart NAME.service`、`docker start/stop/restart 完整64位容器ID`                                          |
| 人工审阅 | 所有其他命令、Shell 拼接/重定向/替换、多行命令，以及没有关联服务器的建议                                                         |

每条可执行建议显示固定目标和命令，点击“审核此命令”后须再次勾选批准。变更还须手动输入该命令对应的完整确认语句。每次只处理一条，无“全部执行”、自动批处理、提权或重试。

执行由后端将保存的建议 ID 映射到既有类型化操作，使用固定环境、Docker 本机 socket、参数校验及 Shell 单引号转义，模型原文不作为任意 Shell 运行。前端不能通过执行请求替换命令。建议绑定原 Session、Transport 和连接签名，10 分钟有效、消费后不可重放。断线/退出/30 秒执行超时复用运维取消机制；变更超时后的真实状态需人工核实。

结果在本地展示且再次脱敏，不自动回传模型。未知命令仅供人工审阅，没有应用内执行入口。

## 隔离、限制与验证

模型列表独立存于已有 `application_settings` 表的 `ai_models` 行（格式版本 1）。首次访问时原 `ai_config` 在事务中转换，成功后移除旧行；转换失败保留原数据并报错。不改变 AppConfig、数据库版本或启动依赖，模型列表和 Key 不进入配置备份。网络、认证、额度、格式、凭据库或 AI 配置故障只影响 AI；日志仅记录错误类别/HTTP 状态，不记录载荷。其他运维功能继续使用原流程。

单次模型请求上限 60 秒、响应上限 256 KiB、并发 1；内部准备快照最多 8 个、可执行建议最多 64 个、待确认智能体计划最多 8 个，过期后拒绝使用。内置智能体使用上述有界工具循环，当前不提供流式回答、持久对话或其他协议适配器。JavaScript 临时输入无法保证物理清零，保存完成或关闭表单会清空 Key 字段。

当前自动匹配验证见 [VALIDATION_ASSISTANT_HOSTS.md](../validation/ai/VALIDATION_ASSISTANT_HOSTS.md)，对话及原始能力记录保留于 [VALIDATION_ASSISTANT_CHAT.md](../validation/ai/VALIDATION_ASSISTANT_CHAT.md)、[VALIDATION_AI_ASSISTANT.md](../validation/ai/VALIDATION_AI_ASSISTANT.md)。`node tools/native-ai-e2e.mjs` 验证隔离 Windows 应用、真实 IPC/OS 凭据、本机 HTTP 与测试资产连接失败，不连接用户服务器。`ai_live_probe` 示例从 stdin 临时接收 Key，以真实模型检查无服务器上下文的预览/发送链路，完成后清理临时 OS 凭据。
