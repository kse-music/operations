# Docker 管理

独立 UI v4 标准插件包。界面、交互业务与前端测试在 `frontend/`，WASM 能力策略与 Rust 测试在 `backend/`；分别只引用公开 `@serverdeck/plugin-sdk` 和 `serverdeck-plugin-sdk`，普通 Vue/测试依赖按工作区管理。宿主通过相同沙箱、SDK、WASM 和授权机制加载内置与上传包。

镜像页顶部「导入镜像」选择本机 `docker save` 归档，通过登录身份 SFTP 上传、校验后执行 `docker image load`；同名标签可能替换，不更新已有容器。行内「导出」选择本机目录与 `.tar` 文件名，核对完整 ID 后按所选标签执行 `docker image save`，无标签按 ID 导出，校验后下载，不覆盖本机已有文件。文件选择、下载及传输预授权使用 SDK 5.6.0 通用能力，需要 `sftp.read/write/transfer` 及独立的 `sftp.transfer.preapproved`；上传安装需另行授予预授权与 `/tmp` 文件范围。点击导入/导出后直接执行，传输准备、启动及长命令均不再逐次弹窗确认。界面以 MB 显示已传/总量、以 MB/s 显示速度（十进制，两位小数），保留任务输出与取消，成功导入刷新列表。`load/save` 使用可取消长命令流，不受单次 Execute 的 30 秒限制。

归档只在当前主机私有 `/tmp/serverdeck-image-<nonce>/` 暂存，不经 JS/WASM 传输字节。关闭先排空传输再结束命令流，脚本仅清理已知文件和空目录；取消不回滚已加载镜像。断线、权限撤销、异常退出可能保留暂存，失败显示路径，核对任务结束后手动清理，不自动递归删除。需要 Linux 远端 Shell、Docker CLI、SFTP、可写且非链接的 `/tmp` 及足够空间，不安装工具或提权。标签与完整 ID 的复核不能提供 Docker daemon 的原子标签锁，外部并发改标签仍有竞态。

清单预授权版本检测、容器列表、镜像列表、容器详情、环境变量、资源使用、Compose 项目列表、服务快照、启动配置及 Compose 配置隐藏/显式变量十一条完整固定查询，进入、刷新、打开启动配置或环境变量标签无需逐次命令确认。详情与资源使用读取当前主机快照，再按完整容器 ID 筛选；概览不读取环境变量，环境变量快照仅在打开环境变量或启动配置标签时查询，前端只收到当前容器的数据，切换或关闭时清除明文。查询仍受平台输出和超时限制，容器数量或详情过大时会明确失败。内置包预置独立 `ssh.execute.preapproved` 授权；作为上传包安装时需在权限页核对命令后单独授予。

容器详情为「概览、资源使用、启动配置、环境变量」。端口映射和挂载通过启动配置中的只读 Compose YAML 展示：Compose 来源读取当前项目文件的完整 service 及其引用的顶层定义；普通容器根据 inspect 转换，未支持的有效设置明确提示，已存在的卷和网络保留 external 引用。Compose 配置由两条固定预授权脚本读取，按项目去重并复验成员的原始目录和有序文件；失败可显式改用容器信息转换。先检测 Compose 选项，旧版不使用不支持的 `--no-env-resolution`，启动配置按当前项目环境解析 env_file 与变量表达式。单个项目失败不会阻断当前其他项目，参数逐项传递，未扩展宿主匹配或变更权限。当前文件可能与创建时不同，转换结果不能保证完整复现历史启动参数或独立部署；不提供配置编辑或执行。启动配置进入即直接显示环境变量值，不提供查看/隐藏按钮，切换或关闭清除明文及迟到响应；容器详情标题、关闭按钮和分类标签固定，只有下方内容滚动，切换标签重置滚动位置；内联 secrets/configs 内容始终隐藏，不读取它们引用的文件。

日志和 Shell 直接打开，使用独立 `ssh.interactive.preapproved` 权限；上传安装仍需用户单独授予，该能力允许当前安装版本直接启动任意远程流/终端命令。Shell 默认 `/bin/sh`。容器启动、停止、删除及镜像删除仅保留宿主一次确认，无需输入目标 ID。标题明确操作，正文显示容器/镜像名称、短 ID、实际 SSH 主机及服务中断/数据丢失影响，按钮直接标注“启动”“停止”或“删除”；不提供“执行详情”或命令脚本入口，完整命令仍由原生审批绑定。取消不执行命令；删除仍不强制、不删除卷。其他未声明命令继续审批，宿主没有 Docker 专用匹配规则。

「Compose 项目」标签通过远端 `docker compose ls --all --format json` 发现已有项目，查看包含已停止容器的服务状态、镜像及退出码，打开带服务前缀的项目日志，并确认整组启动、停止或重启。启动仅启动已有容器，不拉取镜像、创建或重建服务；不编辑配置、不删除项目或数据卷。一次性运行容器不参与服务详情和执行配置选择，全部容器已删除的项目不可发现。

变更和日志在执行前绑定 SSH 配置修订，从真实容器标签重新读取原始工作目录及有序配置文件，不接受前端传入路径；各路径逐项引用，目录或配置元数据缺失、相互冲突或不是绝对路径时明确拒绝。启用全部 profiles，使已创建的 profile 服务也参与整组操作。命令仍依赖远端原始配置和环境；配置文件名包含逗号时不支持恢复；不保证恢复自定义 `--env-file` 等全部历史启动参数，文件缺失或变量无法解析时如实失败。命令超时可能部分完成，须刷新核对，不自动重放。切换容器/镜像/Compose 标签或隐藏页面会关闭自有日志流，迟到的日志打开结果也会释放。

Shell 弹窗展示容器名称、短 ID 和 `/bin/sh`，宿主单独显示真实 SSH 地址与连接状态。默认窗口增大，可最大化/还原；工具栏提供查找、字号调整/重置和本地清屏，支持右键复制粘贴及 Ctrl+滚轮缩放，查找框按 Esc 关闭。所有显示操作保持同一 PTY；清屏不向远端发送 `clear` 或停止进程。断线/失败保留输出和原因，从原 Shell 入口重新打开，不重放一次性票据。容器上下文经公开 SDK 可选纯文本 `presentation` 传入，只用于呈现，不改变授权或实际目标。

日志弹窗固定标题和工具栏，只在日志区滚动，默认显示并自动跟随最新输出；向上翻阅时停止自动滚动，新日志继续接收，点击“最新日志”恢复跟随。暂停期间保持阅读位置，继续后回到末尾。过滤条件切换、无匹配或不足一屏、窗口尺寸与字号变化均保持原跟随/历史模式，自动重排不当作用户翻阅；跟随模式仍定位末尾，真实滚轮、滚动条和键盘滚动继续生效；保留纯文本过滤、复制、导出和原有缓存限额，无匹配内容明确提示。

“Docker信息”入口和同名弹窗展示安装/运行状态、Docker 服务端版本、客户端版本、运行平台及操作系统名称。操作系统由版本固定查询附带读取 `docker info --format '{{json .OperatingSystem}}'`，只返回该字段，不读取完整 info；读取失败保留诊断并显示“不可用”。运行平台仍为服务端 OS/架构，不使用客户端或桌面本机系统代替。三个标签页的搜索框约 320px 宽，刷新按钮统一为“刷新”。

容器列表工具栏提供「清空容器日志」「重启已退出容器」。操作针对当前 SSH 主机，不受搜索筛选影响，宿主确认后才在远端查询本次目标；已退出重启使用精确的 `status=exited` 筛选。容器行内提供「重启」，复用完整 ID 校验与宿主一次确认，已停止容器会被启动。批量重启按实际返回的 ID 统计成功和失败；日志逐个核对清理。返回匹配、成功、失败和跳过数量，空目标不执行变更，失败不伪装成功，超时可能部分完成，须刷新核对后再决定是否重试。批量操作沿用平台单次 30 秒限额。

日志清理从当前 Docker daemon 读取数据目录，并逐容器核对 `json-file` 驱动、实际 `LogPath` 与标准 `<DockerRootDir>/containers/<ID>/<ID>-json.log` 路径。只截断已存在的普通当前日志，拒绝数据目录/容器目录/日志文件本身的符号链接及路径不一致；不扫描任意目录、不创建缺失日志、不删除容器或轮转日志。其他驱动跳过；文件权限不足、容器消失或清理失败如实显示。需要远端 `truncate` 和当前 SSH 账号的文件写权限，不自动提权；清空的内容不可恢复。

验证：`npm run test -w @serverdeck/desktop -- ../../plugins/system/docker/frontend`；原生单测用 `cargo test --manifest-path plugins/system/docker/backend/Cargo.toml --target-dir target --offline --locked --no-run` 编译，将生成的测试 EXE 复制到 QA 目录再运行。构建会同时打包 WASM、UI 声明和独立 JS/CSS，完整契约见 [开发指南](../../../docs/plugins/PLUGIN_DEVELOPMENT.md)。

WSL Shell 回归：对复制后的测试 EXE 执行 `--ignored --nocapture`。此用例只执行生产命令体与隔离的 Docker Shell 夹具，验证选择、计数、空列表、查询失败、异常 ID、非默认且带空格的数据目录、符号链接、路径越界、轮转文件保留及写入失败，不连接真实 Docker daemon。

构建：`node tools/build-plugin.mjs plugins/system/docker OUTPUT.sdplugin`。

该包可像用户上传的插件一样安装、授权、启停、升级及卸载；系统来源只由应用的首次分发记录设置。
