# Docker 管理

独立 UI v4 标准插件包。界面、交互业务与前端测试在 `frontend/`，WASM 能力策略与 Rust 测试在 `backend/`；分别只引用公开 `@serverdeck/plugin-sdk` 和 `serverdeck-plugin-sdk`，普通 Vue/测试依赖按工作区管理。宿主通过相同沙箱、SDK、WASM 和授权机制加载内置与上传包。

镜像行内「远程传输」从已保存主机中单选其它目标，先读取目标镜像快照，指向不同 ID 的同名标签需明确确认替换。源归档就绪后通过通用 remote 文件传输经本机中转，SHA-256 校验后目标自动 load 并核对平台、配置及有序文件层的内容摘要，不更新或重启已有容器。只保留所选标签，无标签按 ID 传输；导入前标签快照变化时拒绝继续。两端需要 Docker、SFTP 与暂存空间，本机不保存完整归档，但承担中转带宽。进度区分打包、中转、校验、加载与两端清理；取消先排空传输再停止两端归档流，错误保留两端主机及恢复目录，不自动重试或回滚已加载镜像。跨 Docker 存储实现的显示 ID 不作相等要求；空默认配置字段统一省略，当前内容核对以 inspect 默认平台为准。无标签接收从本次 load 输出解析目标实际 ID。失败详情仅发到全局通知，弹窗保留失败状态并展开完整任务输出。

镜像页顶部「导入镜像」选择本机 `docker save` 归档，通过登录身份 SFTP 上传、校验后执行 `docker image load`；同名标签可能替换，不更新已有容器。行内「导出」选择本机目录与 `.tar` 文件名，核对完整 ID 后按所选标签执行 `docker image save`，无标签按 ID 导出，校验后下载，不覆盖本机已有文件。文件选择、下载及传输预授权使用 SDK 5.6.0 通用能力，需要 `sftp.read/write/transfer` 及独立的 `sftp.transfer.preapproved`；上传安装需另行授予预授权与 `/tmp` 文件范围。点击导入/导出后直接执行，传输准备、启动及长命令均不再逐次弹窗确认。界面以 MB 显示已传/总量、以 MB/s 显示速度（十进制，两位小数），保留任务输出与取消，成功导入刷新列表。字节传满后进入「校验并提交」，不再显示 MB/s；原生 completed 仍须带 SHA-256 和完整字节数，导入再进入 Docker 加载，最后等待暂存清理再显示整体成功。校验阶段通过 SFTP 回读远端文件，大文件的等待不计入复制进度，不能把 100% 字节数视为导入/导出完成。`load/save` 使用可取消长命令流，不受单次 Execute 的 30 秒限制。

归档只在参与操作的主机私有 `/tmp/serverdeck-image-<nonce>/` 暂存，远程传输在来源与目标两端暂存，不经 JS/WASM 传输字节。关闭先排空传输再结束命令流，脚本仅清理已知文件和空目录；取消不回滚已加载镜像。断线、权限撤销、异常退出可能保留暂存，失败显示路径，核对任务结束后手动清理，不自动递归删除。需要 Linux 远端 Shell、Docker CLI、SFTP、可写且非链接的 `/tmp` 及足够空间，不安装工具或提权。标签与完整 ID 的复核不能提供 Docker daemon 的原子标签锁，外部并发改标签仍有竞态。

清单预授权版本检测、容器列表、镜像列表、容器详情、环境变量、资源使用、Compose 项目列表、服务快照、启动配置及 Compose 配置隐藏/显式变量十一条完整固定查询，进入、刷新、打开启动配置或环境变量标签无需逐次命令确认。详情与资源使用读取当前主机快照，再按完整容器 ID 筛选；概览不读取环境变量，环境变量快照仅在打开环境变量或启动配置标签时查询，前端只收到当前容器的数据，切换或关闭时清除明文。查询仍受平台输出和超时限制，容器数量或详情过大时会明确失败。内置包预置独立 `ssh.execute.preapproved` 授权；作为上传包安装时需在权限页核对命令后单独授予。

容器详情为「概览、资源使用、启动配置、环境变量」。端口映射和挂载通过启动配置中的只读 Compose YAML 展示：Compose 来源读取当前项目文件的完整 service 及其引用的顶层定义；普通容器根据 inspect 转换，未支持的有效设置明确提示，已存在的卷和网络保留 external 引用。Compose 配置由两条固定预授权脚本读取，按项目去重并复验成员的原始目录和有序文件；失败可显式改用容器信息转换。先检测 Compose 选项，旧版不使用不支持的 `--no-env-resolution`，启动配置按当前项目环境解析 env_file 与变量表达式。单个项目失败不会阻断当前其他项目，参数逐项传递，未扩展宿主匹配或变更权限。当前文件可能与创建时不同，转换结果不能保证完整复现历史启动参数或独立部署；不提供配置编辑或执行。启动配置进入即直接显示环境变量值，不提供查看/隐藏按钮，切换或关闭清除明文及迟到响应；容器详情标题、关闭按钮和分类标签固定，只有下方内容滚动，切换标签重置滚动位置；内联 secrets/configs 内容始终隐藏，不读取它们引用的文件。

日志和 Shell 直接打开，使用独立 `ssh.interactive.preapproved` 权限；上传安装仍需用户单独授予，该能力允许当前安装版本直接启动任意远程流/终端命令。Shell 默认 `/bin/sh`。容器启动、停止、删除及镜像删除仅保留宿主一次确认，无需输入目标 ID。标题明确操作，正文显示容器/镜像名称、短 ID、实际 SSH 主机及服务中断/数据丢失影响，按钮直接标注“启动”“停止”或“删除”；不提供“执行详情”或命令脚本入口，完整命令仍由原生审批绑定。取消不执行命令；删除仍不强制、不删除卷。其他未声明命令继续审批，宿主没有 Docker 专用匹配规则。

「Compose 项目」标签通过远端 `docker compose ls --all --format json` 发现已有项目，查看包含已停止容器的服务状态、镜像及退出码，打开带服务前缀的项目日志，并确认整组启动、停止或重启。启动仅启动已有容器，不拉取镜像、创建或重建服务；不编辑配置、不删除项目或数据卷。一次性运行容器不参与服务详情和执行配置选择，全部容器已删除的项目不可发现。

变更和日志在执行前绑定 SSH 配置修订，从真实容器标签重新读取原始工作目录及有序配置文件，不接受前端传入路径；各路径逐项引用，目录或配置元数据缺失、相互冲突或不是绝对路径时明确拒绝。启用全部 profiles，使已创建的 profile 服务也参与整组操作。命令仍依赖远端原始配置和环境；配置文件名包含逗号时不支持恢复；不保证恢复自定义 `--env-file` 等全部历史启动参数，文件缺失或变量无法解析时如实失败。命令超时可能部分完成，须刷新核对，不自动重放。切换容器/镜像/Compose 标签或隐藏页面会关闭自有日志流，迟到的日志打开结果也会释放。

Shell 弹窗展示容器名称、短 ID 和 `/bin/sh`，宿主单独显示真实 SSH 地址与连接状态。默认窗口增大，可最大化/还原；工具栏提供查找、字号调整/重置和本地清屏，支持右键复制粘贴及 Ctrl+滚轮缩放，查找框按 Esc 关闭。所有显示操作保持同一 PTY；清屏不向远端发送 `clear` 或停止进程。断线/失败保留输出和原因，从原 Shell 入口重新打开，不重放一次性票据。容器上下文经公开 SDK 可选纯文本 `presentation` 传入，只用于呈现，不改变授权或实际目标。

日志弹窗固定标题和工具栏，只在日志区滚动，默认显示并自动跟随最新输出；工具栏「清屏」只清空本窗口已接收内容的本地缓存并恢复跟随，后续收到的日志继续追加；保留过滤条件和暂停/错误状态，不重启日志流或清理 Docker 日志。复制和导出使用清屏后剩余的可见内容。向上翻阅时停止自动滚动，新日志继续接收，点击“最新日志”恢复跟随。暂停期间保持阅读位置，继续后回到末尾。过滤条件切换、无匹配或不足一屏、窗口尺寸与字号变化均保持原跟随/历史模式，自动重排不当作用户翻阅；跟随模式仍定位末尾，真实滚轮、滚动条和键盘滚动继续生效；保留纯文本过滤、复制、导出和原有缓存限额，无匹配内容明确提示。

三个标签页上方共用 Docker 服务端版本、本地镜像数、运行容器数和 Compose 配置数，不提供独立“Docker信息”弹窗。同一主机连接内缓存成功统计和已访问列表，切回页面不清空重读；未完成或失败的读取按需补齐，主机或连接变化清除缓存。刷新、变更成功和镜像传输完成后更新当前列表与统计，并使其他缓存页签在再次显示时重读。刷新期间保留旧值，失败明确提示；外部变更需手动刷新。三个标签页的搜索框约 320px 宽，刷新按钮统一为“刷新”。

容器列表工具栏提供「重启已退出容器」。操作针对当前 SSH 主机，不受搜索筛选影响，宿主确认后才在远端查询本次目标；已退出重启使用精确的 `status=exited` 筛选。容器行内提供「重启」，复用完整 ID 校验与宿主一次确认，已停止容器会被启动。批量重启按实际返回的 ID 统计成功和失败。返回匹配、成功、失败和跳过数量，空目标不执行变更，失败不伪装成功，超时可能部分完成，须刷新核对后再决定是否重试。批量操作沿用平台单次 30 秒限额。

容器与 Compose 日志通过独立 SSH 流执行。关闭、隐藏日志窗口或关闭插件页面时先停止流；主动断开 SSH 先排空对应日志，再释放连接；正常退出应用先排空插件和日志，再关闭 SSH。停止流时，即使正在暂停或等待 ACK，也向远端发送 TERM 和 stdin EOF，并等待退出确认，2 秒未确认则发送 KILL，再等待 1 秒；消费者异常也执行同样清理。未确认退出时明确报告，不能把关闭通道当作进程已结束。日志关闭不影响共享 SSH 的其它窗口。容器和 Compose 日志另有远端监督 Shell：stdin EOF 或 HUP/TERM 触发清理，由 GNU coreutils `timeout --kill-after=1s 10m` 管理本次日志进程组；SSH 服务端忽略 signal 请求时仍能通过 EOF 结束。需要远端已安装 GNU timeout，不自动安装或退回无监督命令；每次查看最多 10 分钟，标题显示时限，结束后从日志入口重新打开。网络硬中断、服务端拒绝信号或应用被强杀无法保证远端即时结束，须在恢复连接后核对；本功能不修复 Docker daemon 内部已发生的日志扫描故障。

验证：`npm run test -w @serverdeck/desktop -- ../../plugins/system/docker/frontend`；原生单测用 `cargo test --manifest-path plugins/system/docker/backend/Cargo.toml --target-dir target --offline --locked --no-run` 编译，将生成的测试 EXE 复制到 QA 目录再运行。构建会同时打包 WASM、UI 声明和独立 JS/CSS，完整契约见 [开发指南](../../../docs/plugins/PLUGIN_DEVELOPMENT.md)。

WSL Shell 回归：对复制后的测试 EXE 执行 `--ignored --nocapture`。此用例只执行生产命令体与隔离的 Docker Shell 夹具，验证 exited 选择、计数、空列表、查询失败和异常 ID，不连接真实 Docker daemon。原生日志生命周期实测使用 `tools/docker-logs-fixture.py` 创建本机隔离 OpenSSH/Compose 夹具，再运行 Application 中的 opt-in `real_docker_logs_exit_on_dialog_hidden_scope_ssh_disconnect_and_app_shutdown`；只使用本机已有镜像，验证容器/Compose 输出及关闭、隐藏、页面关闭、SSH 会话/主机断开、应用退出后远端日志客户端进程数为零，结束后清理本次夹具。

构建：`node tools/build-plugin.mjs plugins/system/docker OUTPUT.sdplugin`。

该包可像用户上传的插件一样安装、授权、启停、升级及卸载；系统来源只由应用的首次分发记录设置。
