# Docker 管理

独立 UI v4 标准插件包。界面、交互业务与前端测试在 `frontend/`，WASM 能力策略与 Rust 测试在 `backend/`；分别只引用公开 `@serverdeck/plugin-sdk` 和 `serverdeck-plugin-sdk`，普通 Vue/测试依赖按工作区管理。宿主通过相同沙箱、SDK、WASM 和授权机制加载内置与上传包。

清单预授权版本检测、容器列表、镜像列表、容器详情、环境变量、资源使用、Compose 项目列表和服务快照八条完整固定查询，进入、刷新及查看详情无需逐次确认。详情与资源使用读取当前主机快照，再按完整容器 ID 筛选；概览不读取环境变量，环境变量快照仅在打开对应标签时查询，前端只收到当前容器的数据，切换或关闭时清除明文。查询仍受平台输出和超时限制，容器数量或详情过大时会明确失败。内置包预置独立 `ssh.execute.preapproved` 授权；作为上传包安装时需在权限页核对命令后单独授予。

日志和 Shell 直接打开，使用独立 `ssh.interactive.preapproved` 权限；上传安装仍需用户单独授予，该能力允许当前安装版本直接启动任意远程流/终端命令。Shell 默认 `/bin/sh`。容器启动、停止、删除及镜像删除仅保留宿主一次确认，无需输入目标 ID。标题明确操作，正文显示容器/镜像名称、短 ID、实际 SSH 主机及服务中断/数据丢失影响，按钮直接标注“启动”“停止”或“删除”；不提供“执行详情”或命令脚本入口，完整命令仍由原生审批绑定。取消不执行命令；删除仍不强制、不删除卷。其他未声明命令继续审批，宿主没有 Docker 专用匹配规则。

2.1.0 新增「Compose 项目」标签：通过远端 `docker compose ls --all --format json` 发现已有项目，查看包含已停止容器的服务状态、镜像及退出码，打开带服务前缀的项目日志，并确认整组启动、停止或重启。启动仅启动已有容器，不拉取镜像、创建或重建服务；不编辑配置、不删除项目或数据卷。一次性运行容器不参与服务详情和执行配置选择，全部容器已删除的项目不可发现。

变更和日志在执行前绑定 SSH 配置修订，从真实容器标签重新读取原始工作目录及有序配置文件，不接受前端传入路径；各路径逐项引用，目录或配置元数据缺失、相互冲突或不是绝对路径时明确拒绝。启用全部 profiles，使已创建的 profile 服务也参与整组操作。命令仍依赖远端原始配置和环境；配置文件名包含逗号时不支持恢复；不保证恢复自定义 `--env-file` 等全部历史启动参数，文件缺失或变量无法解析时如实失败。命令超时可能部分完成，须刷新核对，不自动重放。切换容器/镜像/Compose 标签或隐藏页面会关闭自有日志流，迟到的日志打开结果也会释放。

版本弹窗按核心字段展示安装/运行状态、Docker 服务端版本、客户端版本和服务端 OS/架构；不渲染原始版本对象或额外组件信息。服务端信息缺失显示“不可用”，不以客户端值代替。

验证：`npm run test -w @serverdeck/desktop -- ../../plugins/system/docker/frontend`；原生单测用 `cargo test --manifest-path plugins/system/docker/backend/Cargo.toml --target-dir target --offline --locked --no-run` 编译，将生成的测试 EXE 复制到 QA 目录再运行。构建会同时打包 WASM、UI 声明和独立 JS/CSS，完整契约见 [开发指南](../../../docs/plugins/PLUGIN_DEVELOPMENT.md)。

构建：`node tools/build-plugin.mjs plugins/system/docker OUTPUT.sdplugin`。

该包可像用户上传的插件一样安装、授权、启停、升级及卸载；系统来源只由应用的首次分发记录设置。
