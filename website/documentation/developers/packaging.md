# 打包与安装

## 生成标准包

在独立开发包中执行 `npm run package`，工具按锁定 / 离线要求编译前端和 WASM，再生成标准 `.sdplugin`。

`.sdplugin` 是带严格载荷和摘要清单的 UTF-8 JSON，不是 ZIP。不要手工拼接绕过路径、大小或摘要检查。后端入口、UI 声明和前端单文件资源都必须包含在合法载荷中。

包结构、字段和限制见[插件包格式](/developers/reference/package-format.html)。

输出文件必须不存在。需要再次构建时先移动旧产物，或指定新文件名，例如在开发包根目录运行 `node tools/build-plugin.mjs ./example ./example-candidate.sdplugin`，不要通过覆盖输出掩盖候选包差异。

## 核对身份与兼容范围

使用自己的反向域名 ID、明确名称、作者与业务版本。`apiVersion` 声明实际使用的 Host API 范围；UI、WASM ABI 和包格式分别遵循当前契约。

更新包提高插件自身版本，不能只重打包同版本期待客户端自动替换。SDK 版本与插件业务版本不要混为一谈，详见[版本与兼容性](/developers/reference/versions.html)。

## 在客户端安装候选包

1. 打开插件管理，上传本次构建的候选文件。
2. 检查身份自述、版本、来源和权限，再确认安装。
3. 按需要启用并授权，从真实贡献入口进入页面。
4. 验证正常、失败、取消与撤权，核对服务器上的实际结果。
5. 验证升级、回滚与卸载后，资源是否正确收尾，配置是否按契约保留。

::: warning 摘要不是发布者签名
当前包没有密码学签名验证。作者、publisher 与 SHA-256 不能单独证明可信身份。分发时明确来源与适用版本，使用者仍需审核权限。
:::

## 当前分发边界

当前支持本地包的安装和管理，尚无在线市场、订单、付费授权或远程自动下载安装接口。不要在插件中假设付款、联网或相同作者会带来任何宿主特权。

内置插件随客户端构建和分发，第三方包通过本地安装进入应用数据目录，不能靠添加宿主私有注册表或复制安装目录取得系统来源。
