# 权限与审批

## 声明实际需要的能力

先列出业务需要的 UI、SSH、文件或模型原语，再在 manifest 中声明相应权限和 operation。未知业务权限会拒绝，不能通过名称自述新增宿主能力。

具体权限名、请求参数与资源限额以 [SDK 参考](/developers/reference/sdk.html)为准。插件只调用本包声明动作，不能任意转发原生 IPC。

## 安装、授权和执行是不同步骤

上传包默认禁用且未授权。用户需要分别核对来源、启用和授予能力。权限绑定当前安装修订，相同 ID、作者或旧包不能自动继承执行权。

一次执行确认绑定完整请求、实际目标和生命周期。业务说明可以帮助用户理解影响，但不能替代真实目标、命令和修订的原生核验。

::: warning 不要把“读取”当成自动可信
固定命令、交互命令、任务读取和传输预授权分别声明与授予。命令自称只读、字段自称 confirmed 或当前模式更宽，都不能增加基础权限。
:::

## 选择预授权方式

固定后台查询先在 manifest 的 `preapprovedCommands` 声明完整 Command，并声明 `ssh.execute`、`ssh.execute.preapproved`；用户审核后单独授予权限和 operation，才对程序、参数及超时完全匹配的 Execute 免除逐次确认。普通固定清单最多 16 项、合计 JSON ≤48 KiB，不允许用动态通配符绕过审核。

需要直接启动流或终端时，另行声明并获得 `ssh.interactive.preapproved`，基础 `ssh.execute` 仍须授权。它允许当前安装修订启动任意交互命令，不能当作只读权限，也不能代替 Execute、文件写入或本机 TCP 连接的确认。

需要带参数的任务读取时，单独声明并授权受限 argv 模板。完全访问还需要可信宿主首次授权，限于已有能力和目录；切换回 request / assist、新对话或关闭 owner 时撤销，隐藏页面不能代替结束会话。上传包不默认获得这些能力。精确模板、任务模式与失效规则以 [SDK 审批契约](/developers/reference/sdk.html#审批模式与计划确认)为准。

## 审批之后仍有校验

首次主机指纹、真实账户权限、授权目录和目标 / 原文复验始终保留。插件文件原语使用主机 SSH 登录身份，不继承文件页手动 sudo 切换的身份或密码。

授权失败、目标变更、取消或断线要保留真实状态。取消不保证远端动作从未发生，不能把没有完整确认的结果写成成功。

## 保护数据和秘密

密码、私钥、模型 Key 与内部租约不进入插件公开资产 DTO。调用模型需要明确授权，插件负责业务上下文选择、脱敏与用户可读说明。

禁止把秘密、完整敏感载荷或凭据写入日志。插件包当前没有密码学签名验证，发布者信息和摘要不能证明身份。[完整安全契约](/developers/reference/security.html)是开发与审查依据。
