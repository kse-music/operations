# 调试与测试

## 先验证开发包自身

在独立开发包根目录运行公开检查入口：

```sh
npm run typecheck
npm test
npm run package
```

先修复类型、锁文件和打包问题，再在隔离应用数据目录中安装。缺少公开依赖时按[准备步骤](/developers/quickstart.html)预取，不修改版本或跳过校验来绕过失败。

## 覆盖真正的行为

| 场景                 | 需要检查的结果                     |
| -------------------- | ---------------------------------- |
| 正常读取             | 显示真实数据、来源和适用主机       |
| 成功空结果           | 正常空状态，不与读取失败混淆       |
| 非法参数或无权限     | 在实际边界拒绝，不执行副作用       |
| 超时、断线、输出截断 | 呈现原始失败或未确认状态           |
| 取消和关闭页面       | 排空与清理所属资源，保留已完成项   |
| 撤权、升级或模型修订 | 旧句柄、预览与授权失效             |
| 重复点击或重试       | 不重放一次性授权，不重复已提交操作 |

涉及变更时检查真实对象和实际结果，不能只看命令退出码或页面出现成功文案。

## 使用可控环境

协议和故障注入可使用本地夹具，但夹具通过不能代替真实 SSH、模型账号、远端工具版本和原生平台验收。远程测试只使用已经明确授权的测试主机和资源。

调试期间保留安全错误码与原因链，按需要提供去敏日志。不要记录密码、私钥、模型 Key 或完整业务正文。

## 交付前检查

用新目录解压开发包并执行准备、构建；上传同一个候选 `.sdplugin`，核对版本、声明权限、页面入口、真实失败与取消。多平台声明需要分别验证，不能由 manifest 的平台数组推断已经支持。

原生 Rust 测试复用既有构建目录，Windows 测试 EXE 复制到隔离 QA 目录运行，避免锁定构建输出。更多边界见[源码与构建契约](/developers/reference/development.html)。
