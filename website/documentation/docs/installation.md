# 安装与升级

## 安装前准备

Windows 安装包按当前用户安装，需要 WebView2。安装器名称中的版本以实际发布产物为准，安装包与校验文件由发布渠道提供，不随源码仓库分发。核对可信来源、发布者签名状态及 SHA-256；摘要不能代替身份验证。macOS/Linux 客户端须分别完成验收后再发布。

1. 打开[官网下载入口](/#download)，点击“下载客户端”进入 GitHub 最新发布页，在附件列表中选择 Windows x64 安装包。
2. 正常退出正在运行的 ServerDeck，再运行安装器。
3. 按提示完成安装，打开应用，进入工具启动台。

首次使用不要求注册账号，也不会自动连接服务器。接着[连接第一台主机](/docs/quickstart.html)。

## 升级与卸载

升级和卸载前正常退出应用，保留数据目录与系统凭据。卸载默认保留数据，不要选择删除数据来解决启动故障。

## 应用内更新

Windows x64 安装版可在“设置 → 关于 → 软件更新”检查和下载新版，分发源为 `kse-music/operations` 的 GitHub Releases。“自动检查更新”默认开启，每次启动后在后台检查一次。自动检查发现新版本时弹出更新说明。选择“稍后”可收起弹窗，下次启动发现该版本时仍会提醒。选择“忽略此版本”会跳过这个版本的自动提示，发现更高版本时会再次提示。也可以到“关于”手动检查并下载，包括已忽略的版本。检查失败会在“关于”显示原因，可手动重试。

下载可取消，切换页面继续下载；下载完毕并通过签名与版本校验后，点击“安装并重启”，审核连接、任务和未保存内容后确认。取消确认保留原会话；确认后安全结束工作，再调用安装器。更新包仅保留在当前运行期内存中，普通退出后需重新下载。主机、设置、凭据引用和用户插件数据继续保留，启动后按现有规则升级数据。仅 Windows x64 正式 NSIS 安装版可执行应用内更新，开发版、独立 EXE 和其他平台显示限制；没有更新能力的旧客户端仍需手动安装一次新版本。GitHub 的实际可达性取决于用户网络，检查或下载失败时可稍后重试。

## 数据升级与故障

升级前保留数据目录及系统凭据，启动会按支持范围完成数据升级。备份、失败保护与恢复注意事项见[设置与数据](/docs/settings.html#备份与升级保护)。下载或更新失败时先确认网络可访问 GitHub，再查[排障指南](/docs/troubleshooting.html)。
