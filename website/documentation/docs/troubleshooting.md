# 常见问题与排障

## SSH 连接失败

先区分超时、指纹、认证和代理 / 跳板错误。核对地址、端口、账户、认证方式及每一跳路由，再重新测试。

| 提示或现象              | 处理方式                                   |
| ----------------------- | ------------------------------------------ |
| 首次主机指纹待核对      | 通过可信渠道核对后再信任                   |
| 已知密钥变化            | 停止连接，确认服务器或网络变化，不直接覆盖 |
| `SSH_RSA_SHA2_REQUIRED` | 升级服务器 SSH 或使用 Ed25519 / ECDSA      |
| 系统凭据库不可用        | 恢复系统凭据服务后重试，不使用明文配置替代 |
| 修改草稿后不能保存      | 重新测试，成功凭证绑定原草稿且有时限       |

## 传输 100% 后还在等待

字节传输完成后仍有远端读回校验、解包或提交。等待最终任务状态，不要仅凭进度条判断文件已经可用。校验阶段的速度、数据用时和剩余时间不会代表整个任务耗时。

失败先核对原目标、已提交文件和恢复路径。SFTP 文件页上传可在重连或重启后重新选择同一文件和目标目录，匹配的断点将自动续传。下载失败可从头重试。

## 终端已 sudo，文件页仍提示权限不足

终端与 SFTP 使用不同通道。终端中的用户变化不会自动影响文件页；需要时使用文件页的确认式“切换用户”，并确认服务器支持无 PTY sudo 和外部 sftp-server。

## Docker 或 Compose 不可用

确认实际 SSH 登录账户具有 Docker 权限、远端已安装必要工具。Compose 配置缺失或命令失败不能靠盲目重试解决；刷新并独立核对真实对象。

日志需要 GNU `timeout`。本地“清屏”不删除远程日志，日志轮转由 Docker 管理。

## 助手没有可用模型，或回答中断

先在模型设置检查来源是否就绪、远程模型是否通过真实测试，再在助手插件中绑定。远程来源需要支持 Chat Completions SSE；中断片段不会被当成完整回答或可执行计划。

模型返回答案不等于变更已执行。遇到未确认状态，核对主机后再继续，不自动重放。

## 更新或启动升级失败

检查 GitHub 分发源可达性。更新检查失败不表示已经最新；下载必须完成签名与版本校验。

保留原数据、完整升级备份和去敏日志。未知格式、未来版本或损坏内容不能通过清库修复。恢复前正常退出并明确核对新增数据。

## 提交有效反馈

说明客户端版本、Windows 环境、操作步骤、预期结果、真实错误和是否可重现。可以复制安全错误信息；不要提交凭据、完整终端正文或业务秘密。反馈入口为项目 [GitHub Issues](https://github.com/kse-music/operations/issues)。
